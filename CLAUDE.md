# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Cloudy Canvas (by DarkRedgm) is a desktop-first Figma + FigJam app built with Tauri 2, React 19, Vite, TypeScript (strict, `noUncheckedIndexedAccess`), Tailwind v4, shadcn/ui (Radix), Zustand and React Router. One app holds two **products** on one shared canvas engine: **Board** (`.cboard`, FigJam-style; the editor is at `/board/:id` and is being rebuilt on the element architecture, see Elements) and **Design** (`.cdesign`, Figma-style; the editor is at `/design/:id`, built on modules from the start: frames and rectangles in a layer tree so far, see Design). Roadmap: desktop with local files, then a web build of the same frontend, then real-time collaboration (Yjs + Hocuspocus, Laravel backend). It must build on Windows 11 and Arch Linux, and on macOS (built on a Mac or in CI, never cross-built).

## Commands

```sh
pnpm install
pnpm tauri dev      # desktop app
pnpm dev            # frontend only in a browser (native dialogs unavailable)
pnpm lint           # ESLint (flat config, eslint.config.js)
pnpm typecheck      # tsc for app + vite config (noEmit)
pnpm format         # Prettier (with tailwind plugin); format:check to verify
pnpm tauri build    # production bundle
pnpm release:linux  # AppImage (src-tauri/target/release/bundle/appimage/)
pnpm release:arch   # pacman package (packaging/arch/PKGBUILD, needs makepkg):
                    # packaging/arch/cloudy-canvas-<ver>-1-x86_64.pkg.tar.zst, with the
                    # desktop entry, icons and the .cboard/.cdesign mime types
pnpm release:win    # Windows installer cross-built from Linux (cargo-xwin, NSIS):
                    # src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/
pnpm release        # both
pnpm release:win:native  # on Windows itself: NSIS and MSI installers
pnpm release:mac    # on macOS itself: a universal .app and .dmg (both Rust darwin targets),
                    # src-tauri/target/universal-apple-darwin/release/bundle/
pnpm release:tag 0.2.0   # bump the version, commit, tag v0.2.0 and push: CI builds a draft release
```

There is no test framework. **Verification is `pnpm lint` and `pnpm typecheck` only** (plus `pnpm format:check`). Do not run `tauri dev`, cargo, builds or browser checks to verify changes unless asked.

`VITE_MOCK_RECENTS=true` in `.env.local` (see `.env.example`) fills the Home "Recent files" grid with mock data in dev builds. `/design-system` is a dev-only page that previews tokens and components.

## Project structure

`src/` is the frontend (shared by the desktop app and the future web build). `src-tauri/` stays next to it: it's the Rust crate for the desktop shell, built by cargo, and the Tauri CLI expects it at the root.

```
src/
  app/          shell: entry, router, providers, theme sync, MCP server wiring (app/mcp)
  platform/     Tauri implementations of the shared/core interfaces (storage, dialogs, agent channel)
  shared/       app-wide, product-agnostic
    core/       plain TS: ids, files, keyboard, Storage/AgentChannel interfaces, MCP protocol
    ui/         design system: tokens, shadcn components, layout, hooks, brand
    stores/     Zustand stores for app UI state (theme, recent files, agent server)
    agent-server/  the "Agents" menu shown in every top bar
  canvas/       the canvas engine every product shares (plain TS, no React, no product code)
  canvas-ui/    React pieces every editor shares: hosting an engine, chrome components
  products/
    board/      engine side: its points, palette, shared agent tools, file format
      modules/  one folder per feature (its element types, tools, agent tools + `ui/` +
                `<name>.module.ts`), see Modules
      ui/       the board editor (React); composes the product from the modules
    design/     engine side: its points, file format and modules (core: the node base and the
                layer tree; frame, rectangle, layers, assets, plugins-tab)
      ui/       the design editor (React): rail, left panel, properties panel, toolbar
  pages/        app pages that aren't a product: home, settings, join, design-system
server/relay/   the live sessions' relay (iroh-relay config, Docker, deploy script, guide)
```

### Layering (enforced by ESLint `no-restricted-imports`)

Path aliases: `@app/*`, `@pages/*`, `@platform`, `@shared/*` (`@shared/core`, `@shared/ui/…`, `@shared/stores/…`, `@shared/agent-server`), `@canvas`, `@canvas-ui`, `@board`, `@design` (`@board/ui`, `@design/ui` for the editors). They're defined in both `tsconfig.json` and `vite.config.ts`, so keep the two in sync (`components.json` uses them too).

- **Engine code is plain TypeScript**, so the web version can reuse it: `shared/core`, `canvas/`, and `products/*` outside their UI (`ui/`, `modules/*/ui/`, `modules/*/*.module.ts`) may not import a product's UI, React, UI layers (`@shared/ui`, `@shared/stores`, `@canvas-ui`, `@pages`, `@app`) or platform code (`@platform`, `@tauri-apps/*`).
- **Lower layers never know higher ones:** `shared/` can't import `@canvas`/`@canvas-ui`; `shared/`, `canvas/` and `canvas-ui/` can't import products. **Products can't import each other.**
- A product's `ui/` uses its own engine side through its barrel (`@board`), plus `@canvas`, `@canvas-ui` and `@shared/*`. Module files and module `ui/` reach the editor's pieces with deep imports (`@board/ui/board-engine-context`).
- Platform access goes through interfaces in `shared/core` (e.g. `Storage` in `storage.types.ts`), implemented in `platform/` (Tauri).
- Business logic lives in TypeScript, not Rust. `src-tauri/` registers plugins (dialog, fs, clipboard-manager, opener, single-instance, deep-link), holds window config/capabilities and file associations, runs the agent server's HTTP transport (`src-tauri/src/mcp/`, which carries no MCP logic), lists the installed fonts (`src-tauri/src/system_fonts.rs`, `fontdb`), hands over the paths the OS asks to open (`src-tauri/src/open_files.rs`; on macOS Finder sends them as `RunEvent::Opened`, `on_run_event`, kept with the launch paths until the webview takes them) and the `cloudy-canvas://` links it opens (`src-tauri/src/app_links.rs`), and carries live sessions' frames peer to peer (`src-tauri/src/share/`, iroh; no session logic).
- Ids come from `createId()` (`crypto.randomUUID()`), never auto-increment.
- Zustand stores (`shared/stores/`) hold app UI state only, never canvas content.

## Canvas engine (`src/canvas/`)

The engine is the same for every product. **A product is a `CanvasProduct`** (`canvas-product.types.ts`): its `kinds` (`ElementKinds`), `createTools(ctx)` (added after the built-in select and hand tools), `keybindings` and `defaultOptions`. `O` is the product's tool options type, threaded through `CanvasEngine<O>`, `ElementKind<E, O>`, `ToolContext<O>` and `EngineState<O>`. Products are assembled from modules with `composeProduct` (see Modules): the board's is `getBoardProduct()` (`products/board/ui/modules/board-modules.ts`), the design's `getDesignProduct()` (`products/design/ui/modules/design-modules.ts`).

- **Services** (`canvas/services/`): `defineService(id, (doc) => facade)` is a typed token, and `engine.service(def)` (or `ctx.service(def)` in tools, `useService(def)` in React) creates the facade on first use, once per engine. Facades must need no cleanup (they observe through a `DocumentFeed`). The board's are `DB_SCHEMA` (`DbSchema`) and `ER_MODEL` (`ErModel`).

- `CanvasEngine` (`canvas-engine.ts`) is a coordinator, created with `{ product, theme, document? }`. It wires the pieces together:
  - `CanvasDocument`: the content, a Yjs doc.
  - `Camera`
  - `Scene`: element list, selection, hover and marquee, plus spatial queries.
  - `Renderer`: PixiJS.
  - The tools.
  - Input modules: pointer, wheel and keyboard.
  - `TextEditor`: a DOM textarea overlay. Tools type a new element's text with `ctx.editNewText(draft)`: the draft is added to the document (and selected) only when the edit is committed with some text. An element with several texts (a table's cells) names each with a `part` key (`ElementText.partAt`/`partBox`/`nextPart`/`firstPart`): double-click edits the part under the pointer, Tab moves to the next, and only that part's text slot is hidden while editing.
  - **Rich text** (`text/rich/`, `text/rich-editor/`): a text with styled ranges is `TextRun`s (`{ start, end, style }`, UTF-16 indexes, the style the product's; `normalizeRuns`, `spliceRuns`, `styleRuns`, `clearRunFields`, `runsForText` move and split them as the text changes) over styled `RichSpan`s, which `layoutRichText(text, spans, frame)` lays out (`RichTextLayout`: lines of fragments, words wrapping greedily across spans, a line as tall as its tallest span, every span on one baseline centered in its own line height, align and justify), measured with `measureSpan`/`spanOffsets` and `fontMetrics` (Pixi's, dropped by `fontsChanged` when a font loads; caches key on `fontsVersion()`, and the engine re-syncs the views using it). `ElementView.placeRichText(layout, alpha)` draws it into one canvas texture (`RichTextSprite`, `drawRichText`: fragments on their baselines, `decorationRect` underlines and strikethroughs; drawn white for `setPaintTextMask`). A kind with `ElementText.rich` (`RichTextSpec`: `runs`, `layout`, `apply`, `shortcut`) is edited by a `RichTextSession` instead of the textarea: a hidden textarea takes typing, IME and the clipboard (its value is the text), the canvas redraws the element as edited (`renderer.previewElement`, or the draft layer for a new one), the caret and highlight are DOM (`RichEditorOverlay`) from the same layout (`rich-caret.ts`: `caretRect`, `selectionRects`, `indexAt`, `wordRange`), clicks/drags/double and triple clicks select (`pointerSelect`), Up/Down/Home/End move by layout lines, Ctrl+B/I/U and Ctrl+Shift+X toggle styles, and the session keeps its own undo (`SessionHistory`), written as one document step when it ends. Focus moving to the app's controls keeps it open; `EngineState.textSelection`, `engine.editingText()` and `engine.styleTextRange(patch)` (on what's typed next with only a caret) are what panels use.
  - **Line heights below the font's own** center each line's glyphs in it as CSS and Figma do (they reach past the line): `ElementView.placeText` moves Pixi's text up by `negativeHalfLeading` (`render/text-leading.ts`; Pixi starts every line at its top) and aligns by the lines' height, and the design's glyph outlines (`textOutline`) place baselines the same way.
  - **Text and fonts** (`text/`): text is shaped by a `TextFont` (`textFont(size, options)`: family, weight, style, line height, letter spacing; the app's Inter by default), which drawing (`canvasTextStyle`, `view.placeText`, alignment left/center/right/justify, top/middle/bottom), measuring (`measureTextBlock`; `measureText`/`measureWrapped` are its app-font shorthands) and the editor (`textEditorStyle`) share. An element's text sizing is `fitContent`, `fitHeight` or, per element, `text.sizing(el)` (`content`/`height`/`fixed`). Kinds name the faces their text uses with `fonts(el)` (`FontRequest`); the engine's `FontTracker` loads each once through `CanvasEngineOptions.fonts` (a `FontLoader`; `useCanvasEngine` passes `fontLibrary` from `@platform`), then redraws the elements using it (`ElementView.refreshText`) after their kind's `fontsLoaded(el)` patch (e.g. an auto-sized text's new size, outside the undo history). Fonts are `FontLibrary` (`shared/core/fonts/`: types, weights and names, `closestVariant`, Google catalog and CSS parsing): `platform/fonts/` lists installed families (the Rust `system_fonts` command) and Google's (`fonts.google.com/metadata/fonts`, cached a week, a short fallback list offline), and loads a Google face as `FontFace`s from its CSS, caching the files in `<appData>/fonts/`.

  It exposes `kinds`, `keymap`, `commands` and `elementInfo(type)` to hosts. `mount(container, onLoading?)` opens the canvas fitted to its content (at most 100%): it builds the views a slice at a time (`Renderer.syncElementsChunked`, about 12 ms per frame), then waits for the scope's images (`Renderer.preloadImages`) and fonts (`FontTracker.settled`), at most 8 s, reporting each step as an `EngineLoading`; input starts once it resolves. `useCanvasEngine` returns `{ engine, loading }` and both editors show `CanvasLoadingOverlay` (`canvas-ui`) until the engine is there. Hosts close it with `engine.close()` (`useCanvasEngine` does on unmount): input stops, the tasks set with `engine.onClose(key, task)` run while it can still draw (at most 3 s), then it's destroyed. `engine.clientToWorld(client)` (`null` outside the canvas) and `engine.elementAt(world)` let DOM drags drop onto the canvas. `engine.thumbnail({ width, height })` is a small JPEG of the whole canvas framed to that size (`export/thumbnail.ts`), or `null` when it's empty: drawn from the views already built (`Renderer.captureView`: the world at identity, unculled, extracted; about a frame, no new views or image loads), never through `snapshot`, so large files stay cheap.

- **Registries are per product, never global.** Everything that needs an element's kind (document, scene, renderer, overlay, text editor, tools via `ctx.kinds`, agent helpers) gets the product's `ElementKinds` and calls `kinds.kindOf(el)`.
- **Content lives only in the Yjs doc.** Each element is a `Y.Map` inside the `"shapes"` map (the name is kept so existing files load). Order is a fractional-index string (`index`), and lexicographic order is z-order.
  - All edits go through `CanvasDocument` methods (`add`, `update`, `updateMany`, `remove`), which transact with `LOCAL_ORIGIN` so `Y.UndoManager` tracks only local changes.
  - Call `doc.checkpoint()` before a user action to start a new undo step.
  - **After-edit hook:** the product's `afterEdit(doc, change)` (point `afterEdit`, one module; `doc.setAfterEdit`, set by the engine) runs when the outermost edit ends, inside its transaction and so its undo step, with an `EditedChange` (`updated` ids, `removed` elements, `before`: the changed fields' earlier values); its own writes run it again with what they changed, until nothing does (at most 32 passes; `update` only records fields whose value changes). Untracked updates run it too; `addUntracked`/`addAllUntracked` (what a file opens with, imports) don't, and undo/redo don't. `doc.deferAfterEdit()` holds it back until the returned function is called (the select tool's drags, so moved elements aren't put back mid-drag; it runs once after `onMoved`). `doc.ids()` and `doc.field(id, key)` read the store without reading whole elements.
  - Binary data (image files) lives in the doc's `"assets"` map (`doc.addAsset`, `doc.getAsset`), keyed by a `createId()` id that elements point at. It's outside the undo history and shared by copies of an element; nothing deletes unused assets yet. Kinds name the assets an element shows with `kind.assets(el)`. The renderer decodes each one once into a texture (`render/image-cache.ts`; SVGs are rasterized first, `render/svg-image.ts`), and a drawer shows it with `view.placeImage(assetId, box, fit?)` (proportions kept: `contain`, the default, or `cover`, which crops). SVG icons are drawn with `view.placeIcon(key, svg, box)`, parsed once per icon.
  - The document's own **title and description** live in its `"meta"` map (`doc.meta()`, `doc.setMeta(patch)`, `doc.observeMeta`; undoable like elements). The title is shown instead of the file name when set (`displayName(file)` in `shared/core`); `useDocumentMeta(doc)` (`canvas-ui`) reads it in React. `doc.onChange(listener)` fires on any change (elements, view state, assets, meta): it's what dirty tracking and autosave listen to.
  - A document reads elements through the product's kinds (`new CanvasDocument(kinds)`, `CanvasDocument.fromUpdate(kinds, bytes)`): `doc.get`/`doc.all` return only registered types, with `kind.fillDefaults` applied. Elements of unregistered types (e.g. DB or ER shapes in older boards) stay in the doc untouched but aren't shown. Reads are cached per element (dropped when it changes: the document's own writes, and `beforeObserverCalls` for undo, redo and remote updates), so a change to a few elements doesn't read the whole file again; `doc.all()` is a new array of **shared elements: never mutate one** (they're frozen in development builds).
- **Data flow is one-way.** Tools write to the document, and `doc.observe` reports `{ updated, removed, fields }` (`fields`: what each element changed, `"all"` when added; `changesOnly(change, GEOMETRY_FIELDS)` tells a move or resize apart, which feeds like the design's layers and pages ignore). The engine then refreshes the `Scene`, syncs only the changed Pixi views (`render/layers/element-layer.ts`) and requests a frame (fonts are asked for only for the changed elements).
  - A view only draws again when its element changed more than its `x`/`y` (`viewChange`, `render/view-change.ts`: fields by identity, then `deepEqual`); a moved one is only moved, so kinds must draw in local coordinates from the element's fields. What else a drawing depends on is `kind.drawnFrom(el)` (compared by identity; the design's boolean gives its result), and `renderer.syncElements(…, redraw)` / `engine.refreshElements(ids)` draw again anyway (a text's glyph outlines or font arrived).
  - Rendering is on demand: Pixi uses `autoStart: false`, and `FrameScheduler` renders at most once per animation frame.
  - **Render cost:** each frame, views outside `camera.visibleWorldRect()` are culled (`ElementView.cull`, from its cached drawn `extent()`). A clipped view gets a mask only when the clip cuts something off (`clipCovers`). Text textures are capped by their element's size (`cappedTextResolution`, at most 4096 px a side; resolution at most 4), and image textures are scaled down to 4096 px when decoded (`ImageCache`).
- **Tools** implement `Tool` (`tools/tool.types.ts`, `id: string`) and act only through `ToolContext`, never through the engine directly. Select and hand are built in (`createBaseTools`); a product adds its own in `createTools`. A tool previews an element it's creating with `ctx.setDraft(el)`: the draft layer draws it with its kind, like any element. Other gesture feedback (a line being dragged, a drop target) is a `Guide` set with `ctx.setGuide(fn)`, drawn above the elements. `ctx.setFaded(ids)` dims elements a gesture is about to remove (the eraser); switching tools clears it. **Modes** (`canvas/modes/`): a product's modules register `CanvasMode`s (the `modes` point, keyed by id; `CanvasProduct.modes`) besides `DEFAULT_MODE` (`default`: every tool): `tool` (it starts with, and Esc goes back to), `tools` (the others that work in it; `setTool` ignores the rest, shortcuts included, `modeAllows`) and `isolate(el)` (only what it accepts can be hit, selected, marqueed or Ctrl+A'd: `Scene.isolation`, `Scene.reachable(el)`, which every locked check goes through; the rest is dimmed, the engine's `applyFaded` merging it with `setFaded`, again on each scene refresh, and leaves the selection), `faded(context)` (a `ModeFadeContext`: the scene's elements, the document, the active tool and the scope on screen; what it dims instead of what `isolate` leaves out, worked out again on each scene refresh and tool switch: the Catalog's unprinted frames), `commands` (the only engine commands that run while it's on besides its keybindings' and `tool.<id>`: `modeAllowsCommand`, `engine.allowsCommand(id)`, checked by `createCommands` after `toolTakes`; the context menu hides what isn't allowed, `allowedGroups`, a submenu of actions counting by its id, and the design's main menu shows it disabled). `keybindings` (shortcuts that exist only while it's on: the `Keymap`'s layer, `keymap.setLayer`, matched and labelled first; their commands are host commands without keys of their own). `engine.setMode(id)`, `engine.modeId`, `EngineState.mode`, `ctx.getMode()`/`ctx.setMode(id)` (and `ctx.getScope()`); Esc drops the part, then the selection, then goes back to the mode's tool, then leaves the mode. `SelectTool` is exported so tools can build on it (`ScaleTool`; `movesSelection: false` keeps what it selects in place and `ResizeMode` `none` shows no handles or rotate zones, the Catalog's tool); `Tool.editsOnDoubleClick` (the select tool's, not the Scale tool's) is what lets double-click enter groups, call `editElement` and edit text. `ctx.animateIn(ids)` plays a quick pop on elements a tool just added (`render/entrance.ts`; the element layers advance it each frame and the engine keeps requesting frames while it plays; skipped with reduced motion).
- **Product hooks** keep product features out of the engine:
  - `createLinks()` returns `CanvasLinks` (`links/`): lines derived from the elements (e.g. database relations), re-resolved on every document change and drawn under the elements, highlighted when they touch the selection.
  - Links can show text with `view.label(text, at, options)` (pooled text nodes, e.g. ER cardinalities).
  - **Element actions and DOM overlays:** a kind's `interactionAt` press can call `ctx.activate(elementId, action)` for something only the host can do (play a video, open a link); hosts listen with `engine.onElementAction`. DOM placed over an element follows it with `engine.worldRectToScreen(rect)` and `engine.onViewChange(listener)` (camera, resize and document changes).
  - `resolveElements(elements)` gives elements whose geometry follows others (ER aggregation boxes, constraints) their current geometry: `Scene.refresh()` runs it and keeps last refresh's object for an element that resolved the same (`deepEqual`, same `drawnFrom`), so only those that resolved differently (`Scene.derivedIds`) are synced. **Read geometry from the scene** (`engine.getElement`, `ctx.getElement`), not from `doc.get`; the stored bounds of derived elements are stale. The text editor places itself from the scene too.
  - `withMembers(ids, elements, purpose)` adds what goes with the ids when they're moved (`ctx.withMembers` in the select tool) or deleted (`engine.deleteElements`), e.g. an entity's attributes.
  - `onRemove(doc, removed, before)` cleans up after deletions (e.g. clears refs to deleted tables, frees connector ends), inside the same undo step. `before` is the scene as it was, so resolved geometry of removed elements is still readable.
  - `prepareCopies(copies, { copied, existing })` fixes copied elements before they're added (the board: free DB names via `prepareDbCopies`, a new ER diagram per source diagram via `prepareErCopies`, loose connector ends via `prepareConnectorCopies`). `pasteText(text, at, index, options)` turns text pasted from outside the app into an element (the board: a text element), and `pasteImage(image, view, index, options)` an image (the board: an image element, `createPastedImage`).
- **Scopes** (`CanvasScopes`, the product's `scopes`, one module at most): a document split into parts shown one at a time (the design's pages). `list(doc)` is the scope ids in order, `of(el)` an element's scope (`null`: never shown, e.g. the page records), `place(el, scope)` puts a new element in one and `label(doc, scope)` names it for people (`engine.scopeLabel`, the design's page names). The `Scene` holds only the current scope's elements (`Scene.scope`, `scopeIds`), so hits, selection, exports, thumbnails, links and agents' `engine.elements()` stay in it; `doc.setPlacement` (set by the engine) places every added element in the scope on screen, so tools, pastes and agents need no code for it. `engine.scope`/`engine.setScope(id)` (and `EngineState.scope`): switching clears the selection, goes back to the select tool and restores that scope's camera (or fits its content). When the scope on screen is deleted the next one shows; an undo or redo that only touched another scope shows that one. Elements updated into another scope leave the canvas like removed ones. `doc.addUntracked` adds outside the undo history (what a file needs when it opens).
- **View, order and drops:** `view` (`CanvasViewOptions`: `minZoom`, `maxZoom`, `grid`: `"dots"`, `"pixels"`, a one-unit grid drawn over the content from 800%, or `"none"`; unset values are `DEFAULT_VIEW_OPTIONS`, the board's) sets the camera's limits and the grid layer (`render/layers/create-grid-layer.ts`). `orderKeys(elements)` replaces `zOrderKey` as the drawing order (the design's layer tree): `Scene.orderKey` is what `ElementLayer` stacks by, and `Scene.restackedIds` are redrawn when a key changes without its element (a parent moved in the order). `clips(elements)` gives the world area clipped elements show in (`ElementClip`: a rect and a corner radius): `Scene.clipOf` is what `ElementLayer` masks views with (`ElementView.setClip`; layers get `LayerPlacement`: `orderOf` and `clipOf`), `Scene.elementAt` ignores clicks on clipped-away parts, and `Scene.replacedIds` (order or clip changed) are placed again. `editElement(el, ctx)` (point `editElement`; several modules may give one, the first returning `true` wins) edits an element its own way on double-click (after groups are entered) and Enter, before its text (the design's vector edit mode, the board's image crop and ER mode). Tools may have `onActivate()` (feedback that stays while they're on) and `onCommand(command)`, which every command asks first (`engine.toolTakes`), so a mode can own Esc, Enter, Delete and Ctrl+A; `ctx.getTool()` is the active one. The editor point `toolbars` (`ToolbarModeEntry`: `tools`, `component`) replaces the main toolbar while one of its tools is on (`ModuleToolbar`); the editor point `modes` (`EditorModeEntry`: the mode's `id`, `label`, `description`, `icon`, `order` and an optional `toolbar` shown instead of the main one while it's on) feeds the `ModeSwitcher` beside the toolbar (shown with two modes or more; the product's core module gives the default mode's entry, the board's "Board"), and `useEditorMode()` (`EditorModeContext`: `id`, `entry`, `isDefault`, `setMode`, `leave`) is what a mode's UI reads. `selectTarget(hitId, { selection, deep, enter }, elements)` decides what a click selects (`ctx.targetAt`, `ctx.targetOf`; the select tool, double-click and right-click use it; e.g. a design group). `FreehandTool` (`tools/freehand-tool.ts`) is the base of freehand drawing tools (the board's marker, the design's pencil): it collects, previews, smooths (`smoothPoints`, `smooth-points.ts`) and adds. `onMoved(doc, moved, elements)` runs when the select tool finishes a drag (`ctx.moved`), in the drag's undo step (the design drops nodes into frames and reorders auto layouts). The canvas theme is read from the editor's container (`readCanvasTheme(container)`), so a product can override the `--canvas-*` tokens (`[data-product="design"]` in `tokens.css`).
- **Paths** (`canvas/path/`, plain TS): a `PathShape` is contours of cubic `PathSegment`s (`PathContour { start, segments, closed, hole? }`; a closed contour's last segment ends at its start). `booleanPaths(op, operands)` (`union`, `subtract`: the first minus the rest, `intersect`, `exclude`; each `PathOperand` filled by its own `fillRule`) and `normalizePath(shape, fillRule)` (overlaps and self-crossings resolved into outers followed by their holes) run Clipper2 (`clipper2-ts`) on flattened integer paths (`flattenContour`, adaptive to `FLATTEN_TOLERANCE`, ×`PATH_SCALE`) whose points carry `SourceTags` in `z` (the curve and `t` each came from; Clipper's Z callback tags crossings), so `rebuildContour` turns the result back into the source curves' exact parts (`subCurve`). `outlineStroke(shape, { width, cap, join, miterLimit })` is a stroke's area (`ClipperOffset`); `strokeArea(shape, { …, align, dashes, dashOffset })` lays it `inside`/`center`/`outside` (twice as wide, cut by what the closed contours enclose; open ones stay centered) after `dashPath(shape, pattern, offset)` (dashes as open parts of the source curves by arc length, an odd pattern repeated, the dash over a closed contour's start joined); `rectPath(rect, radius)` is a (rounded) box and `boxSidesStroke(w, h, radius, sides, align)` a box's band with a weight per side (`BoxSides`). Also `pathBounds` (exact curve extremes), `pointInPath` (even-odd over normalized contours) and `distanceToPath`, `placePath`/`localPath`/`mapPath`, the bezier helpers (`pointAt`, `splitAt`, `subCurve`, `flatness`, …) and `fillPath(g, shape, style)` (each outer filled, its holes `cut()`) / `strokePath`. `LruCache` and `identityKey` (`canvas/utils`) cache what's worked out from shapes.
- **Images in a box** (`canvas/image/`, plain TS): an `ImageTransform` is Figma's `imageTransform` (2×3, the layer's normalized box → the picture's), an `ImageCrop` the axis-aligned case (`cropTransform`/`transformCrop`), `ImageRotation` quarter turns and `ImagePlacement` what the renderer takes (`contain`/`cover` with a rotation, `transform`, `tile` with a scale). Helpers: `fitTransform` (the transform that looks like contain/cover), `imageQuad`, `panTransform`, `zoomTransform`, `reframeTransform` (the box changes, the picture stays), `rotateTransform90`, `clampCrop`, `cropInside`, `coverCrop`. `ImagePaintLayer.placement` is drawn by `PaintStack`'s image slot (a sprite placed with `imageMatrix`, or a `TilingSprite` whose tiles use the picture's own size, `ImageCache.naturalSize`); `view.placeImage(assetId, box, fit | crop)` crops the texture's frame (`fitImage`). `ImageCropOverlay` (`canvas-ui/components/image-crop/`, pure drag math in `crop-drag.ts`) edits one: the picture dimmed past the box, drag to move, its corners scale it (Alt: round its middle), the box's sides resize the element (Shift keeps the ratio), Enter/Esc finish; `clamp` keeps the crop inside the picture. Overlays map boxes to the screen with `canvas-ui/overlay/` (`normalizedToScreen`, `screenToNormalized`, `screenToLocal`, `useViewMapping`; an `OverlayFrame` with `mirrored` maps in the frame of what a mirrored element draws, so crop and gradient handles sit on the mirrored picture), and `useAssetUrl` shows an asset in the DOM.
- **Effects** (`canvas/effects/` data, `render/effects/` drawing): a `CanvasEffect` (`id`, `type`, `visible`, plus its type's fields) is plain JSON; the product's `effectRenderers` (point `effectRenderers`, keyed by type) draw them on the GPU and its `effects(elements)` hook (one module) returns `ElementEffects`: an `EffectScope` per element with effects (`effects`, `home`, `box`, `rotation`, `bounds` of what it holds) and `homes` (element → its `EffectSlot`). Slots are a `ScopeSlot` (`MaskSlot | EffectSlot`), so masks' and effects' scopes nest in each other (`homeOf`, `scopeHome`, `sameSlot` in `layer-placement.ts`; a product gives both consistently, the design through `treeSlots`); `Scene.effects`, `Scene.visualBounds(el)` (shown bounds grown by `effectsOutset`, what exports frame) and `masksOf` walk them. `ElementLayer` puts an element's view and what it holds into an `EffectScopeView` (`render/layers/effect-scope-view.ts`: at the element's order key, clipped like its view, culled with its reach) whose one `EffectStackFilter` (a Pixi `Filter` overriding `apply`) runs the effects' `EffectRenderer`s stage by stage (`backdrop`, `content`, `behind`, `filter`) over the content texture, each `render(pass, effect, current)` returning the new result. An `EffectPass` gives `content`, `backdrop` (the back texture, for renderers with `backdrop`/`readsBackdrop`; the canvas then keeps Pixi's back buffer, `RendererOptions.backdrop`), `px`/`offset` (world → CSS px, turned with the element), `toLocal` (texture coordinates → the element's own), `texture()`, `run(shader, input)` and a Gaussian `blur(input, radius)` (`blurShader`, taps spread past `MAX_BLUR_TAPS`); textures are pooled and returned after. `EffectShader` wraps a GLSL ES 3 fragment (highp; `FILTER_HEADER`, `SAMPLING_GLSL`: `sampleIn`, `px`) with its uniforms (`set`) and samplers (`bind`); shared ones: `copyShader`, `silhouetteShader` (offset, round spread, invert, color), `underShader`, `atopShader`, `shapeUnderShader`. `ElementLayer.setEffectScale` is the zoom (1 in snapshots); on the canvas renderer effects are skipped. **Compositing:** an `EffectScope` may carry a `composite` (`ScopeComposite`: `opacity`, a `BlendMode` from `canvas/effects/` (`BLEND_MODES`, Figma's eighteen), `isolated`): the filter's last step is `compositeShader` (`render/effects/composite-shader.ts`, the W3C formulas over `pass.backdrop`, so the canvas keeps the back buffer for products with an `effects` hook), and a non-isolated opacity-only scope with no effects runs no filter, its container's `alpha` handing the opacity down. Paint layers take a `blendMode` too (`pixiBlendMode`: Pixi's own modes, `pixi.js/advanced-blend-modes` registered by the renderer; hue draws normal).
- **Undrawn elements:** the product's `undrawn(elements)` hook (one module) names elements that are hit, selected and moved but not drawn on their own (a design boolean's operands, which it draws combined): `Scene.drawn(el)`, `LayerPlacement.drawn`, `ElementView.setDrawn` (a view with an empty clip, what a hidden parent holds, isn't drawn either); snapping skips them. `engine.refreshElements(ids)` reads elements again with what derives from them though the document didn't change (a text's glyph outlines arrived).
- **Masks** (Figma's, `render/layer-placement.types.ts`): the product's `masks(elements)` hook (one module) returns `ElementMasks`: each `ElementMask` (`id`, `mode`: `alpha`/`vector`/`luminance`, `inverted`, `home`: the `MaskSlot` its scope sits in, `bounds`, `shape`: world-placed `MaskShape`s (`path`, drawn with holes) for a vector mask or `null`, `contains(p)`) and `homes` (element → its innermost `MaskSlot`: `{ mask, role: "source" | "masked" }`). The scene keeps them (`Scene.masks`, `masksOf(el)`, a changed slot is in `replacedIds`); `elementAt` skips what a mask hides, `shownBounds(el)` (bounds ∩ clip ∩ the masks it shows through) is what marquees, snapping, exports and thumbnails read, and the overlay outlines the hovered (or single selected) element's masks dashed (`OverlayState.masks`). `ElementLayer` nests views: each mask is a `MaskScopeView` (in its home's container at the mask's order key) holding a `MaskSource` (the mask's views, never drawn on their own: rendered into the mask's texture, an `AlphaMask` through the `MaskSourceEffect` Pixi extension) and the masked views; `luminance` puts brightness in the red channel with a `ColorMatrixFilter`, `vector` is a stencil of the outlines (or the source made opaque when a part has none), `inverted` is Pixi's inverse mask. A scope off screen is culled and its texture covers only what's on screen (`boundsArea`).
- **Frames:** a kind with `frame = true` (ER aggregation boxes, sections) is drawn in its own layer behind the links and the other elements, larger frames further back (`zOrderKey`, `elements/z-order.ts`), and a marquee selects it only when it encloses it.
- **Feeds:** board-level facades (`DbSchema`, `ErModel`) notify React through a `DocumentFeed` (`document/document-feed.ts`), which observes the document only while someone subscribes, so they need no cleanup and can be created in a `useMemo`.
  - Kinds offer `interactionAt` and `handles` (see Elements), which the select tool and overlay use.
- **Copy and paste** (`clipboard/`): `ElementClipboard` copies the selection with what moves with it (`withMembers(…, "move")`), as scene elements, to the system clipboard as JSON (`encodeClipboard`/`decodeClipboard`, tagged with the product id, with the assets they show in base64 so images paste into other files). `insertCopies` clones them (`cloneElements`: fresh ids and indexes, and `remapIds` rewrites every string equal to a copied id, so references between copies follow without knowing the types), runs the product's `prepareCopies`, offsets them with `kind.move` and adds them as one undo step. Pastes land 20 units further each time while the source is in view, otherwise centered in it. Anything else on the clipboard goes through `paste-external.ts`: an image (preferred over text) becomes an asset plus the product's `pasteImage` element, and text goes to `pasteText`. Files dropped on an open editor go the same way (`drop-files.ts`, `engine.dropFiles(files, clientPoint)`): images and SVGs through `pasteImage` (fit and centered on the drop point; SVGs are sized by `svgSize`), `.txt` files through `pasteText`, cascaded by a paste step, as one undo step. The system clipboard is the `Clipboard` interface (`shared/core/clipboard.types.ts`: text, plus `readImage()` as an encoded file; `platform/clipboard.ts`: Tauri's clipboard manager, whose RGBA images are encoded to PNG, or `navigator.clipboard` in the browser), passed as `CanvasEngineOptions.clipboard` by `useCanvasEngine`; without one, the engine uses a `MemoryClipboard`. The commands are `copy`, `cut`, `paste` and `duplicate` (Ctrl+D). Alt-dragging with the select tool duplicates in place (`ctx.duplicate`) and drags the copies.
- **Context menu, z-order, lock and export:** a right-click selects what's under the pointer (locked elements too; empty space clears the selection) and reports a `ContextMenuRequest` to `engine.onContextMenu` listeners; `CanvasContextMenu` (`canvas-ui/components/context-menu/`) shows it, its items are data (`SELECTION_MENU`, `CANVAS_MENU`: engine commands, labels from `BASE_COMMAND_LABELS`; a `ContextMenuCategory` is a submenu of commands, like Copy/Paste as and Order, and a module's `contextMenu` group with a `label` becomes one, like the design's Transform, Mask and Boolean, so the menu stays short; menus past the window's height scroll, `MENU_FITS_SCREEN`). `reorderSelection` (`bringToFront` `]`, `bringForward` Ctrl+], `sendBackward` Ctrl+[, `sendToBack` `[`) rewrites indexes with `reorderIndexes` (`elements/reorder.ts`: front/back of everything, or one step past the nearest overlapping element; frames keep their area order). An element with `locked` is skipped by `Scene.elementAt` (unless asked), `elementsInRect`, `findInteraction`, `selectAll` and the select tool's drags (`toggleLock` Ctrl+Shift+L, `unlockAll` Ctrl+Alt+Shift+L). `pasteToReplace` (Ctrl+Shift+R) pastes centered on the selection and removes it in the same undo step (`ElementClipboard.paste({ replace })`). Exports (`canvas/export/`): `engine.exportElements({ format, background, area })` draws the selection (with its `withMembers(…, "move")`) or the whole canvas off screen (`Renderer.snapshot`, fresh layers and the product's `createLinks()`, images loaded first) as PNG or JPG (`ExportOptions.rect`: exactly that world area, no padding, e.g. a page frame), a one-page PDF (`encodePdf`, a hand-written JPEG page; `encodePdfPages(pages, { pointsPerUnit })` writes several, the Catalog's brochure with a unit as a point) or CSV of the elements whose kind has `rows(el)` (tables, DB tables; `encodeCsv`). `copyAsPng` (Ctrl+Shift+C) writes one with `Clipboard.writeImage`. The `export` command (Ctrl+Shift+E) is a host action: `ExportDialog` (`canvas-ui/components/export-dialog/`) handles it and saves with `exportFile` from `@platform`.
- **Nudge, resize and size label:** the arrow keys nudge the selection (`nudgeLeft`…, Shift: `nudgeLeftFar`…, 10 units; `engine.nudgeSelection`, `engine.moveElements` with `withMembers(…, "move")`, locked ones stay, no `onMoved`, so nothing changes parent); a burst of presses is one undo step (`nudgeCheckpoint`, `canvas/arrange/nudge.ts`; tools take them with `onCommand` and `nudgeStep(command)`, e.g. vector edit mode nudges its points). The resize handles belong to a `ResizeTarget` (`handles/resize-target.ts`, `resizeTarget(selected, kinds)`): one resizable element, or a multi-selection with a resizable element in it, by the box round the outlined ones; `ResizeGesture` scales each element into the new box (`scaleRectInBox`, `geometry.ts`) through `kind.resize` (ones that can't resize move by their center, with their members). Shift (or any `keepsRatio` kind) keeps the proportions, Alt resizes round the center (`resizeRect(…, { keepRatio, fromCenter })`). `CanvasViewOptions.sizeLabel` (the design's) shows the selection's `W × H` in a tag under it (`render/layers/size-label-layer.ts`, from `OverlayState.size`).
- **Snapping and smart guides** (`canvas/snapping/`): a gesture asks `ctx.createSnapper(exclude)` (what it moves, with its members) for a `Snapper` (`GestureSnapper`) and calls `move(box, p)` (an offset for the moved box), `resize(box, handle, p)` (for the dragged sides) or `point(world, p)`, then `clear()` when it ends. Targets are collected on first use (`engine.snapTargets`: the scene's elements whose `kind.snapTarget(el)` is true (outlined ones; hidden design layers and groups aren't), clipped like they're drawn, on and around the screen) as sorted edge lists (`snapTargets`, `snap-edges.ts`: start, center and end lines, `nearestOffset`, `edgesAt`). A move snaps each axis to the nearest edge or to equal spacing (`equal-spacing.ts`: centered between its neighbors on the row, or repeating a gap of the row), whichever is closer within 5 screen px; with `pixelGrid`, axes nothing snapped are rounded to whole units. Ctrl/Cmd (`p.modKey`) turns object snapping off. The guides are a `SnapFeedback` (`lines` with × marks, `gaps` with their length) drawn in screen space by `render/layers/snap-layer.ts` in the `--canvas-snap` color (`CanvasTheme.snap`); `ctx.setSnapFeedback` shows any (the select tool's Alt + hover distances, `measureGaps`). Used by the select tool's moves, `ResizeGesture`, the design's `NodeDrawTool` and `LineEndDrag`. `SnapSettings` (`objects`, `pixelGrid`) start from `CanvasViewOptions.snapping` (the design's: both on; the board's: off), are `EngineState.snapping` and `engine.setSnapping(patch)`; `useCanvasEngine` applies the user's choice and `useSnapping()` (`canvas-ui`) changes and remembers it per product (`shared/stores/snapping-store.ts`). The toggles are in `ZoomMenu` ("Snap to pixel grid" only with the `pixels` grid).
- **Align, distribute and tidy up** (`canvas/arrange/`, pure functions over `ArrangeItem`s: `alignOffset`, `distributeOffsets` (the first and last stay, equal spaces, whole units), `tidyUpOffsets` (rows by middle, columns as wide as their widest item, the median spacing)): `arrangeItems` picks the outlined, unlocked ids that don't already move with another of them; the engine's `alignElements`/`distributeElements`/`tidyUpElements` (and the `…Selection` commands `alignLeft`, `alignCenterX`, `alignRight`, `alignTop`, `alignCenterY`, `alignBottom` (Alt+A/H/D/W/V/S, matched by `code`), `distributeHorizontal`/`distributeVertical` (Alt+Shift+H/V) and `tidyUp` (Alt+Shift+T)) move them with `moveElementsBy` (with their members) in one undo step, with no `onMoved`, so nothing changes parent. Several elements align with their bounds; one aligns with the product's `alignTarget` (the design: its nearest container, `containerAlignTarget`; the board: the smallest section it's in, `sectionAlignTarget`), and `engine.canAlign(ids)` says whether there's one. The selection's context menu has an "Align" submenu; the design's Position section has the buttons (`ArrangeButtons`).
- **Scale tool (K)** (Figma's): `ScaleTool` (`tools/scale-tool.ts`, a `SelectTool` with `resizeMode: "scale"`) is built in next to select and hand; products bind its key (`tool.scale`: K in the design, Shift+K on the board, where K is the sticker tool) and put it in the toolbar's `move` menu with select. The active tool's `Tool.resizeMode` is `Scene.resizeMode`, which `resizeTarget(selected, kinds, mode)`, `findInteraction` and the overlay read: in `scale` mode what's `scalable` gets handles (a line, a group, a board text too) and the box takes lines along. `ResizeGesture` in `scale` mode keeps the proportions and scales every element with its `withMembers(…, "move")` round the drag's fixed point (`resizeAnchor`: the opposite corner or side, the center with Alt; turned for a turned element) through `kind.scale(el, t)` (`ScaleTransform { origin, factor }`, `elements/element-scale.ts`: `scalePoint`, `scaleRect`, `scaleLength`, `scaleOffsets`; `scalePatches`, `canvas/arrange/scale.ts`). The default resizes a resizable element to its scaled box and moves the rest; `BoxKind` and `LineKind` (points) are `scalable`, and kinds scale what they draw: the design's nodes their `strokeWeight`, rectangles and frames their `cornerRadius`, texts `fontSize` and `letterSpacing` (laid out again), lines their ends, vectors their network (groups leave it to their children); the board's texts their `fontSize`, stickies and tables a `textScale` (font and insets, `tableTypography`), shapes their `fontSize` and `strokeWidth`, strokes and connectors their `size` (free connector ends move), images their `padding`; DB and ER elements only move. `engine.scaleElements(ids, factor, anchor)` (a `ScaleAnchor` of the box round them, `anchorPoint`, `SCALE_ANCHORS`) is one undo step: the design's `ScaleSidebar` (the tool's `toolSidebars` entry: W, H, %, the 3×3 `AnchorPicker`) and the agents' `scale_shapes`/`scale_nodes` (`canvas/agent/scale-tool.ts`, part of `arrangeTools`: `factor`, `width` or `height`, `anchor`) use it.

In the `ZoomMenu`, the selection's context menu and the design's View menu.

The design's nodes take `opacity`, `fills`, `strokes`, `strokeWeight` (`NODE_STYLE_FIELDS`; `nodeStylePatch` drops fills where `fillable` is off, strokes where `strokable` is, image paints from strokes and kinds without `imageFills`), rectangles and frames `cornerRadius`, texts their typography and alignment (set again with `retypeset`), lines their caps; groups nothing. In the selection's context menu and the design's Edit menu.

Kinds opt in with `ElementKind.rotatable` (the design's nodes; board kinds don't) and turn with `kind.rotate(el, degrees, pivot)` (the corner orbits, `rotation` adds up; the design's line turns its ends instead and keeps 0). Kinds work unturned: `Scene.elementAt` and `findInteraction` hand them `toUnrotated(p, el)`, `ElementView` places, turns and culls the view (`rotation.ts`: `rotatePoint`, `rotatedBounds`, `rotatedBoundsAround`, `pointInRotatedRect`, `normalizeAngle`, `angleOf`). `elementBounds(kind, el)` is where an element shows (the box round it when turned): hits, marquees, snapping, arranging, exports, thumbnails and paste placement read it; resizing reads `kind.bounds`. `ElementClip.rotation` turns a clip (masks are drawn in the view's frame, `clipCovers` checks in the clip's; `clipBounds`). - **Rulers and ruler guides** (`canvas/ruler-guides/`): a product that keeps guides gives the `guides` hook (`CanvasGuides`: `read(doc, scope)`/`write(doc, scope, guides)`, one module at most; the design keeps them on each page's record). A `RulerGuide` is `{ axis, value, frame? }` (on `x` a vertical line): a page guide crosses the whole canvas at `value`; a frame's guide (`frame`, an element id) counts from that element's corner, shows only inside it and moves with it. `placeGuides` turns them into `PlacedGuide`s (world value, `within` the frame's unturned bounds and its `rotation`; guides of a gone frame are left out), `guideInside` says whether one crosses its frame, and a turned frame's guides turn with it (`frameGuideEnds`, hit through `inGuideFrame`, dragged along the frame's axes, never snapped to). They're snap targets (`SnapSettings.guides`: edges without marks or boxes, `snapTargets(boxes, lines)`), and a press within 3 px of one (inside its frame; after handles, element interactions and rotate zones) is the `guide` interaction: the select tool drives a `GuideDrag` (`tools/guide-drag.ts`: snaps with `Snapper.line`, not to itself, `rulerGuideKey`; a frame's guide stays the frame's while it crosses it and becomes a page guide past its edges; dropped on its ruler, `overRuler` within `RULER_SIZE` = 20 px while the rulers show, it's removed). They redraw on `onViewChange` and selection changes. `CanvasViewOptions.rulers` says a product shows them (the design's).

- **Agent helpers** (`agent/`): `AgentTool<H>` (generic over what the tool can reach), argument parsers (`tool-args.ts`), `asUndoStep(doc, edit)`, and `buildElement` / `elementPatch` / `summarizeElement`, which go through the kinds. Products assemble their MCP tools from these.

## Elements

Everything on a canvas is an element. **Elements are plain data and behavior lives in kind classes.** Never branch on `el.type` outside an element's folder: ask its kind. The framework is in `canvas/elements/`; the element types live in their product's modules (`products/board/modules/<name>/`).

- **Data:** every element extends the `CanvasElement` interface (`id`, `type: string`, `index`, `x`, `y`, `w`, `h`) in `element.types.ts`. They're plain JSON because they live in the Yjs doc. **The set of types is open:** there's no closed union of types, so plugins can add types the engine has never heard of. Code outside an element's folder only sees `CanvasElement` and asks its kind. Patches are `ElementPatch<E>` (typed by the kind for its element), and the document takes the base `ElementPatch`.
- **Behavior:** each type has one `ElementKind<E, O>` subclass (`element.kind.ts`), registered in its product's `ElementKinds` (`element.kinds.ts`, a `Registry` from `utils/registry.ts` that throws on duplicate keys; `composeProduct` fills it from the modules' `boardCanvas.kinds` contributions). `kinds.kindOf(el)` returns it, and `kinds.isElement(data)` is true only for registered types. Every kind declares its metadata: `label`, `description` (tooltips, listings) and `tool`, the id of the tool that creates it. The hotkey isn't stored on the kind: `engine.elementInfo(type)` reads it from the keymap through `tool`. The toolbar takes element tools' label and description from `elementInfo`. A kind can provide:
  - `draw`, `bounds`, `hitTest`
  - `move`, `resizable` / `resize`, `keepsRatio` (always resize proportionally, not only with Shift)
  - `assets(el)`: the document assets it shows (e.g. an image's file)
  - `text`: an `ElementText` spec (`get`, `set`, `style`) that the `TextEditor` and the drawer share, so edited text lines up with drawn text. `fitContent` sizes the element to its unwrapped text (the editor grows while typing), and `removeWhenEmpty` deletes it when its text is emptied
  - `fillDefaults` (for older files)
  - `describe` (agent summaries), `completePatch(el, patch, context)` (fields that follow from an agent's patch, e.g. a text's size; it throws on invalid values, e.g. an unknown geo `kind`, and maps fields the element doesn't store, e.g. a connector's `from`/`to`, which `patchableFields` must list)
  - `optionsOf` / `restyle` (the tool options panel, typed with the product's options `O`)
  - `text.style(el).singleLine`: a one-line text (a name), where Enter finishes editing
  - `partAt(el, p)`, `partBounds(el, part)` / `removePart(el, part)`: a selected part of the single selected element (a table cell, picked by clicking the already selected element at `partAt`, which gets the click's Shift and Ctrl/Cmd to extend the current part; or a row, set by a handle with `ctx.setPart`; read as `EngineState.selectedPart`, cleared when the selection changes or Esc is pressed). The overlay outlines it and Delete removes it instead of the element.
  - `interactionAt(el, p, query)`: part of the element a press grabs before selecting it (a handle, a button). It returns an `ElementInteraction` (`cursor`, `press(ctx, p)`); `press` runs a one-shot action or returns an `ElementGesture` (`move`, `finish`, `cancel`, `onCameraChange`) that the select tool drives. Resize handles of the single selection win over it.
  - `handles(el, zoom)`: `ElementHandle`s the overlay draws while the element is selected or hovered (`look: "dot"` for small actions; `bar` and `add`, with `w`/`h`, for grips and "+" strips). A hovered element with handles stays hovered a little outside its bounds, so handles drawn outside it can be reached.
  - `boxed`: whether selection and hover outline its bounds (`false` for connectors, which show their ends)
  - `connectable` and `anchor(el, side)`: whether connectors attach to it, and where on each `ElementSide` (`BoxKind` is connectable; geo variants give their own `sideAnchor`)
  - `build(spec, index, context)` from an `ElementSpec` (agents' `create_shapes`), plus `creatable` and `patchableFields`. Type-specific spec fields are declared in `specProperties` (merged into the `create_shapes` schema) and read from `spec.args`; `context.lookup(ref)` finds elements by id or by a `key` given earlier in the same call.
- **Shared bases** (`canvas/elements/bases/`). Anything several types do goes in a base, never copied into each kind:
  - `BoxKind`: hit anywhere in the bounds, resizable.
  - `TextBoxKind extends BoxKind`: in-place `text` (get, set, describe). Subclasses only give `textStyle`.
  - `LineKind`: hit near a polyline `points`.
  - `ElementKind.specRect` turns a spec into bounds for `build`.
  - Factories start from `createElementBase(type, rect, index)` (`element.factory.ts`: id, type, index, bounds) and spread their own fields on top. The editor's aria label is `${kind.label} text`.
- **One folder per type** (in its module's folder, or a subfolder of it for families like `db/` and `er/`). Files are named `<name>.<role>.ts` so the role shows in the name:
  - `<type>.types.ts`: the data interface
  - `<type>.factory.ts`: `create<Type>()`, pure data with no rendering
  - `<type>.draw.ts`: the Pixi drawer
  - `<type>.kind.ts`: the `ElementKind` subclass
  - `<type>.defaults.ts`: one typed object (`STICKY_DEFAULTS`, `GEO_DEFAULTS`) that satisfies its `<Type>Defaults` interface, which extends `ElementDefaults` (`size?`, `fontSize?`). The kind exposes it as `kind.defaults`, so generic code (e.g. `loadFonts`) reads defaults through the kinds and never names a type's constants. Values every element shares (font family, line height, minimum size) are in `ELEMENT_DEFAULTS` (`canvas/elements/element.defaults.ts`). No loose constants.
  - `index.ts`: the folder's exports

  Extra pieces follow the same pattern (`stroke.outline.ts`, `geo/variants/<id>.variant.ts`, `variant.registry.ts`, `bases/box.kind.ts`), and one-off helpers keep plain names (`ellipse-arc.ts`). Element folders import the framework from `@canvas`. The board's types are:
  - `sticky/`: `StickyKind extends QuickConnectKind` (a `TextBoxKind`)
  - `connector/`: `ConnectorKind extends LineKind`. Each end (`start`, `end`) is free (`x`, `y`) or attached to a connectable element (`shapeId`, optional `side`). Its route (`straight` or `elbow`, `elbow-route.ts`), bounds and `points` are derived by `resolveConnectors`, part of the board's `resolveElements` (after the ER pass), so **read connectors from the scene**. Moving one moves only its free ends; `detachConnectors` (the board's `onRemove`) frees ends whose element was deleted. Selected, it shows its ends, which drag with `ConnectorDrag` (also used by the `connector` tool). `QuickConnectKind` (the base of `StickyKind` and `GeoKind`) shows a dot beside each side that drags out a new connector.
  - `text/`: `TextKind`, a free label sized to its text (`fitContent`, `removeWhenEmpty`), not resizable. The `text` tool types a draft, or edits the text of whatever it clicks.
  - `stroke/`: `StrokeKind extends LineKind`, a freehand stroke drawn with a `pen`: `"pen"` or `"highlighter"` (translucent, flat ends; the outline settings per pen are in `STROKE_DEFAULTS`). Selected strokes are recolored and resized from the panel (`restyle`). Agents draw strokes from `points` (a flat world-space list, plus `pen`, `size`, `smooth`; `stroke-spec.ts`) and patch their `color` and `size` (`strokeSizePatch`, shared with `restyle`).
  - `db/`: the database schema, one family in one folder:
    - `card/`: `DbCardKind`, the base of tables and enums (sized by content, not resizable, created by the `db` tool or DBML, never from an agent's spec; agents may only move them) and the card frame drawer and row layout.
    - `table/`: `DbTableKind`. Columns are a plain JSON array; a relation lives on the source column (`column.ref`) and points at the target by table/column **id**, so moves and renames never break it. Tables keep `indexes` and a `note`, drawn as bubbles beside the table (`noteHidden` is view state, written with `doc.updateUntracked`).     - `schema/`: tables, enums and stickies with a `noteName` (DBML sticky notes) form the board's single schema. `DbSchema` is the facade and the only place that edits it (`table-edits.ts`, `enum-edits.ts`, `schema-dbml.ts`); it observes the document only while something subscribes, so it needs no cleanup. The play and open buttons call `ctx.activate(id, EMBED_ACTIONS.…)`; `EmbedPlayer` (`modules/embed/ui/`, an overlay) handles them and only then mounts the YouTube iframe over the card (`EmbedPlayerFrame`, placed with `engine.worldRectToScreen` and `engine.onViewChange`). Icons are SVG drawn with `view.placeIcon` (`embed-icons.ts`: Lucide from the `lucide` package, YouTube from `simple-icons`).
  - `geo/`: `GeoKind extends QuickConnectKind`, which delegates the outline (and its connector `sideAnchor`s) to the element's variant. Each variant (`kind`: rectangle, ellipse, diamond, …) is a `GeoVariant` subclass in `geo/variants/<id>.variant.ts`, registered at runtime in `geoVariants` (`variant.registry.ts`), with its label, picker `icon` (an SVG path), default size, `outline` and optional `decorate`. `variantOf(id)` falls back to the rectangle for unknown ids. The shape picker lists `geoVariants.all()`. `PolygonVariant` covers the polygon ones.

- **Where the types live:** each is in its module (`products/board/modules/<name>/`: `draw` holds `stroke`, `geo`, `text`, `connector`, `section`, `table`, `image`, `sticker`, `sticky`, `embed`, `db`, `er`), and paths above are relative to it. A module's tools are `<name>.tool.ts`, its agent tools `<name>.agent-tools.ts`, its options `<name>-options.types.ts` and its panels in `ui/`.
- **Adding a type to a product:** write a module (see Modules): its folder in the product's `modules/`, contributing the kind to `boardCanvas.kinds` and, if it has one, the tool (with its `keys`) to `boardCanvas.tools` and its tool entry to `boardEditor.tools` (icon, placement; see Editors). Agents' `create_shapes` schema, `loadFonts` and `elementInfo` read the composed kinds. A geo variant is still `geoVariants.register(new MyVariant())`.

- **Rendering:** `ElementView` (`canvas/render/element-view.ts`) is the one Pixi container for every element. `sync(el, kind)` calls `kind.draw(view, el)`, and `view.placeText(text, style, w, h)` lays text out like the editor. `view.setPaints(layers, { alpha, visible })` draws a stack of paints above the base graphics (`PaintStack`, `render/paint-stack.ts`): `shape` layers (a fill or stroke traced into a `Graphics`; `draw(g, tools)`, where `tools.gradient(gradient, box, alpha)` is a fill style of a `Gradient` laid on a box: its texture, `render/gradient-texture.ts`, is drawn once per gradient (512² over the box's normalized area with a margin, mirrored past it, a 1024-color ramp (`gradientRamp`), dithered) and shared while views use it) and `image` layers (an asset fitted with `contain`/`cover`, `render/fit-image.ts`, masked by an outline), so images can sit between fills and under strokes. `view.setPaintTextMask(true)` shows the paints only through the view's text (drawn white; `render/text-mask.ts` draws its glyphs with Pixi's `CanvasTextGenerator` into an alpha mask) instead of the text itself. Nothing outside the element folders knows how an element looks.

## Modules

A feature is **one folder with one register file**: `products/<product>/modules/<name>/` holds its engine code (plain TS, the element folder's files, its tool, options type, agent tools), a `ui/` folder (React) and `<name>.module.ts`, which plugs it into every place it needs. Built-ins and plugins use the same API; only the module file and `ui/` may use React (ESLint).

- **The API** (`shared/core/modules/`): `definePoint<T>(id, { keyOf? })` is an `ExtensionPoint<T>`, a typed token exported next to the code that reads it (keyed points throw on a duplicate key, naming both modules). `defineModule({ id, requires?, after?, register(host) })`; `register` calls `host.contribute(point, ...items)`. `createModuleHost(modules)` sorts them (`requires` must be loaded, `after` only orders; cycles throw), runs every `register` and is read-only afterwards (`host.get(point)`, `host.find(point, key)`).
- **Canvas points** (`canvas/modules/`, `createCanvasPoints<O>(product)`, the board's `boardCanvas`): `kinds`, `tools` (`{ id, create(ctx), keys }`), `hostCommands` (`{ id, label, keys }`), `keybindings`, `options` (defaults of the options a module owns; given twice throws), `scopes`, `guides`, `clips`, `masks`, `effects`, `undrawn`, `rulerFrame` and `frames` (one module each), `effectRenderers` (keyed by type), `links`, `resolveElements`, `withMembers`, `alignTarget` (one module), `onRemove`, `prepareCopies`, `pasteText`, `pasteOnto`, `pasteImage`. `composeProduct(id, host, points)` turns them into a plain `CanvasProduct`: keybindings over `BASE_KEYBINDINGS` (a command bound twice throws), hooks chained in module order, the first paste that returns an element wins. So the order of modules matters: `text` is `after: ["embed"]` so a pasted link is a card before it's text, `er` is `after: ["section"]` (a section takes its contents, then ER elements their attributes) and `connector` is `after: ["er"]` (connectors are routed once ER boxes are placed). `sticky` and `geo` `requires: ["connector"]` for their quick-connect dots, and `db` requires `sticky` (DBML notes).
- **Editor points** (`canvas-ui/modules/`, `createEditorPoints(product)`, the board's `boardEditor`): see Editors. **Board points:** `boardAgentTools` and `boardMigrations` (`board-points.ts`; a migration brings an older file's document up to date when it opens), `boardLibrary` (`ui/components/library/library-points.ts`). A module can define points of its own for others to extend.
- **Options:** each module declares the options it owns (`StickyToolOptions`, `DbToolOptions`) and `BoardToolOptions` extends them; a plugin augments it (`declare module "@board" { interface BoardToolOptions extends MyOptions {} }`) and contributes the defaults.
- **The board's modules** are listed in `products/board/ui/modules/board-modules.ts`: `core` (the select and hand buttons, the agent tools that work on any element, in `agent/`), `library` (the library's command and built-in content), and one per feature. Plugins call `registerBoardModule(module)` before a board opens; the modules load on first use (`getBoardModules()`, `getBoardProduct()`, `getBoardEditorModules()`). New board features are written as modules.
- Example: `modules/sticky/sticky.module.ts` contributes the kind, the tool with its `S` key, the `stickyColor` default, the tool entry (toolbar position; it's listed in the library too) and the color panel (for the tool and for selected notes).
- **Plugins** are modules installed outside the source (guide: `docs/plugins.md`, example: `examples/plugins/callout/`). A plugin is a folder with `plugin.json` (`readPluginManifest`, `PLUGIN_API_VERSION` in `shared/core/plugins/`) and one ES module with no imports, whose default `activate(api)` returns modules; `api` is the `PluginApi` (`app/plugins/create-plugin-api.ts`: the module API, kind bases, canvas-ui chrome, the app's React, the board's points and the design's (`api.design`: points, node base, panel blocks, hooks); wrapped by `strictApi` so reading a name it doesn't have throws, naming it, while extension points stay the same objects).
  - **On disk:** `PluginStorage` (`shared/core`, `pluginStorage` in `@platform`): copied plugins in `<appData>/plugins/<id>/`, development folders linked in `plugins/index.json`.
  - **Loading:** `app/main.tsx` awaits `loadPlugins()` (`app/plugins/`) before rendering. Each enabled and trusted plugin is imported from a `blob:` URL (5 s timeout); `activate` returns modules for the one product in its manifest's `products`, or `{ board, design }`, registered with `registerBoardModule`/`registerDesignModule(module, { plugin })`. Plugin modules are **optional** for `createModuleHost` (`ModuleLoadOptions`): one that throws, misses a `requires`, collides on a key or loops is left out with its dependents and reported; `getBoardProduct` recomposes without plugins if composing fails. Built-in errors still throw.
  - **State:** `usePluginsStore` (`shared/stores/plugins-store.ts`): `enabled` and `trusted` are saved; what was found and each `PluginStatus` is not. Settings › Plugins (`pages/settings/sections/plugins/`) installs, links, removes, asks for trust before the first run, and offers a reload.
  - **MCP:** the agent server is built on the first request (`use-agent-server.ts`), so plugin tools are listed. `createAgentTools` leaves out a tool whose name is taken, and `list_plugins` (`agent/plugin-tools.ts`, `AgentHost.plugins`) reports the plugins and their tools (`ModuleHost.ownerOf`).

## Agent (MCP) server

Agents (Claude Code, Cursor, …) connect to the running app at `http://127.0.0.1:47821/mcp`. If that port is taken the server tries the next nine, and the URL is written to `mcp.json` in the app data folder. Access is on by default, with no auth: only loopback, with Host and Origin checked against DNS rebinding.

- **Rust is only the transport** (`src-tauri/src/mcp/`): Streamable HTTP (POST, plus DELETE to end a session). Each body is emitted to the webview as `mcp://message` with the agent's `Mcp-Session-Id` and User-Agent (`AgentMessage`) and answered through the `mcp_reply` command (30 s timeout), whose `session` becomes the response's `Mcp-Session-Id`. `mcp_status` and `mcp_set_enabled` back the UI.
- **Agents are collaborators** (see Collaborators and workspaces): sessions only tell agents apart. `handleMcpMessage(body, server, context, observer)` gives a session on `initialize` (unknown ids are kept, never refused), passes the `McpMessageContext` to `McpTool.run(args, context)`, appends `server.notesFor(context)` after a result, and reports to a `McpObserver` (`connected` with `clientInfo`, `seen`, `toolCall` → its outcome). `createAgentServerDefinition(hostFor, notesFor)` runs each call with `agentHostFor(presenceKey(context))` (`app/mcp/agent-host.ts`): the open file comes with that agent's own workspace (`withWorkspace`, `engine.workspace(id)`), so `AgentBoard`/`AgentDesign` are `AgentFile<BoardWorkspace | DesignWorkspace>` while the editors register `OpenBoard`/`OpenDesign` (the user's engine). `app/mcp/agent-presence-source.ts` is the agent presence source: identification (`identifyAgent`, `AgentClient.match` against the client's name or User-Agent; `agentName` numbers a second one, `agentColor` its brand colour or a free one), activity (`agentCallLabel`, a sentence from the tool's name, also stamped on the agent's undo steps with `history.setNextLabel`), and after each call (`trackAgentCall`: what changed in the workspace, else the ids the arguments name) the agent's selection becomes what it changed, its view follows (`followEdit`) and its cursor goes to the middle; failed calls toast. Steps the user undoes or redoes outside the agent's calls are noted (`createUndoNotes`) and sent with its next reply.
- **The protocol is TypeScript.** `shared/core/mcp/handle-mcp-message.ts` is a small hand-written JSON-RPC handler (`initialize`, `ping`, `tools/list`, `tools/call`). It reaches the platform through the `AgentChannel` interface (`shared/core/agent-channel.types.ts`, `platform/tauri-agent-channel.ts`), and `agentChannel` is `null` outside Tauri.
- **The board's tools are contributed by modules** to `boardAgentTools` (`board-points.ts`) as groups (`BoardAgentToolGroup`: `tools({ kinds })`), one group per file (`agent/`: `board-read-tools`, `shape-edit-tools`, `create-shapes-tool`, `arrange-tools`, `er-tools`, `view-tools`, `export-tools`, `file-tools`, `sticker-tools`; the db module's `db.agent-tools.ts`). `createAgentTools(modules, kinds)` collects them for `app/mcp`. Tools reach a board's facades through `board.engine.service(DB_SCHEMA | ER_MODEL)`. A tool is an `AgentTool<AgentHost>` and gets the `AgentHost` (the open board, recent files, opening a board). Every editing tool wraps its writes in `asUndoStep(engine.doc, …)` so one call is one step of the agent's own undo history (its workspace's; the user's Ctrl+Z doesn't undo it unless they follow the agent), and builds or validates everything before writing. `get_selection`/`get_design_selection` read the user's selection (`userSelection()`); `select_*`, `zoom_*`, `undo`/`redo` and `switch_page` act on the agent's own. Element tools go through the kinds (the canvas `buildElement`, `agentPatches`, `summarizeElement` with `engine.kinds`). `update_shapes` runs `agentPatches` (`canvas/agent/`): each patch is checked against `patchableFields` and the stored field types, a new `w`/`h` goes through `kind.resize` (`resizePatch`: proportions, minimums, a table's grid), the kind's `completePatch` validates the rest, and a moved element takes its `engine.withMembers(…, "move")` members along. `set_board_info` (`board-info-tools.ts`) sets the title and description, which `get_board` and the file tools return. `duplicate_shapes` is `engine.duplicateElements` (Ctrl+D's copy, with `prepareCopies`). The context menu's actions have tools that take ids and leave the selection alone: `reorder_shapes` (`engine.reorderElements`), `lock_shapes` (`engine.setLocked`), `copy_as_png` (`engine.copyAsPng(ids)`) and `export_shapes` (`engine.exportElements` with `ExportOptions.ids`, written by `AgentHost.writeFile`, `writeExportFile` in `@platform`, to a path or next to the board's file). `view_board` returns the board as a PNG: a tool returning a `ToolImage` (`shared/core/mcp`) is sent as MCP image content. `apply_er_text` creates entities a relation names (`createMissing`), as the DBML tools create missing tables. The MCP names still say "shapes" (`create_shapes`, …) so agents' setups keep working.
- **The design's tools are contributed by its modules** to `designAgentTools` (`design-points.ts`, `DesignAgentToolGroup`), each from its own folder: the core module's `modules/core/agent/` (`get_design`, `list_nodes`, `get_nodes`, `get_design_selection`, `set_design_info`, `create_nodes`, `update_nodes`, `delete_nodes`, `duplicate_nodes`, `select_nodes`, `reorder_nodes`, `lock_nodes`, `align_nodes`, `distribute_nodes`, `tidy_up_nodes`, `view_design`, `export_nodes`, `copy_nodes_as_png`, `zoom_design_to_fit`, `zoom_to_node`, `undo_design`, `redo_design`, `list_recent_designs`, `open_design`, `new_design`, `save_design`), and `frame.agent-tools.ts` (`list_frame_presets`, `add_preset_frame`), `group.agent-tools.ts` (`group_nodes`, `ungroup_nodes`), `layers.agent-tools.ts` (`get_layer_tree`), `pages.agent-tools.ts` (`list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`), `vector.agent-tools.ts` (`convert_to_vector`, `shapeToVector`, shared with the edit mode), `image.agent-tools.ts` (`add_image`, a picture file read with `DesignAgentHost.readFile`, `readLocalFile` in `@platform`; `replace_image`) and `text.agent-tools.ts` (`list_fonts`). The plumbing is `products/design/agent/` (`DesignAgentHost`, `requireDesign`, `requireNodes`, `createDesignAgentTools`, `DESIGN_AGENT_INSTRUCTIONS`). `create_nodes` builds through the kinds: a `creatable` `DesignNodeKind` gives `nodeFromSpec(spec, index, context)` (a `NodeBuildContext`: the tool options and `nameFor(base)`; `BoxShapeKind` makes any box shape, kinds add their `specProperties`), `buildNode` adds what every node takes (`applyNodeSpec`: name, visibility, opacity, `fill`/`fills`, `stroke`/`strokes`, `strokeWeight`, paints checked by `readPaints`), and the tool puts it in the container under it (`containerAt`) or the `parent` given (`checkParent`). `update_nodes` is `agentPatches`; `DesignNodeKind.completePatch` checks the shared fields (`checkNodePatch`, `parentId` included) and kinds check theirs (a text lays out again, a line's `points` and a vector's `network` re-wrap their bounds). Both products share `canvas/agent/` (`AgentFile`, `AgentRecentFile`, `AgentToolGroup`, `collectAgentTools`, `exportPath`, `elementSpec`, and `arrangeTools`, which makes each product's `align_*`, `distribute_*` and `tidy_up_*` tools: the board's `align_shapes`, … are in `agent/arrange-tools.ts`).
- **The app wires it up** in `app/mcp/` (`useAgentServer`, mounted by `<AgentServer />` in the providers): one server with the board's and the design's tools (one set of names, so neither shadows the other) and both products' instructions; `agentHost` implements `AgentHost` and `DesignAgentHost`. The open board and design register themselves for agents with `useAgentBoard` (`products/board/ui/agent/`) and `useAgentDesign` (`products/design/ui/agent/`), both `useAgentFile` on a `createActiveFile` (`canvas-ui/agent/`). The on/off setting is `shared/stores/agent-server-store.ts`, and `shared/agent-server/` is the menu in the top bars and the Settings panel (switch, URL, "Connect an agent…"), which open `ConnectAgentDialog` (`connect-agent-dialog/`): a grid of agent apps with their logos (`simple-icons`, Lucide where there's none), "Other AI tools", one app's setup (snippet, where it goes, "Add to …") and "Install manually" (the default settings: URL, transport, the generic JSON). The apps are data, `AGENT_CLIENTS` (`agent-clients.ts`: Claude Code, Codex, Cursor, VS Code, Antigravity, Gemini CLI, Claude Desktop through `mcp-remote`, Windsurf, and under `more` Zed and opencode; `GENERIC_AGENT_CLIENT` is the manual JSON); Cursor and VS Code have a one-click `installLink`, whose `cursor://`/`vscode:` schemes are allowed in the capabilities.

## Collaborators and workspaces

Everyone else on the user's files is a **collaborator**: agents, and people in live sessions, through the same model and UI.

- **Presence** (`shared/core/presence/`, plain data shaped like a Yjs awareness state): a `Collaborator` (`id`, `source`, `kind` `agent`/`user`, `name`, `color`, `avatar`, `permissions`, `running`, `lastSeen`) with its `CollaboratorState` (`fileId`, `scope`, `scopeLabel`, `cursor`, `viewport`, `selection`, `activity`). Sources write through a `PresenceSink` (`join`, `patch`, `leave`, `clearSource`), which `useCollaboratorsStore` (`shared/stores/collaborators-store.ts`) implements; it also holds `following` (`follow`, `unfollow`). `canUndoFor(c)` (`permissions.undo`) says whether the user may undo a collaborator's steps: agents yes, people no (their history is on their computer). The live sessions' room source (`canvas-ui/share/room-presence.ts`, `source: "room"`) maps awareness states to `join`/`patch`/`leave`, and the user's own state comes from the engine (see Live sessions).
- **Workspaces** (`canvas/workspace/`): a collaborator's own context on the document, so the user's page, mode, tool, selection and undo never change what it works on. `CanvasWorkspace<O>` is the context-level API agent tools use (elements of its scope, scope, selection, `userSelection()`, guides, the edits, exports, `zoomToFit`/`zoomToElement`, undo); `CanvasEngine` implements it for the user and `engine.workspace(id, init?)` makes an `ActorWorkspace` for a collaborator (`findWorkspace`, `dropWorkspace`; all dropped on close): a headless `Scene` of its scope (`productSceneHooks`, refreshed lazily), its selection, its `viewport` (`actor-viewport.ts`: `showArea`, `followEdit`, in the user's view proportions), its services (`ServiceCache` on its document) and its history. The edits the engine and workspaces share are plain functions over `WorkspaceParts` (`workspace/operations/`: delete, reorder, lock, move, arrange, transform, style, bounds, `sceneExportHost`).
- **Actor documents** (`canvas/document/`): `doc.runAs({ origin, placement }, fn)` makes the synchronous edits inside `fn` with another transaction origin and placement (calls nest), `doc.createHistory(origin)` is a `DocumentHistory` (a `Y.UndoManager` tracking only that origin; steps carry labels, `setNextLabel`, kept across undo and redo; `onChange` reports `added`/`undone`/`redone`/`cleared`), and `actorDocument(doc, { actor, history })` is a `Proxy` whose writes run as the actor and whose undo methods are its history's, typed `CanvasDocument` so tools, services and `asUndoStep` don't change. The user's own history is `doc.history` (`LOCAL_ORIGIN`).
- **Following** (Figma's): `engine.showViewport(rect)` glides the camera to show a rect exactly (`CameraGlide`, `camera.fitZoom`, reduced motion jumps), `engine.onUserCamera` fires only for the person's own wheel and pan input (following stops then), and `engine.setHistoryTarget({ owner, history })` makes Undo/Redo (commands, `HistoryControls`, `EngineState.canUndo`, `historyOwner`, `undoLabel`/`redoLabel`) step through someone else's history.
- **UI:** `shared/collaborators/` has `CollaboratorAvatar`, `CollaboratorStack` (top bars, Figma's: overlapping round avatars, at most `max` (3, the followed one always shown), the rest in a "+N" `CollaboratorOverflow` menu listing everyone; `followable` in editors: click follows or stops), `CollaboratorList` (the Agents menu's rows, with `actions`) and `useFollowToggle`. `canvas-ui`'s `CollaboratorLayer` (over both editors' canvas) draws the cursors and selection outlines of collaborators on this file and page (`agent-server-store.showCollaborators`) and, while following, `useFollowCollaborator` (their page and viewport drive the camera; Undo/Redo target their history when `canUndoFor`), the `FollowFrame` and the `FollowBar` (activity, page, labelled Undo/Redo, Stop following). `CollaboratorUndoButton` undoes an agent's last step from the menu (`useCollaboratorHistory`).
- **Live sessions** (people editing together; guide: `docs/collaboration.md`): the person sharing a file **is** the server, and guests connect to their app peer to peer; when the host stops or quits, the guests' editors close and nothing stays on their computers. Desktop only.
  - **Transport** (`ShareTransport`, `shared/core/share/share-transport.types.ts`; `shareTransport` in `@platform`, `null` in the browser): `host(relay, handlers)` / `join(addr, relay, handlers)` give a `ShareConnection` (`send`, `closePeer`, `peerPath` `direct`/`relay`, `stop`, which leaves a later session alone), frames reported to `ShareTransportHandlers` (`connected`, `frame`, `closed` `closed`/`lost`); `testRelay`. The desktop's is `TauriShareTransport` over `src-tauri/src/share/`: iroh 1.x (QUIC dialed by public key, hole punching, relay fallback, end to end encrypted), a fresh key per session, ALPN `cloudy-canvas/share/1`, length-prefixed frames on one bi-stream per peer, frames to the webview on a raw `Channel` prefixed with the peer number (u32 BE), `share://connected`/`share://closed` events with the webview's session id; commands `share_host`, `share_join`, `share_send` (raw body, `session`/`peer` headers), `share_close_peer`, `share_peer_path`, `share_stop`, `share_relay_test`. Relays: the official one the build was made with (`BUILT_IN_RELAY`, `shared/stores/built-in-relay.ts`, from `VITE_CLOUDY_RELAY_URL`/`VITE_CLOUDY_RELAY_TOKEN`: `.env.local`, or the `CLOUDY_RELAY_URL`/`CLOUDY_RELAY_TOKEN` secrets in the release workflow), used alone, or n0's public ones. Release builds always host through the official one (`hostingRelay`); `startHost` (`canvas-ui/share/start-host.ts`) starts the session again through n0's when it doesn't come online, and `useRelayStatusStore` (`builtInDownSince`, this run only; skipped for 5 minutes) makes Settings › Collaboration show `RelayDownNote` and the share dialog's `RelayNote` say so. Only development builds (`RELAY_CHOICE_IN_SETTINGS`) let Settings pick the relay (`useCollaborationStore`: `relayChoice` built-in, public or the user's own `customRelay`, e.g. `server/relay/`). The link carries the host's relay, so guests need no setup.
  - **Protocol** (`shared/core/share/protocol/`, `SHARE_PROTOCOL`): a frame is a tag byte then a control message as JSON (`ShareControl`: `hello` with the secret, identity and a `rejoin` key; `waiting`, `admitted` with role, `SharedFileInfo` (product, the host's `fileId`, name, plugins), host and rejoin key; `denied`, `role`, `removed`, `ended`; checked field by field, `decodeFrame`), a y-protocols sync message or an awareness update. Links are `cloudy-canvas://join/<ticket>` (`shareLink`, `readShareTicket`: base64url JSON of the host's address, relay and a 32-byte secret, `createShareSecret`); `parseAppLink` gives `{ action: "join" }`, followed to `/join/:ticket`.
  - **Sync** (`canvas/share/`, plain TS): a star. `ShareHost.start(options)` (the user's `CanvasDocument`, transport, relay, file info, identity) relays every document update (`doc.on("update")`) and awareness update to the admitted guests but the one it came from, applies a guest's sync messages with its own origin only when it can edit (`readSync`, `sync-messages.ts`: a viewer's writes are dropped), turns away wrong secrets and protocols, holds newcomers as `knocks` until `admit(peer, role)`/`deny`, and has `setRole`, `remove`, `peerPath`, `stop` (tells everyone `ended`, gives them a second to close); `state` is a `Store<ShareHostState>` (`guests`, `knocks`). `ShareGuest.join(options)` syncs into its own `Y.Doc` (`HOST_ORIGIN`), sends its edits while it can edit, retries a dropped connection for 30 s with its rejoin key (the host lets it back with its role), and ends on `ended`/`removed`/`denied` (`ShareGuestState`: `status` connecting → waiting → syncing → live, `reconnecting`, `closed` with `end`). Remote updates need nothing else: `doc.observe` redraws them, `afterEdit` runs only where the edit was made, `doc.history` ignores them, and the host's autosave saves them.
  - **Read-only:** `CanvasDocument.setReadOnly(true)` makes every local edit (elements, assets, meta, undo/redo) a no-op, tools, panels and agents alike; a viewer's editor has it and no toolbar.
  - **UI** (`canvas-ui/share/`): `ShareButton` (both top bars; a `LiveBadge` for guests) opens `ShareDialog` (`StartSharing`, then `HostingPanel`: the link, `GuestRow`s with Direct/Via relay, role and Remove, Stop sharing); `LiveSessionLayer` (both chromes) shows `ShareKnocks`. `startSharing`/`stopSharing`/`useHostedSession` hold the one hosted session (quitting stops it, `appLifecycle.onBeforeQuit`); `useHostedFile(file, engine)` marks the file context `live` (`LiveFile`: `side`, `role`, `host`) and stops sharing when the editor closes. Guests: `/join/:ticket` (`pages/join/`: the name asked once, the waiting screens, `useHeldGuest`, which keeps one `ShareGuest` across remounts, the missing-plugins notice, `ReconnectingBanner`), then `BoardEditor`/`DesignEditor` with `live` (the loader's `source.live`, `LiveBoardSession`/`LiveDesignSession` with `useLiveGuestFile`: the host's file id and name, never saved, no thumbnail or recents, read-only for viewers). Home's top bar has Join (paste a link). The name is asked once when the app starts without one (`NamePrompt`, `shared/profile/`, mounted in the providers), prefilled with `randomPersonName()` (`shared/core/presence/`: "Sleepy Puffin"), which is kept if the dialog is dismissed. Session hooks that write derived data run on the host only (`useEmbedPreviews`).
  - **Presence:** awareness states are `{ user: ShareIdentity, presence: CollaboratorState }` (`RoomPresence`); `useRoomPresence` (from `useHostedFile` and `useLiveGuestFile`) publishes the user's pointer (`clientToWorld`), view, selection and page at most every 50 ms and mirrors the others into the collaborators store (`mirrorRoomPresence`), so `CollaboratorLayer`, the stack and following work for people as for agents. Each person's agents on the shared file ride in their state (`RoomPresence.agents`, `RoomAgent`: id, name, app `clientId`, `idleFor` ms rather than a time, `running`, presence; `ownAgentsOn`/`roomAgents` in `room-agents.ts`, re-sent only when the user's own agents change): the others mirror them as `kind: "agent"` collaborators (`room:<client>:<agent id>`) drawn in the owner's colour with the app's logo, with `Collaborator.owner` (`collaboratorTitle`: "Claude Code · Sleepy Puffin" in cursors, outlines, the stack and the follow bar) and `permissions.undo: false` (only the owner undoes them). The Agents menu lists only this app's own (`AGENT_SOURCE`, `CollaboratorList`'s `source`). A viewer's agents can read: on a read-only document an actor document's writes throw `ReadOnlyDocumentError` (`canvas/document/`), and `get_board`/`get_design` report `editable: false`.
  - Testing on one machine: a debug build started with `CLOUDY_INSTANCE` set skips the single-instance plugin (`second_instance_allowed`, `src-tauri/src/lib.rs`).

## Editors (React)

- **Files:** every product's files go through `canvas-ui/file/`: `useCanvasFileLoader(id, { noun, open, create })` loads the `CanvasDocument` from `Storage` (or starts an empty one for a new id), `useCanvasFileSaver(id, engine, info, format)` saves it (a `CanvasFileFormat`: file type, noun, untitled name, `encode`) and is provided as `CanvasFileContext` (`useCanvasFile()`, read by `SaveIndicator` and `DocumentInfoPopover`, also in `canvas-ui/file/`), and `useCanvasThumbnail` takes the preview. A file is a 4-byte magic, a u32 format version and a Yjs update (`encodeCanvasFile`/`decodeCanvasFile`, `canvas/file/`): `CCBD` for `.cboard` (`products/board/file/board-file.ts`; the board's wrappers are `useBoardLoader`, `useBoardSaver`, `BOARD_FILE_FORMAT` in `products/board/ui/file/`), `CCDS` for `.cdesign` (`products/design/file/design-file.ts`, `useDesignLoader`, `DESIGN_FILE_FORMAT`). `TauriStorage` keeps a recent-files index (id → path) in the app data folder. Ctrl+S / Ctrl+Shift+S are engine commands that run the host's handlers (`engine.handleHostAction("save", …)`).
  - **Autosave** (`useCanvasAutosave`, driven by `useCanvasFileSaver`): 1.5 s after changes stop (at most every 10 s while editing), and once more when the editor closes. A board with no file is autosaved as a **draft** (`storage.saveDraft`: `<appData>/drafts/<id>.cboard`, `FileInfo.draft`, badged on Home); Save asks where to put it and the draft file is removed (`storage.save`), forgetting a draft deletes it, and clearing the recents keeps drafts. Revisions counted per change keep the board dirty when it changes mid-save. The top bar's `SaveIndicator` shows a cloud while saving and a checked cloud for 3 s after (`saved` in the file context); the unsaved dot shows only when autosave is off or failed. The setting is `shared/stores/autosave-store.ts` (on by default, Settings › Files & storage). Closing the window waits for the tasks set with `appLifecycle.onBeforeQuit` (`AppLifecycle` in `shared/core`, `platform/tauri-app-lifecycle.ts`, up to 5 s; it needs `core:window:allow-destroy`): pending autosaves are flushed. Home's previews are pictures of each file (`useCanvasThumbnail(id, engine, saved)`: `engine.thumbnail`, only when the document changed since the last one, taken after a manual save, when the quit dialog opens and as the editor's `onClose` task and a quit task (skipped when already taken); it returns `capture`, stored with `storage.saveThumbnail` in `<appData>/thumbnails/<id>.jpg`, removed when the file is forgotten); `useFileThumbnail` (`pages/home/`) loads them and reloads when `thumbnail-store` bumps the file's version. Saves pass the document's title and description to `storage.save`/`saveDraft` (`FileMeta`), so the recents show them (a draft is named by its title); the file's name opens `DocumentInfoPopover` to edit them.
  - The index is validated on read (`isFileInfo`), written atomically (temp file + rename) and edited one change at a time (`mutate`); an unreadable one is set aside as `recent-files.corrupt.json` (`storage.takeIndexReset()`). Saves are atomic too.
  - `useRecentFilesStore` holds the recents and the ids of `missing` files (re-checked on window focus), plus `open(path)`, `relocate(id)` and `forget(id)`. Home's cards show missing files with Locate… / Remove, and every card has a ⋯ and right-click menu (`use-file-actions.ts`).

It takes the preview (`capture`) as it opens. Leaving the editor inside the app (Back to home) doesn't ask; the preview is the editor's `onClose` task. `cloudy-canvas://` links (the deep-link plugin, scheme in `tauri.conf.json`; installers and the Arch desktop entry register it, dev builds and the AppImage register it at startup) arrive through `AppLinks` (`shared/core/app-links/`, `platform/tauri-app-links.ts`) and are read by `parseAppLink`: `open?path=<file>`, `board/<id>` / `design/<id>` (a recent file), `new/board` / `new/design`, `home`, `settings`; `app/open-requests/open-app-links.ts` follows them. A drop without a `.cboard`/`.cdesign` goes to the open editor's target in `file-drop-store` (registered by `useCanvasFileDrop(engine)` in `canvas-ui`), which adds the files to its canvas.
- **FigJam import** (`products/board/figjam/`, outside the `@board` barrel: loaded only by `import("@board/figjam")` in `importFigJamFile`, `ui/file/`; reading and converting run in a worker, `figjam-import.worker.ts` via `convertFigJamFile`, with the shared `@canvas/figma` reader): `.jam` files ("Save local copy…") opened, dropped or picked in Home's open dialog (`figmaImportOf(path)` in `shared/core`: `fig` → design, `jam` → board) become a new board draft named after the file. `convertFigJam` takes the first page and flattens frames, groups and sections into world coordinates (`convertFigJamNode`, one converter per node type in `convert/`): stickies, shapes with text and connectors keep their looks and text in `nodeGenerationData` parts (`generatedPart`: 0 the body, 1 the text); stickies → `sticky`, shapes → `geo` (by `shapeWithTextType`), texts → `text` (wrapped lines kept from `derivedTextData`), connectors → `connector` (built last, `FigJamOutput.defer`, ends on the elements their nodes became, `FigJamContext`; curved ones straight, labels become texts), sections → `section`, image fills → `image` (FigJam's white border as padding), link preview widgets → `embed`, marker vectors → `stroke`. What was lost is counted and shown in a toast (`toastImportWarnings`, `canvas-ui/file/import-steps.ts`, shared with the Figma import).

## Design (`products/design/`)

Figma-style files, built only from modules (`products/design/ui/modules/design-modules.ts`: `core`, `pages`, `frame`, `catalog`, `rectangle`, `group`, `mask`, `effects`, `shader-effect`, `layers`, `assets`, `plugins-tab`, …; plugins call `registerDesignModule`). Points: `designCanvas`, `designAgentTools` and `designMigrations` (`design-points.ts`) and `designEditor` (`ui/modules/design-editor-points.ts`): the shared editor points plus `leftTabs` (a left panel tab and its rail button, in the modes its `modes` lists, the default mode's when unset: `tabsForMode`, `useLeftTabs`), `propertySections` (a properties panel section for the Design or Prototype tab, shown `when(selection)` fits, by capability rather than type) and `mainMenu` (the logo's menu: engine commands, labelled and bound by the keymap, or `run({ engine, navigate })`; a group without a label is listed in the menu, labelled ones (File, Edit, View, …) open as submenus, `mainMenuSections`, and the menu scrolls past the window's height) `toolSidebars` (what the properties panel shows instead of the sections while a tool is on), `modeSidebars` (the same while a mode is on, keyed by mode) and `layerIcons` (icons of layer types no tool creates, e.g. groups). The core module gives the default mode's entry ("Design"), so the `ModeSwitcher` shows once a module adds a mode, and `useStartMode` (a session hook) opens a design in the mode its link asks for (`/design/<id>?mode=catalog`, Home's "New Catalog") or the one it was left in (`ui/stores/design-mode-store.ts`, per file). Kinds add `canGoInto(parent, parentKind)`, `layerName(el)` (`layerNameOf`), `strokable` and `imageFills` to the node base. `DesignToolOptions` extends the modules' options (`FrameToolOptions`, `RectangleToolOptions`) and plugins augment it.

- **Nodes** (`modules/core/node/`): every design element is a `DesignNode` (`name`, `parentId`, `visible`, `opacity`, `fills`/`strokes` as `Paint[]`, `strokeWeight`) and its kind extends `DesignNodeKind` (a `BoxKind`: skips hidden nodes when hit, fills the shared defaults, lists its image paints as `assets`; `container` for frames, `fillable` (false for lines)). The kinds form one hierarchy: `BoxShapeKind` (a shape drawn as a box: `createNode(rect, name, index, parentId, options)` and `clickSize(options)`, its defaults' `size` unless overridden, e.g. the frame's preset) is the base of `RectangleKind`, `EllipseKind`, `FrameKind` and `PointsShapeKind` (a shape outlined by `points(el)`, which gives its drawing and hit test: `PolygonKind`, `StarKind`); `LineKind` extends `DesignNodeKind` directly. A paint is a `SolidPaint`, a `GradientPaint` or an `ImagePaint` (`assetId`, `scaleMode`, Figma's: `fill` crops to cover, `fit` shows it all, `crop` shows what its `transform` (an `ImageTransform`) picks, `tile` repeats it at `scalingFactor` (default `DEFAULT_TILE_SCALE`, 0.5; the Scale tool scales it, `scaleTiles`); `rotation` turns `fill`/`fit`/`tile` by quarters; `imagePaint(assetId)`, `imagePlacement(paint)` is how it's drawn, `toCropPaint(paint, box, image)` a crop showing what it showed); the kind's `assets` are its image paints. **Cropping:** the image module's `cropImage` host command (toolbar `selectionActions` button, context menu; `useCropImageCommand`) or the paint picker's Crop (`PaintField` while open) put a fill in crop mode (`ui/stores/image-crop-store.ts`), and the image module's `ImageCrop` overlay shows the `canvas-ui` `ImageCropOverlay` over the layer (resizing the layer goes through `kind.resize`). The picker's `ImageEditor` has the four modes, Rotate 90° (`rotateTransform90` for a crop), the tile scale and a CSS preview (`imagePreviewStyle`). Agents give `crop: { x, y, w, h }` or `transform`, `scalingFactor` and `rotation` (`image-paint-args.ts`); the Figma import maps STRETCH (crop), TILE (`scale`) and `rotation` (`fig-image-paint.ts`). A `GradientPaint` is a canvas `Gradient` (`canvas/gradient/`: `type` `linear`/`radial`/`angular`/`diamond`, `stops` (`ColorStop`: position, color, opacity, optional `ease` to the next one), `transform`, Figma's 2×3 `gradientTransform` from the box's normalized space, and optional `interpolation`, `oklab` for smoother middles) plus opacity and visibility. `gradientPaint(type, from)` starts one as Figma does (the paint's color fading out, linear top to bottom, the others centered; `defaultGradientTransform`), `isGradientPaint` tells them apart, `gradientHandles`/`transformFromHandles` turn the matrix into the start, end and width handles and back, `rotateGradient90`, `flipGradient` (`flipPaints`, run by every kind's `flip`), `reverseStops`, `addStop`, `sampleStops` edit and sample them, and `gradientCss`/`parseCssGradient` go to and from CSS. Factories start from `createNodeBase`. **A node's shape is data:** `DesignNodeKind.geometry(el)` is its `NodeGeometry` (`{ fill, stroke }` `PathShape`s in local coordinates, the fill normalized so holes stay open), cached in `GEOMETRY_CACHE` (an LRU) by `type` + `geometryKey(el)` (only the fields that change the shape; a vector's is `identityKey(el.network)`, as stored networks are replaced, not changed) and worked out by `buildGeometry(el)` (`BoxShapeKind`: its `vectorNetwork` through `networkGeometry(net, normalize)`; frames and sections their rounded box; vectors their regions normalized by winding rule; lines a stroke-only path; text its glyphs). Drawing, hit tests, vector masks, booleans and Flatten all read it; `ownsShape` (false for groups) says whether a node has one of its own. Kinds `draw` with `drawPaints(view, node, geometry, kind.strokeOf(el))` (fills, consecutive solid and gradient ones in one drawing, gradients laid on the node's box, image fills clipped to the fill, then strokes, with the node's opacity and visibility, through `view.setPaints`; plugins' kinds may still pass a hand-traced `PaintOutline`); `traceBox` is a (rounded) box outline. Drawing tools extend `NodeDrawTool<E, S>` (`modules/core/tools/`, a template method: the press/drag/click gesture past `DRAW_THRESHOLD_PX`, naming ("Rectangle 3", `nextLayerName`), adding at the top, placing it in the frame under it with `parentFor` (`core/tree/parent-for.ts`), selecting it and returning to select, in one undo step); a subclass gives the shape `S` a drag or click makes (`dragShape`, `clickShape`, `createNode`, `shapePatch`). `BoxDrawTool` is the concrete tool for any `BoxShapeKind` (`new BoxDrawTool(ctx, kind)`: id from `kind.tool`, name from `kind.label`), so box shapes have no tool classes of their own; `LineTool` draws between two ends.
- **The layer tree** (`modules/core/tree/`): nodes store `parentId`; coordinates stay in world units. The core module gives the canvas `treeOrderKeys` (parents draw before their children, siblings by `index`), `withDescendants` (`withMembers`: a frame moves and deletes with what it holds), `reparentMoved` (`onMoved`: a dropped node goes into the topmost visible container under its center, `containerAt`) and `prepareTreeCopies`. `DESIGN_TREE` (`DesignTree`: `layers()`, `node`, `ancestors`, with `subscribe`/`getVersion`) is what the Layers tab reads. **Moving layers** (`core/tree/move/`) is one place for every caller: `moveIntoProblem(node, parent, kinds, byId)` is the rule set (the parent holds layers, `holdsLayers`: a `container` or a `childHost`; `canGoInto`; same page; not into itself), `LayerDestination { parentId, position }` (topmost first among the children that don't move), `layerChildren`, `layerDestinationAt(elements, id, "above" | "below" | "inside")`, `placeLayers` (indexes between the neighbours, order kept), `layerMovePatches` (checked) and `moveLayers(doc, kinds, ids, destination)` (writes them and prunes emptied groups and booleans; the caller makes the undo step). `checkParent` (agents' `parent`/`parentId`), `reparentMoved` (canvas drops) and the agents' `move_layers` (`layers/move-layers.agent-tool.ts`) use it. The Layers tab (`layers/ui/`) is a flat list of `visibleRows` (`LayerRowItem`; opened layers plus the selection's ancestors) drawn with `useVirtualList` (`shared/ui/hooks/`, fixed 28 px rows, `LAYER_METRICS`) and memoized `LayerRow`s; `drag/` drags rows Figma's way: `layerDrop` (pure: a row's top/bottom quarter drops above/below it, the middle into a layer that holds others, below an open layer is its top child, moving left below a last child goes out a level; refused places show nothing), `useLayerDrag` (pointer-based past `MOVE_THRESHOLD_PX`, drags the selection or the pressed row, scrolls at the edges, opens a closed layer held over, Esc cancels, one undo step) and `DropIndicator` (the line and a ghost label).
- **Pages** (`modules/pages/`): a page is a `page` element (`PageKind`: a record, never drawn or hit; its `index` orders the pages) and every node has `pageId`. `PAGE_SCOPES` is the design's `scopes`, so one page is on screen at a time and new nodes land on it (`createNodeBase` leaves `pageId` empty; `prepareTreeCopies` clears it so pastes go to the page on screen). `DESIGN_PAGES` (`DesignPages`) reads and edits them, one undo step each: `add(after, name?)` ("Page N"), `rename`, `duplicate` (the page and its nodes, `cloneElements`), `remove` (with its nodes; never the last page), `reorder(id, position)` and `moveNodes(ids, pageId)` (with descendants, on top, parents left behind become the top of the page). `ensurePages` (a `designMigrations` entry, also run on new designs by `newDesignDocument`) gives a design without pages "Page 1" and puts unplaced nodes on it. `DESIGN_TREE.layers(page)` reads one page's tree. UI (`modules/pages/ui/`): `PagesSection` at the bottom of the Layers tab (click shows a page, double-click renames, ⋯ renames, duplicates and deletes, rows drag to reorder, "+" adds one after the current), the Page section (its name, zoom), "Move to page" in the selection's context menu (a `ContextMenuSubmenu`: `canvas-ui` context menu items can be submenus of actions), and the `previousPage`/`nextPage` host commands (PageUp/PageDown, in the main menu). Agent tools: `list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`; every other tool works on the page on screen (`get_design` reports `currentPage`). Each page keeps its ruler guides (`PageElement.guides`, `PAGE_GUIDES` is the design's `guides`; duplicated with the page, frames' guides following their copies; a deleted frame's are dropped by `pruneFrameGuides`, an `onRemove`; kept from Figma pages by `figPageGuides`); the core module's `toggleRulers` (Shift+R), `toggleGuides` (Shift+;) and `clearGuides` host commands (`useViewCommands`, remembered in `ui/stores/design-view-store.ts`) are checkbox items of the main menu (`MainMenuItem.checked`), "Snap to guides" is in the `ZoomMenu`, and agents use `list_guides`, `add_guides` (with an optional `frame`) and `remove_guides` (`guides.agent-tools.ts`; `get_design` counts them).

## Code conventions

- **Small, single-purpose files:** one component, tool, layer or helper per file, re-exported through a folder `index.ts`. Split a file once it mixes concerns or grows past ~200 lines. Reuse the shared helpers before writing new ones:
  - `canvas/utils`: `Store`, `Emitter`, `Disposables`, `FrameScheduler`, `Registry`, `debounce`, `clamp`/`mod`.
  - `canvas/geometry.ts` (`roundPoint`, `roundRect`, `fitInView`, `rectCenter`, …) and `canvas/tools/drag-threshold.ts` (`pastThreshold`, `MOVE_THRESHOLD_PX` for dragging existing things, `DRAW_THRESHOLD_PX` for creating tools).
  - Text fields that commit on Enter/blur and revert on Escape: `useCommitField` + `commitFieldProps(field)` (`canvas-ui/components/commit-field/`), never hand-written key handlers.
  - `shared/core/keyboard.ts`
  - `shared/ui/layout`: `AppHeader`, `PageContainer`.
  - `shared/ui/hooks`
  - `canvas-ui` for editor chrome.
- **Types go in sibling `<file>.types.ts` files:**
  - Every `interface` and `type`, including component props, goes in a `.types.ts` file next to its code, and is imported with `import type`.
  - Barrels re-export them with `export type`.
  - Vendored shadcn primitives in `src/shared/ui/components/ui/` are exempt and stay as generated.

## Design system

- **Tokens** live in `src/shared/ui/styles/tokens.css` and are mapped to Tailwind in `src/app/styles.css`. Tailwind's default colors and radii are reset, so only design-system values exist.
  - Components use **semantic tokens only** (`bg-surface`, `text-muted-foreground`, `bg-primary`, …). They never hard-code colors or use the palette scales (`ice`, `seal`, `blush`, `sand`, `lilac`).
  - Canvas colors are tokens too (`--canvas-*`).
  - Code colors are tokens too (`--syntax-*`, read by the `CodeEditor` theme).
  - Document content colors (sticky/marker palettes in `products/board/palette.ts`) are data saved with the file, not theme tokens.
- **Sharp shapes:** the user dislikes rounded styles.
  - Radii are 4px for controls (`rounded-md`) and 6px for cards and menus (`rounded-card`/`rounded-lg`), with 8px as the maximum.
  - No pills.
- **Roles:** primary = ice blue, secondary = seal gray, accent = blush peach (use sparingly), board = sand, design = lilac. The mascot/logo is a "foca watona" (spotted seal) peeking over a canvas (`src/shared/ui/brand/`).
- **Light theme only for now.** `FORCE_LIGHT_THEME` in `src/shared/stores/theme-store.ts` (mirrored in the `index.html` bootstrap script) disables dark mode. The `.dark` tokens and the theme plumbing are kept for later.
