# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Cloudy Canvas (by DarkRedgm) is a desktop-first Figma + FigJam app built with Tauri 2, React 19, Vite, TypeScript (strict, `noUncheckedIndexedAccess`), Tailwind v4, shadcn/ui (Radix), Zustand and React Router. One app holds two **products** on one shared canvas engine: **Board** (`.cboard`, FigJam-style; the editor is at `/board/:id` and is being rebuilt on the element architecture, see Elements) and **Design** (`.cdesign`, Figma-style; the editor is at `/design/:id`, built on modules from the start: frames and rectangles in a layer tree so far, see Design). Roadmap: desktop with local files, then a web build of the same frontend, then real-time collaboration (Yjs + Hocuspocus, Laravel backend). It must build on both Windows 11 and Arch Linux.

## Commands

```sh
pnpm install
pnpm tauri dev      # desktop app
pnpm dev            # frontend only in a browser (native dialogs unavailable)
pnpm lint           # ESLint (flat config, eslint.config.js)
pnpm typecheck      # tsc for app + vite config (noEmit)
pnpm format         # Prettier (with tailwind plugin); format:check to verify
pnpm tauri build    # production bundle
pnpm release:linux  # AppImage (src-tauri/target/release/bundle/appimage/)
pnpm release:arch   # pacman package (packaging/arch/PKGBUILD, needs makepkg):
                    # packaging/arch/cloudy-canvas-<ver>-1-x86_64.pkg.tar.zst, with the
                    # desktop entry, icons and the .cboard/.cdesign mime types
pnpm release:win    # Windows installer cross-built from Linux (cargo-xwin, NSIS):
                    # src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/
pnpm release        # both
pnpm release:win:native  # on Windows itself: NSIS and MSI installers
```

There is no test framework. **Verification is `pnpm lint` and `pnpm typecheck` only** (plus `pnpm format:check`). Do not run `tauri dev`, cargo, builds or browser checks to verify changes unless asked.

`VITE_MOCK_RECENTS=true` in `.env.local` (see `.env.example`) fills the Home "Recent files" grid with mock data in dev builds. `/design-system` is a dev-only page that previews tokens and components.

## Project structure

`src/` is the frontend (shared by the desktop app and the future web build). `src-tauri/` stays next to it: it's the Rust crate for the desktop shell, built by cargo, and the Tauri CLI expects it at the root.

```
src/
  app/          shell: entry, router, providers, theme sync, MCP server wiring (app/mcp)
  platform/     Tauri implementations of the shared/core interfaces (storage, dialogs, agent channel)
  shared/       app-wide, product-agnostic
    core/       plain TS: ids, files, keyboard, Storage/AgentChannel interfaces, MCP protocol
    ui/         design system: tokens, shadcn components, layout, hooks, brand
    stores/     Zustand stores for app UI state (theme, recent files, agent server)
    agent-server/  the "Agents" menu shown in every top bar
  canvas/       the canvas engine every product shares (plain TS, no React, no product code)
  canvas-ui/    React pieces every editor shares: hosting an engine, chrome components
  products/
    board/      engine side: its points, palette, shared agent tools, file format
      modules/  one folder per feature (its element types, tools, agent tools + `ui/` +
                `<name>.module.ts`), see Modules
      ui/       the board editor (React); composes the product from the modules
    design/     engine side: its points, file format and modules (core: the node base and the
                layer tree; frame, rectangle, layers, assets, plugins-tab)
      ui/       the design editor (React): rail, left panel, properties panel, toolbar
  pages/        app pages that aren't a product: home, settings, design-system
```

### Layering (enforced by ESLint `no-restricted-imports`)

Path aliases: `@app/*`, `@pages/*`, `@platform`, `@shared/*` (`@shared/core`, `@shared/ui/…`, `@shared/stores/…`, `@shared/agent-server`), `@canvas`, `@canvas-ui`, `@board`, `@design` (`@board/ui`, `@design/ui` for the editors). They're defined in both `tsconfig.json` and `vite.config.ts`, so keep the two in sync (`components.json` uses them too).

- **Engine code is plain TypeScript**, so the web version can reuse it: `shared/core`, `canvas/`, and `products/*` outside their UI (`ui/`, `modules/*/ui/`, `modules/*/*.module.ts`) may not import a product's UI, React, UI layers (`@shared/ui`, `@shared/stores`, `@canvas-ui`, `@pages`, `@app`) or platform code (`@platform`, `@tauri-apps/*`).
- **Lower layers never know higher ones:** `shared/` can't import `@canvas`/`@canvas-ui`; `shared/`, `canvas/` and `canvas-ui/` can't import products. **Products can't import each other.**
- A product's `ui/` uses its own engine side through its barrel (`@board`), plus `@canvas`, `@canvas-ui` and `@shared/*`. Module files and module `ui/` reach the editor's pieces with deep imports (`@board/ui/board-engine-context`).
- Platform access goes through interfaces in `shared/core` (e.g. `Storage` in `storage.types.ts`), implemented in `platform/` (Tauri).
- Business logic lives in TypeScript, not Rust. `src-tauri/` registers plugins (dialog, fs, clipboard-manager, opener, single-instance, deep-link), holds window config/capabilities and file associations, runs the agent server's HTTP transport (`src-tauri/src/mcp/`, which carries no MCP logic), lists the installed fonts (`src-tauri/src/system_fonts.rs`, `fontdb`), hands over the paths the OS asks to open (`src-tauri/src/open_files.rs`) and the `cloudy-canvas://` links it opens (`src-tauri/src/app_links.rs`).
- Ids come from `createId()` (`crypto.randomUUID()`), never auto-increment.
- Zustand stores (`shared/stores/`) hold app UI state only, never canvas content.

## Canvas engine (`src/canvas/`)

The engine is the same for every product. **A product is a `CanvasProduct`** (`canvas-product.types.ts`): its `kinds` (`ElementKinds`), `createTools(ctx)` (added after the built-in select and hand tools), `keybindings` and `defaultOptions`. `O` is the product's tool options type, threaded through `CanvasEngine<O>`, `ElementKind<E, O>`, `ToolContext<O>` and `EngineState<O>`. Products are assembled from modules with `composeProduct` (see Modules): the board's is `getBoardProduct()` (`products/board/ui/modules/board-modules.ts`), the design's `getDesignProduct()` (`products/design/ui/modules/design-modules.ts`).

- **Services** (`canvas/services/`): `defineService(id, (doc) => facade)` is a typed token, and `engine.service(def)` (or `ctx.service(def)` in tools, `useService(def)` in React) creates the facade on first use, once per engine. Facades must need no cleanup (they observe through a `DocumentFeed`). The board's are `DB_SCHEMA` (`DbSchema`) and `ER_MODEL` (`ErModel`).

- `CanvasEngine` (`canvas-engine.ts`) is a coordinator, created with `{ product, theme, document? }`. It wires the pieces together:
  - `CanvasDocument`: the content, a Yjs doc.
  - `Camera`
  - `Scene`: element list, selection, hover and marquee, plus spatial queries.
  - `Renderer`: PixiJS.
  - The tools.
  - Input modules: pointer, wheel and keyboard.
  - `TextEditor`: a DOM textarea overlay. Tools type a new element's text with `ctx.editNewText(draft)`: the draft is added to the document (and selected) only when the edit is committed with some text. An element with several texts (a table's cells) names each with a `part` key (`ElementText.partAt`/`partBox`/`nextPart`/`firstPart`): double-click edits the part under the pointer, Tab moves to the next, and only that part's text slot is hidden while editing.
  - **Text and fonts** (`text/`): text is shaped by a `TextFont` (`textFont(size, options)`: family, weight, style, line height, letter spacing; the app's Inter by default), which drawing (`canvasTextStyle`, `view.placeText`, alignment left/center/right/justify, top/middle/bottom), measuring (`measureTextBlock`; `measureText`/`measureWrapped` are its app-font shorthands) and the editor (`textEditorStyle`) share. An element's text sizing is `fitContent`, `fitHeight` or, per element, `text.sizing(el)` (`content`/`height`/`fixed`). Kinds name the faces their text uses with `fonts(el)` (`FontRequest`); the engine's `FontTracker` loads each once through `CanvasEngineOptions.fonts` (a `FontLoader`; `useCanvasEngine` passes `fontLibrary` from `@platform`), then redraws the elements using it (`ElementView.refreshText`) after their kind's `fontsLoaded(el)` patch (e.g. an auto-sized text's new size, outside the undo history). Fonts are `FontLibrary` (`shared/core/fonts/`: types, weights and names, `closestVariant`, Google catalog and CSS parsing): `platform/fonts/` lists installed families (the Rust `system_fonts` command) and Google's (`fonts.google.com/metadata/fonts`, cached a week, a short fallback list offline), and loads a Google face as `FontFace`s from its CSS, caching the files in `<appData>/fonts/`.

  It exposes `kinds`, `keymap`, `commands` and `elementInfo(type)` to hosts. `mount(container, onLoading?)` opens the canvas fitted to its content (at most 100%): it builds the views a slice at a time (`Renderer.syncElementsChunked`, about 12 ms per frame), then waits for the scope's images (`Renderer.preloadImages`) and fonts (`FontTracker.settled`), at most 8 s, reporting each step as an `EngineLoading`; input starts once it resolves. `useCanvasEngine` returns `{ engine, loading }` and both editors show `CanvasLoadingOverlay` (`canvas-ui`) until the engine is there. Hosts close it with `engine.close()` (`useCanvasEngine` does on unmount): input stops, the tasks set with `engine.onClose(key, task)` run while it can still draw (at most 3 s), then it's destroyed. `engine.thumbnail({ width, height })` is a small JPEG of the whole canvas framed to that size (`export/thumbnail.ts`), or `null` when it's empty.

- **Registries are per product, never global.** Everything that needs an element's kind (document, scene, renderer, overlay, text editor, tools via `ctx.kinds`, agent helpers) gets the product's `ElementKinds` and calls `kinds.kindOf(el)`.
- **Content lives only in the Yjs doc.** Each element is a `Y.Map` inside the `"shapes"` map (the name is kept so existing files load). Order is a fractional-index string (`index`), and lexicographic order is z-order.
  - All edits go through `CanvasDocument` methods (`add`, `update`, `updateMany`, `remove`), which transact with `LOCAL_ORIGIN` so `Y.UndoManager` tracks only local changes.
  - Call `doc.checkpoint()` before a user action to start a new undo step.
  - Binary data (image files) lives in the doc's `"assets"` map (`doc.addAsset`, `doc.getAsset`), keyed by a `createId()` id that elements point at. It's outside the undo history and shared by copies of an element; nothing deletes unused assets yet. Kinds name the assets an element shows with `kind.assets(el)`. The renderer decodes each one once into a texture (`render/image-cache.ts`; SVGs are rasterized first, `render/svg-image.ts`), and a drawer shows it with `view.placeImage(assetId, box, fit?)` (proportions kept: `contain`, the default, or `cover`, which crops). SVG icons are drawn with `view.placeIcon(key, svg, box)`, parsed once per icon.
  - The document's own **title and description** live in its `"meta"` map (`doc.meta()`, `doc.setMeta(patch)`, `doc.observeMeta`; undoable like elements). The title is shown instead of the file name when set (`displayName(file)` in `shared/core`); `useDocumentMeta(doc)` (`canvas-ui`) reads it in React. `doc.onChange(listener)` fires on any change (elements, view state, assets, meta): it's what dirty tracking and autosave listen to.
  - A document reads elements through the product's kinds (`new CanvasDocument(kinds)`, `CanvasDocument.fromUpdate(kinds, bytes)`): `doc.get`/`doc.all` return only registered types, with `kind.fillDefaults` applied. Elements of unregistered types (e.g. DB or ER shapes in older boards) stay in the doc untouched but aren't shown.
- **Data flow is one-way.** Tools write to the document, and `doc.observe` reports `{ updated, removed }` ids. The engine then refreshes the `Scene`, syncs only the changed Pixi views (`render/layers/element-layer.ts`) and requests a frame.
  - Rendering is on demand: Pixi uses `autoStart: false`, and `FrameScheduler` renders at most once per animation frame.
  - **Render cost:** each frame, views outside `camera.visibleWorldRect()` are culled (`ElementView.cull`, from its cached drawn `extent()`). A clipped view gets a mask only when the clip cuts something off (`clipCovers`). Text textures are capped by their element's size (`cappedTextResolution`, at most 4096 px a side; resolution at most 4), and image textures are scaled down to 4096 px when decoded (`ImageCache`).
- **Tools** implement `Tool` (`tools/tool.types.ts`, `id: string`) and act only through `ToolContext`, never through the engine directly. Select and hand are built in (`createBaseTools`); a product adds its own in `createTools`. A tool previews an element it's creating with `ctx.setDraft(el)`: the draft layer draws it with its kind, like any element. Other gesture feedback (a line being dragged, a drop target) is a `Guide` set with `ctx.setGuide(fn)`, drawn above the elements. `ctx.setFaded(ids)` dims elements a gesture is about to remove (the eraser); switching tools clears it. `ctx.animateIn(ids)` plays a quick pop on elements a tool just added (`render/entrance.ts`; the element layers advance it each frame and the engine keeps requesting frames while it plays; skipped with reduced motion).
- **Product hooks** keep product features out of the engine:
  - `createLinks()` returns `CanvasLinks` (`links/`): lines derived from the elements (e.g. database relations), re-resolved on every document change and drawn under the elements, highlighted when they touch the selection.
  - Links can show text with `view.label(text, at, options)` (pooled text nodes, e.g. ER cardinalities).
  - **Element actions and DOM overlays:** a kind's `interactionAt` press can call `ctx.activate(elementId, action)` for something only the host can do (play a video, open a link); hosts listen with `engine.onElementAction`. DOM placed over an element follows it with `engine.worldRectToScreen(rect)` and `engine.onViewChange(listener)` (camera, resize and document changes).
  - `resolveElements(elements)` gives elements whose geometry follows others (ER aggregation boxes, constraints) their current geometry: `Scene.refresh()` runs it, and the elements it replaced are redrawn on every change. **Read geometry from the scene** (`engine.getElement`, `ctx.getElement`), not from `doc.get`; the stored bounds of derived elements are stale. The text editor places itself from the scene too.
  - `withMembers(ids, elements, purpose)` adds what goes with the ids when they're moved (`ctx.withMembers` in the select tool) or deleted (`engine.deleteElements`), e.g. an entity's attributes.
  - `onRemove(doc, removed, before)` cleans up after deletions (e.g. clears refs to deleted tables, frees connector ends), inside the same undo step. `before` is the scene as it was, so resolved geometry of removed elements is still readable.
  - `prepareCopies(copies, { copied, existing })` fixes copied elements before they're added (the board: free DB names via `prepareDbCopies`, a new ER diagram per source diagram via `prepareErCopies`, loose connector ends via `prepareConnectorCopies`). `pasteText(text, at, index, options)` turns text pasted from outside the app into an element (the board: a text element), and `pasteImage(image, view, index, options)` an image (the board: an image element, `createPastedImage`).
- **Scopes** (`CanvasScopes`, the product's `scopes`, one module at most): a document split into parts shown one at a time (the design's pages). `list(doc)` is the scope ids in order, `of(el)` an element's scope (`null`: never shown, e.g. the page records) and `place(el, scope)` puts a new element in one. The `Scene` holds only the current scope's elements (`Scene.scope`, `scopeIds`), so hits, selection, exports, thumbnails, links and agents' `engine.elements()` stay in it; `doc.setPlacement` (set by the engine) places every added element in the scope on screen, so tools, pastes and agents need no code for it. `engine.scope`/`engine.setScope(id)` (and `EngineState.scope`): switching clears the selection, goes back to the select tool and restores that scope's camera (or fits its content). When the scope on screen is deleted the next one shows; an undo or redo that only touched another scope shows that one. Elements updated into another scope leave the canvas like removed ones. `doc.addUntracked` adds outside the undo history (what a file needs when it opens).
- **View, order and drops:** `view` (`CanvasViewOptions`: `minZoom`, `maxZoom`, `grid`: `"dots"`, `"pixels"`, a one-unit grid drawn over the content from 800%, or `"none"`; unset values are `DEFAULT_VIEW_OPTIONS`, the board's) sets the camera's limits and the grid layer (`render/layers/create-grid-layer.ts`). `orderKeys(elements)` replaces `zOrderKey` as the drawing order (the design's layer tree): `Scene.orderKey` is what `ElementLayer` stacks by, and `Scene.restackedIds` are redrawn when a key changes without its element (a parent moved in the order). `clips(elements)` gives the world area clipped elements show in (`ElementClip`: a rect and a corner radius): `Scene.clipOf` is what `ElementLayer` masks views with (`ElementView.setClip`; layers get `LayerPlacement`: `orderOf` and `clipOf`), `Scene.elementAt` ignores clicks on clipped-away parts, and `Scene.replacedIds` (order or clip changed) are placed again. `editElement(el, ctx)` (point `editElement`) edits an element its own way on double-click (after groups are entered) and Enter, before its text (the design's vector edit mode). Tools may have `onActivate()` (feedback that stays while they're on) and `onCommand(command)`, which every command asks first (`engine.toolTakes`), so a mode can own Esc, Enter, Delete and Ctrl+A; `ctx.getTool()` is the active one. The editor point `toolbars` (`ToolbarModeEntry`: `tools`, `component`) replaces the main toolbar while one of its tools is on (`ModuleToolbar`). `selectTarget(hitId, { selection, deep, enter }, elements)` decides what a click selects (`ctx.targetAt`, `ctx.targetOf`; the select tool, double-click and right-click use it; e.g. a design group). `FreehandTool` (`tools/freehand-tool.ts`) is the base of freehand drawing tools (the board's marker, the design's pencil): it collects, previews, smooths (`smoothPoints`, `smooth-points.ts`) and adds. `onMoved(doc, moved, elements)` runs when the select tool finishes a drag (`ctx.moved`), in the drag's undo step (the design drops nodes into frames). The canvas theme is read from the editor's container (`readCanvasTheme(container)`), so a product can override the `--canvas-*` tokens (`[data-product="design"]` in `tokens.css`).
- **Frames:** a kind with `frame = true` (ER aggregation boxes, sections) is drawn in its own layer behind the links and the other elements, larger frames further back (`zOrderKey`, `elements/z-order.ts`), and a marquee selects it only when it encloses it.
- **Feeds:** board-level facades (`DbSchema`, `ErModel`) notify React through a `DocumentFeed` (`document/document-feed.ts`), which observes the document only while someone subscribes, so they need no cleanup and can be created in a `useMemo`.
  - Kinds offer `interactionAt` and `handles` (see Elements), which the select tool and overlay use.
- **Copy and paste** (`clipboard/`): `ElementClipboard` copies the selection with what moves with it (`withMembers(…, "move")`), as scene elements, to the system clipboard as JSON (`encodeClipboard`/`decodeClipboard`, tagged with the product id, with the assets they show in base64 so images paste into other files). `insertCopies` clones them (`cloneElements`: fresh ids and indexes, and `remapIds` rewrites every string equal to a copied id, so references between copies follow without knowing the types), runs the product's `prepareCopies`, offsets them with `kind.move` and adds them as one undo step. Pastes land 20 units further each time while the source is in view, otherwise centered in it. Anything else on the clipboard goes through `paste-external.ts`: an image (preferred over text) becomes an asset plus the product's `pasteImage` element, and text goes to `pasteText`. Files dropped on an open editor go the same way (`drop-files.ts`, `engine.dropFiles(files, clientPoint)`): images and SVGs through `pasteImage` (fit and centered on the drop point; SVGs are sized by `svgSize`), `.txt` files through `pasteText`, cascaded by a paste step, as one undo step. The system clipboard is the `Clipboard` interface (`shared/core/clipboard.types.ts`: text, plus `readImage()` as an encoded file; `platform/clipboard.ts`: Tauri's clipboard manager, whose RGBA images are encoded to PNG, or `navigator.clipboard` in the browser), passed as `CanvasEngineOptions.clipboard` by `useCanvasEngine`; without one, the engine uses a `MemoryClipboard`. The commands are `copy`, `cut`, `paste` and `duplicate` (Ctrl+D). Alt-dragging with the select tool duplicates in place (`ctx.duplicate`) and drags the copies.
- **Context menu, z-order, lock and export:** a right-click selects what's under the pointer (locked elements too; empty space clears the selection) and reports a `ContextMenuRequest` to `engine.onContextMenu` listeners; `CanvasContextMenu` (`canvas-ui/components/context-menu/`) shows it, its items are data (`SELECTION_MENU`, `CANVAS_MENU`: engine commands, labels from `BASE_COMMAND_LABELS`). `reorderSelection` (`bringToFront` `]`, `bringForward` Ctrl+], `sendBackward` Ctrl+[, `sendToBack` `[`) rewrites indexes with `reorderIndexes` (`elements/reorder.ts`: front/back of everything, or one step past the nearest overlapping element; frames keep their area order). An element with `locked` is skipped by `Scene.elementAt` (unless asked), `elementsInRect`, `findInteraction`, `selectAll` and the select tool's drags (`toggleLock` Ctrl+Shift+L, `unlockAll` Ctrl+Alt+Shift+L). `pasteToReplace` (Ctrl+Shift+R) pastes centered on the selection and removes it in the same undo step (`ElementClipboard.paste({ replace })`). Exports (`canvas/export/`): `engine.exportElements({ format, background, area })` draws the selection (with its `withMembers(…, "move")`) or the whole canvas off screen (`Renderer.snapshot`, fresh layers and the product's `createLinks()`, images loaded first) as PNG or JPG, a one-page PDF (`encodePdf`, a hand-written JPEG page) or CSV of the elements whose kind has `rows(el)` (tables, DB tables; `encodeCsv`). `copyAsPng` (Ctrl+Shift+C) writes one with `Clipboard.writeImage`. The `export` command (Ctrl+Shift+E) is a host action: `ExportDialog` (`canvas-ui/components/export-dialog/`) handles it and saves with `exportFile` from `@platform`.
- **Nudge, resize and size label:** the arrow keys nudge the selection (`nudgeLeft`…, Shift: `nudgeLeftFar`…, 10 units; `engine.nudgeSelection`, `engine.moveElements` with `withMembers(…, "move")`, locked ones stay, no `onMoved`, so nothing changes parent); a burst of presses is one undo step (`nudgeCheckpoint`, `canvas/arrange/nudge.ts`; tools take them with `onCommand` and `nudgeStep(command)`, e.g. vector edit mode nudges its points). The resize handles belong to a `ResizeTarget` (`handles/resize-target.ts`, `resizeTarget(selected, kinds)`): one resizable element, or a multi-selection with a resizable element in it, by the box round the outlined ones; `ResizeGesture` scales each element into the new box (`scaleRectInBox`, `geometry.ts`) through `kind.resize` (ones that can't resize move by their center, with their members). Shift (or any `keepsRatio` kind) keeps the proportions, Alt resizes round the center (`resizeRect(…, { keepRatio, fromCenter })`). `CanvasViewOptions.sizeLabel` (the design's) shows the selection's `W × H` in a tag under it (`render/layers/size-label-layer.ts`, from `OverlayState.size`).
- **Snapping and smart guides** (`canvas/snapping/`): a gesture asks `ctx.createSnapper(exclude)` (what it moves, with its members) for a `Snapper` (`GestureSnapper`) and calls `move(box, p)` (an offset for the moved box), `resize(box, handle, p)` (for the dragged sides) or `point(world, p)`, then `clear()` when it ends. Targets are collected on first use (`engine.snapTargets`: the scene's elements whose `kind.snapTarget(el)` is true (outlined ones; hidden design layers and groups aren't), clipped like they're drawn, on and around the screen) as sorted edge lists (`snapTargets`, `snap-edges.ts`: start, center and end lines, `nearestOffset`, `edgesAt`). A move snaps each axis to the nearest edge or to equal spacing (`equal-spacing.ts`: centered between its neighbors on the row, or repeating a gap of the row), whichever is closer within 5 screen px; with `pixelGrid`, axes nothing snapped are rounded to whole units. Ctrl/Cmd (`p.modKey`) turns object snapping off. The guides are a `SnapFeedback` (`lines` with × marks, `gaps` with their length) drawn in screen space by `render/layers/snap-layer.ts` in the `--canvas-snap` color (`CanvasTheme.snap`); `ctx.setSnapFeedback` shows any (the select tool's Alt + hover distances, `measureGaps`). Used by the select tool's moves, `ResizeGesture`, the design's `NodeDrawTool` and `LineEndDrag`. `SnapSettings` (`objects`, `pixelGrid`) start from `CanvasViewOptions.snapping` (the design's: both on; the board's: off), are `EngineState.snapping` and `engine.setSnapping(patch)`; `useCanvasEngine` applies the user's choice and `useSnapping()` (`canvas-ui`) changes and remembers it per product (`shared/stores/snapping-store.ts`). The toggles are in `ZoomMenu` ("Snap to pixel grid" only with the `pixels` grid).
- **Align, distribute and tidy up** (`canvas/arrange/`, pure functions over `ArrangeItem`s: `alignOffset`, `distributeOffsets` (the first and last stay, equal spaces, whole units), `tidyUpOffsets` (rows by middle, columns as wide as their widest item, the median spacing)): `arrangeItems` picks the outlined, unlocked ids that don't already move with another of them; the engine's `alignElements`/`distributeElements`/`tidyUpElements` (and the `…Selection` commands `alignLeft`, `alignCenterX`, `alignRight`, `alignTop`, `alignCenterY`, `alignBottom` (Alt+A/H/D/W/V/S, matched by `code`), `distributeHorizontal`/`distributeVertical` (Alt+Shift+H/V) and `tidyUp` (Alt+Shift+T)) move them with `moveElementsBy` (with their members) in one undo step, with no `onMoved`, so nothing changes parent. Several elements align with their bounds; one aligns with the product's `alignTarget` (the design: its nearest container, `containerAlignTarget`; the board: the smallest section it's in, `sectionAlignTarget`), and `engine.canAlign(ids)` says whether there's one. The selection's context menu has an "Align" submenu; the design's Position section has the buttons (`ArrangeButtons`).
- **Scale tool (K)** (Figma's): `ScaleTool` (`tools/scale-tool.ts`, a `SelectTool` with `resizeMode: "scale"`) is built in next to select and hand; products bind its key (`tool.scale`: K in the design, Shift+K on the board, where K is the sticker tool) and put it in the toolbar's `move` menu with select. The active tool's `Tool.resizeMode` is `Scene.resizeMode`, which `resizeTarget(selected, kinds, mode)`, `findInteraction` and the overlay read: in `scale` mode what's `scalable` gets handles (a line, a group, a board text too) and the box takes lines along. `ResizeGesture` in `scale` mode keeps the proportions and scales every element with its `withMembers(…, "move")` round the drag's fixed point (`resizeAnchor`: the opposite corner or side, the center with Alt; turned for a turned element) through `kind.scale(el, t)` (`ScaleTransform { origin, factor }`, `elements/element-scale.ts`: `scalePoint`, `scaleRect`, `scaleLength`, `scaleOffsets`; `scalePatches`, `canvas/arrange/scale.ts`). The default resizes a resizable element to its scaled box and moves the rest; `BoxKind` and `LineKind` (points) are `scalable`, and kinds scale what they draw: the design's nodes their `strokeWeight`, rectangles and frames their `cornerRadius`, texts `fontSize` and `letterSpacing` (laid out again), lines their ends, vectors their network (groups leave it to their children); the board's texts their `fontSize`, stickies and tables a `textScale` (font and insets, `tableTypography`), shapes their `fontSize` and `strokeWidth`, strokes and connectors their `size` (free connector ends move), images their `padding`; DB and ER elements only move. `engine.scaleElements(ids, factor, anchor)` (a `ScaleAnchor` of the box round them, `anchorPoint`, `SCALE_ANCHORS`) is one undo step: the design's `ScaleSidebar` (the tool's `toolSidebars` entry: W, H, %, the 3×3 `AnchorPicker`) and the agents' `scale_shapes`/`scale_nodes` (`canvas/agent/scale-tool.ts`, part of `arrangeTools`: `factor`, `width` or `height`, `anchor`) use it.
- **Rotation** (Figma's model): `CanvasElement.rotation` is degrees counterclockwise round the element's top-left corner (`x`, `y`); `w`×`h` is its unturned size, so growing from the corner (text, vector re-wrapping, right/bottom resizes) needs no correction. Kinds opt in with `ElementKind.rotatable` (the design's nodes; board kinds don't) and turn with `kind.rotate(el, degrees, pivot)` (the corner orbits, `rotation` adds up; the design's line turns its ends instead and keeps 0). Kinds work unturned: `Scene.elementAt` and `findInteraction` hand them `toUnrotated(p, el)`, `ElementView` places, turns and culls the view (`rotation.ts`: `rotatePoint`, `rotatedBounds`, `rotatedBoundsAround`, `pointInRotatedRect`, `normalizeAngle`, `angleOf`). `elementBounds(kind, el)` is where an element shows (the box round it when turned): hits, marquees, snapping, arranging, exports, thumbnails and paste placement read it; resizing reads `kind.bounds`. `ElementClip.rotation` turns a clip (masks are drawn in the view's frame, `clipCovers` checks in the clip's; `clipBounds`). The overlay draws `Outline`s (rect + rotation); a single turned element's resize handles sit on its turned box (`ResizeTarget.rotation`, `resizeHandlePoint`/`resizeHandleAt`/`resizeCursor` take it) and `ResizeGesture.resizeTurned` resizes it in its own frame; in a multi-resize turned elements follow by their center. A press just outside a corner of the selection's target when everything in it turns (`rotateZoneAt`, `ResizeTarget.resizable` false for turn-only targets like a group) starts a `RotateGesture` (round the target's center, Shift: 15° steps, the angle shown with `SnapFeedback.labels`, the `rotateCursor`). `engine.rotateElements(ids, degrees | (el) => degrees, "selection" | "each")` and the `rotateLeft`/`rotateRight` commands (no keys) turn with members in one undo step. The text editor turns its textarea.
- **Rulers and ruler guides** (`canvas/ruler-guides/`): a product that keeps guides gives the `guides` hook (`CanvasGuides`: `read(doc, scope)`/`write(doc, scope, guides)`, one module at most; the design keeps them on each page's record). A `RulerGuide` is `{ axis, value, frame? }` (on `x` a vertical line): a page guide crosses the whole canvas at `value`; a frame's guide (`frame`, an element id) counts from that element's corner, shows only inside it and moves with it. `placeGuides` turns them into `PlacedGuide`s (world value, `within` the frame's bounds; guides of a gone or turned frame are left out) and `guideInside` says whether one crosses its frame. The engine reads them once per document change (`ScopeGuides`, `engine.placedGuides()`): `engine.guides()`, `setGuides`/`addGuides`/`removeGuides(indexes?)` (one undo step each), `setGuidesShown` and `setRulersShown` (`EngineState.guidesShown`/`rulersShown`). `render/layers/ruler-guide-layer.ts` draws them as 1px filled rects in the snap color (across the view, or across their frame), with the dragged one's value (a frame's from its corner) by its ruler. They're snap targets (`SnapSettings.guides`: edges without marks or boxes, `snapTargets(boxes, lines)`), and a press within 3 px of one (inside its frame; after handles, element interactions and rotate zones) is the `guide` interaction: the select tool drives a `GuideDrag` (`tools/guide-drag.ts`: snaps with `Snapper.line`, not to itself, `rulerGuideKey`; a frame's guide stays the frame's while it crosses it and becomes a page guide past its edges; dropped on its ruler, `overRuler` within `RULER_SIZE` = 20 px while the rulers show, it's removed). The rulers are DOM (`canvas-ui` `Rulers`, `components/rulers/`): two `<canvas>` strips over the canvas's top and left edges (`drawRuler`, steps of 1/2/5 × 10ⁿ from `rulerStep(zoom)`, the selection's extent from `engine.selectionBounds()` with its values, which hide the numbers they'd overlap, colors from `--canvas-ruler*`), measuring `engine.rulerFrame()` (the product's `rulerFrame(selected, elements)` hook, one module, returns the element; the design's `selectionRulerFrame`: the container the selection shares, or a selected top-level container, unless it's turned): they count from its corner and number only its span, and a guide dragged out of them meanwhile is its guide (`engine.beginGuideDrag(axis, event)` returns a `GuideDragHandle`). They redraw on `onViewChange` and selection changes. `CanvasViewOptions.rulers` says a product shows them (the design's).
- **Commands and shortcuts:** every engine action is a command (`commands.ts`), every tool gets `tool.<id>`, and each of the product's `hostCommands` (e.g. the board's `openLibrary`) runs the handler the host registered with `engine.handleHostAction(id, handler)`. **A product's `keybindings` are the single source for shortcuts**: `BASE_KEYBINDINGS` (`input/base-keybindings.ts`) plus the `keys` its modules give their tools and host commands. The engine wraps them in a `Keymap`; the UI reads labels with `engine.keymap.label(command)`, so never hard-code shortcut strings in components. Key matching and formatting helpers live in `shared/core/keyboard.ts` (shared with the `useHotkey` hook in `shared/ui/hooks/`).
- **UI state** is exposed as an immutable `EngineState` snapshot (`utils/store.ts`, shallow-compared), via `engine.subscribe` / `engine.getState`.
- **Agent helpers** (`agent/`): `AgentTool<H>` (generic over what the tool can reach), argument parsers (`tool-args.ts`), `asUndoStep(doc, edit)`, and `buildElement` / `elementPatch` / `summarizeElement`, which go through the kinds. Products assemble their MCP tools from these.

## Elements

Everything on a canvas is an element. **Elements are plain data and behavior lives in kind classes.** Never branch on `el.type` outside an element's folder: ask its kind. The framework is in `canvas/elements/`; the element types live in their product's modules (`products/board/modules/<name>/`).

- **Data:** every element extends the `CanvasElement` interface (`id`, `type: string`, `index`, `x`, `y`, `w`, `h`) in `element.types.ts`. They're plain JSON because they live in the Yjs doc. **The set of types is open:** there's no closed union of types, so plugins can add types the engine has never heard of. Code outside an element's folder only sees `CanvasElement` and asks its kind. Patches are `ElementPatch<E>` (typed by the kind for its element), and the document takes the base `ElementPatch`.
- **Behavior:** each type has one `ElementKind<E, O>` subclass (`element.kind.ts`), registered in its product's `ElementKinds` (`element.kinds.ts`, a `Registry` from `utils/registry.ts` that throws on duplicate keys; `composeProduct` fills it from the modules' `boardCanvas.kinds` contributions). `kinds.kindOf(el)` returns it, and `kinds.isElement(data)` is true only for registered types. Every kind declares its metadata: `label`, `description` (tooltips, listings) and `tool`, the id of the tool that creates it. The hotkey isn't stored on the kind: `engine.elementInfo(type)` reads it from the keymap through `tool`. The toolbar takes element tools' label and description from `elementInfo`. A kind can provide:
  - `draw`, `bounds`, `hitTest`
  - `move`, `resizable` / `resize`, `keepsRatio` (always resize proportionally, not only with Shift)
  - `assets(el)`: the document assets it shows (e.g. an image's file)
  - `text`: an `ElementText` spec (`get`, `set`, `style`) that the `TextEditor` and the drawer share, so edited text lines up with drawn text. `fitContent` sizes the element to its unwrapped text (the editor grows while typing), and `removeWhenEmpty` deletes it when its text is emptied
  - `fillDefaults` (for older files)
  - `describe` (agent summaries), `completePatch(el, patch, context)` (fields that follow from an agent's patch, e.g. a text's size; it throws on invalid values, e.g. an unknown geo `kind`, and maps fields the element doesn't store, e.g. a connector's `from`/`to`, which `patchableFields` must list)
  - `optionsOf` / `restyle` (the tool options panel, typed with the product's options `O`)
  - `text.style(el).singleLine`: a one-line text (a name), where Enter finishes editing
  - `partAt(el, p)`, `partBounds(el, part)` / `removePart(el, part)`: a selected part of the single selected element (a table cell, picked by clicking the already selected element at `partAt`, which gets the click's Shift and Ctrl/Cmd to extend the current part; or a row, set by a handle with `ctx.setPart`; read as `EngineState.selectedPart`, cleared when the selection changes or Esc is pressed). The overlay outlines it and Delete removes it instead of the element.
  - `interactionAt(el, p, query)`: part of the element a press grabs before selecting it (a handle, a button). It returns an `ElementInteraction` (`cursor`, `press(ctx, p)`); `press` runs a one-shot action or returns an `ElementGesture` (`move`, `finish`, `cancel`, `onCameraChange`) that the select tool drives. Resize handles of the single selection win over it.
  - `handles(el, zoom)`: `ElementHandle`s the overlay draws while the element is selected or hovered (`look: "dot"` for small actions; `bar` and `add`, with `w`/`h`, for grips and "+" strips). A hovered element with handles stays hovered a little outside its bounds, so handles drawn outside it can be reached.
  - `boxed`: whether selection and hover outline its bounds (`false` for connectors, which show their ends)
  - `connectable` and `anchor(el, side)`: whether connectors attach to it, and where on each `ElementSide` (`BoxKind` is connectable; geo variants give their own `sideAnchor`)
  - `build(spec, index, context)` from an `ElementSpec` (agents' `create_shapes`), plus `creatable` and `patchableFields`. Type-specific spec fields are declared in `specProperties` (merged into the `create_shapes` schema) and read from `spec.args`; `context.lookup(ref)` finds elements by id or by a `key` given earlier in the same call.
- **Shared bases** (`canvas/elements/bases/`). Anything several types do goes in a base, never copied into each kind:
  - `BoxKind`: hit anywhere in the bounds, resizable.
  - `TextBoxKind extends BoxKind`: in-place `text` (get, set, describe). Subclasses only give `textStyle`.
  - `LineKind`: hit near a polyline `points`.
  - `ElementKind.specRect` turns a spec into bounds for `build`.
  - Factories start from `createElementBase(type, rect, index)` (`element.factory.ts`: id, type, index, bounds) and spread their own fields on top. The editor's aria label is `${kind.label} text`.
- **One folder per type** (in its module's folder, or a subfolder of it for families like `db/` and `er/`). Files are named `<name>.<role>.ts` so the role shows in the name:
  - `<type>.types.ts`: the data interface
  - `<type>.factory.ts`: `create<Type>()`, pure data with no rendering
  - `<type>.draw.ts`: the Pixi drawer
  - `<type>.kind.ts`: the `ElementKind` subclass
  - `<type>.defaults.ts`: one typed object (`STICKY_DEFAULTS`, `GEO_DEFAULTS`) that satisfies its `<Type>Defaults` interface, which extends `ElementDefaults` (`size?`, `fontSize?`). The kind exposes it as `kind.defaults`, so generic code (e.g. `loadFonts`) reads defaults through the kinds and never names a type's constants. Values every element shares (font family, line height, minimum size) are in `ELEMENT_DEFAULTS` (`canvas/elements/element.defaults.ts`). No loose constants.
  - `index.ts`: the folder's exports

  Extra pieces follow the same pattern (`stroke.outline.ts`, `geo/variants/<id>.variant.ts`, `variant.registry.ts`, `bases/box.kind.ts`), and one-off helpers keep plain names (`ellipse-arc.ts`). Element folders import the framework from `@canvas`. The board's types are:
  - `sticky/`: `StickyKind extends QuickConnectKind` (a `TextBoxKind`)
  - `connector/`: `ConnectorKind extends LineKind`. Each end (`start`, `end`) is free (`x`, `y`) or attached to a connectable element (`shapeId`, optional `side`). Its route (`straight` or `elbow`, `elbow-route.ts`), bounds and `points` are derived by `resolveConnectors`, part of the board's `resolveElements` (after the ER pass), so **read connectors from the scene**. Moving one moves only its free ends; `detachConnectors` (the board's `onRemove`) frees ends whose element was deleted. Selected, it shows its ends, which drag with `ConnectorDrag` (also used by the `connector` tool). `QuickConnectKind` (the base of `StickyKind` and `GeoKind`) shows a dot beside each side that drags out a new connector.
  - `text/`: `TextKind`, a free label sized to its text (`fitContent`, `removeWhenEmpty`), not resizable. The `text` tool types a draft, or edits the text of whatever it clicks.
  - `stroke/`: `StrokeKind extends LineKind`, a freehand stroke drawn with a `pen`: `"pen"` or `"highlighter"` (translucent, flat ends; the outline settings per pen are in `STROKE_DEFAULTS`). The `marker` tool (M) draws with the `drawPen` option, each pen with its own color and size options; with `drawSmooth`, the points are smoothed on release (`smoothPoints`: simplify, then round the corners), so nothing in the data marks it. Selected strokes are recolored and resized from the panel (`restyle`). The `eraser` tool (Shift+E) removes whole strokes: the ones it touches fade (`ctx.setFaded`) and are deleted on release as one undo step. The toolbar's Draw button stays active for both tools (`subTools` on its tool entry), and its panel is `ui/draw-options.tsx`. Agents draw strokes from `points` (a flat world-space list, plus `pen`, `size`, `smooth`; `stroke-spec.ts`) and patch their `color` and `size` (`strokeSizePatch`, shared with `restyle`).
  - `db/`: the database schema, one family in one folder:
    - `card/`: `DbCardKind`, the base of tables and enums (sized by content, not resizable, created by the `db` tool or DBML, never from an agent's spec; agents may only move them) and the card frame drawer and row layout.
    - `table/`: `DbTableKind`. Columns are a plain JSON array; a relation lives on the source column (`column.ref`) and points at the target by table/column **id**, so moves and renames never break it. Tables keep `indexes` and a `note`, drawn as bubbles beside the table (`noteHidden` is view state, written with `doc.updateUntracked`). A column's `type` is the bare name (`varchar`) and its arguments live in `typeArgs` (`column-type.ts`; aliases like `int` → `integer` are normalized, `type-aliases.ts`). The kind offers the note ×/icon and the column handles (`db-table.interactions.ts`); dragging a handle runs `ColumnConnectGesture`, which links the dropped-on row (a header means its primary key).
    - `enum/`: `DbEnumKind`; columns use an enum by naming it as their type.
    - `schema/`: tables, enums and stickies with a `noteName` (DBML sticky notes) form the board's single schema. `DbSchema` is the facade and the only place that edits it (`table-edits.ts`, `enum-edits.ts`, `schema-dbml.ts`); it observes the document only while something subscribes, so it needs no cleanup. DBML is a generated view (`dbml/`: a hand-written parser and serializer for a subset). Parsed text goes through `reconcile*.ts`, which match by name then position so ids survive; `add-missing-tables.ts` creates tables that refs name but nothing defines (on import, paste and blur only). `layout/` tidies it: `schemaGraph` links tables and enums (relations and enum types), `connectedGroup` finds a card's linked group (`DbSchema.connectedTo`, the panel's Select linked), and `tidySchema` (`DbSchema.tidy`, the panel's Tidy up, the `tidy_schema` agent tool) lays each group out in layers (referenced cards left of their users, barycenter ordering, linked rows leveled), stacks the groups and wraps unlinked cards below.
    - `links/`: `DbLinks`, the board's `CanvasLinks` for relations (crow's feet) and enum links. `pruneRefs` is the board's `onRemove`.
  - `er/`: ER diagrams (Chen notation with the extended model; the language is documented in `docs/er-language.md`), one family in one folder:
    - `base/`: `ErKind` (part of a diagram; created by the `er` tool or the ER text, never from an agent's spec; agents may only move them), `ErNamedKind` (the name is edited in place on one line; elements sized by their name resize round their center), `ER_DEFAULTS`, sizes (`er-size.ts`), outlines (`er-outline.ts`) and the shared types. Every element has `diagram` (an id) and `diagramName` (repeated on each element of the diagram): **a board holds several diagrams**.
    - One folder per type: `entity/` (rectangle, doubled when `weak`), `relation/` (diamond, `identifying`, `idMark`; `participants` point **by id** at entities or aggregations, with `(min,max)`, a role and `arrow`), `attribute/` (`ownerId` is an entity, relation, composite attribute, hierarchy or aggregation; key/multi/derived/optional flags, a `look`, an `order`), `isa/` (hierarchy triangle with `parentId` and children), `aggregate/` (a frame, hit by its name strip or border) and `constraint/` (hit near its line). Aggregations' and constraints' geometry is derived (`model/resolve-er.ts`, the board's `resolveElements`).
    - `model/`: `ErModel` (board-level facade: `diagram(id)`, `diagrams()`, `shape(id)`, `remove(id)`, `newDiagram(center?)`) and `ErDiagram` (`text()`, `applyText`, `textRange`, `relayout`, `rename`, `edits`). The text is parsed with the DBML tokenizer (`lang/`) and reconciled by name then position so ids and positions survive (`reconcile-er.ts`, `reconcile-extended.ts`); `applyErPlan` writes one undo step and lays out new elements (`layout/`, deterministic auto-layout). `withErMembers` is the board's `withMembers` (an element takes its attributes; dragging an aggregation takes what it holds), `pruneEr` part of its `onRemove`. Boards from before diagrams existed are split into diagrams when the file opens (`migrateErDiagrams`, the er module's `boardMigrations` entry, run by `openBoardDocument`).
    - `links/`: `ErLinks`, the lines (participants with cardinality labels, attributes, hierarchies; loops for self-relations).
  - `section/`: `SectionKind extends TextBoxKind`, a frame (`frame = true`) with its title edited in place in the strip along its top edge. It's hit by its title or border only, so clicks inside reach its contents. Membership is geometric: the elements fully inside it move and delete with it (`withSectionMembers`, part of the board's `withMembers`), so nothing stores parent links. The top bar's Sections menu (`ui/sections-menu/`) zooms to one.
  - `table/`: `TableKind extends BoxKind`, a grid of cells (`columns` widths, `rows` heights, `cells[row][column]`, `fills[row][column]` per-cell colors (`""` for none), `header`, `color` the header tint). Rows grow to fit their text (`fitRows`); every grid edit is a patch builder in `table-edits.ts` (`insertLine`, `removeLine`, `moveLine`, `resizeLine`, `scaleTable`, `gridFromCells`) that also returns the bounds. Cells are text parts (`"r:c"`, `table-parts.ts`); selected, it shows "+" strips (add a row/column), grips (`"row:i"`/`"column:j"` parts, dragged to reorder with `TableReorderGesture`) and resizable grid lines (`TableLineGesture`). Clicking a cell of a selected table selects it (Enter edits it, Delete clears it); Shift-click selects the block from the first selected cell, Ctrl/Cmd-click adds or removes one (`clickedCells`; several cells are one part, `"0:0,0:1"`). The options panel (`table-options.tsx`) picks the header and its tint, or, with a cell, row or column selected, its fill (`table-cell-fills.tsx`, `fillCells`), and inserts or deletes the selected row or column. `useEngineElement(id)` (`canvas-ui`) re-reads an element as it changes. Agents create it with `cells`, `header` and `fills` (`table-args.ts`), and patch those, `w`/`h` (scaled with `scaleTable`) and `color`.
  - `image/`: `ImageKind extends BoxKind`, a picture pasted from the clipboard (`assetId` points at the document asset). Its bounds include its `padding` (default 0) and its `background` is `"none"` (transparent, the default) or `"white"`, both picked in the options panel (`ui/image-options.tsx`); changing the padding grows the bounds around the image. It always resizes proportionally (`keepsRatio`) and isn't created by agents; they move and resize it and set `background` and `padding` (`imagePaddingPatch`, shared with `restyle`).
  - `sticker/`: `StickerKind extends BoxKind`, a stamped reaction (`keepsRatio`, not connectable, not in `create_shapes`: agents use `list_stickers` and `stamp_stickers`, `sticker.agent-tools.ts`, which take built-in and emoji ids but not custom ones). Its picture is a document asset whose id derives from the sticker's catalog id (`stickerAssetId`: `sticker:seal:happy`, `sticker:emoji:1f44d`, `sticker:custom:<id>`), so every stamp of one sticker shares one copy; `label` and `sticker` feed `describe`. The `sticker` tool (K) stamps the `sticker` tool option (`PickedSticker`: the catalog id, label, asset id and the picture's bytes, stored with `doc.addAsset` on first use) and stays on, with a preview under the pointer; each stamp pops in with `ctx.animateIn`. The catalog is `catalog/`: the "foca watona" moods (`seal/`, SVG built from a shared head plus eyes, mouths and props) and the common stamps (`common/`), both wrapped by `stickerSvg` (a white die-cut edge), and the emojis (`emoji/`: Twemoji art from `@twemoji/svg` via `import.meta.glob`, names and groups from `emojibase-data`; loaded with a dynamic `import()`). The UI (`ui/sticker-picker/`) is the tool's options panel: a wheel of the recently used stickers (`ui/stores/sticker-recents-store`, persisted) around a button that opens a tabbed panel (Stickers, Emojis, Custom) with one search. Custom stickers are the user's library (`StickerLibrary` in `shared/core`, `stickerLibrary` and `importStickerFiles` in `@platform`: files in `<appData>/stickers/` with an `index.json`), held by `custom-stickers-store`.
  - `embed/`: `EmbedKind extends BoxKind`, a pasted link shown as a card (the board's `pasteText` makes one when the text is a single http(s) URL, `createPastedEmbed`). `provider` is `youtube` (plays in place) or `link` (opens in the browser). It's created `loading` (and again when an agent patches its `url`); `useEmbedPreviews` (`modules/embed/ui/`, a session hook) runs `loadEmbedPreview` with `http` from `@platform`, which fetches the title and picture (`fetchLinkPreview` in `shared/core/links/`: YouTube oEmbed and thumbnails, other pages' Open Graph tags), stores the picture as an asset and writes them with `doc.updateUntracked`. The height follows the width (`embedHeight`). The play and open buttons call `ctx.activate(id, EMBED_ACTIONS.…)`; `EmbedPlayer` (`modules/embed/ui/`, an overlay) handles them and only then mounts the YouTube iframe over the card (`EmbedPlayerFrame`, placed with `engine.worldRectToScreen` and `engine.onViewChange`). Icons are SVG drawn with `view.placeIcon` (`embed-icons.ts`: Lucide from the `lucide` package, YouTube from `simple-icons`).
  - `geo/`: `GeoKind extends QuickConnectKind`, which delegates the outline (and its connector `sideAnchor`s) to the element's variant. Each variant (`kind`: rectangle, ellipse, diamond, …) is a `GeoVariant` subclass in `geo/variants/<id>.variant.ts`, registered at runtime in `geoVariants` (`variant.registry.ts`), with its label, picker `icon` (an SVG path), default size, `outline` and optional `decorate`. `variantOf(id)` falls back to the rectangle for unknown ids. The shape picker lists `geoVariants.all()`. `PolygonVariant` covers the polygon ones.

- **Where the types live:** each is in its module (`products/board/modules/<name>/`: `draw` holds `stroke`, `geo`, `text`, `connector`, `section`, `table`, `image`, `sticker`, `sticky`, `embed`, `db`, `er`), and paths above are relative to it. A module's tools are `<name>.tool.ts`, its agent tools `<name>.agent-tools.ts`, its options `<name>-options.types.ts` and its panels in `ui/`.
- **Adding a type to a product:** write a module (see Modules): its folder in the product's `modules/`, contributing the kind to `boardCanvas.kinds` and, if it has one, the tool (with its `keys`) to `boardCanvas.tools` and its tool entry to `boardEditor.tools` (icon, placement; see Editors). Agents' `create_shapes` schema, `loadFonts` and `elementInfo` read the composed kinds. A geo variant is still `geoVariants.register(new MyVariant())`.

- **Rendering:** `ElementView` (`canvas/render/element-view.ts`) is the one Pixi container for every element. `sync(el, kind)` calls `kind.draw(view, el)`, and `view.placeText(text, style, w, h)` lays text out like the editor. `view.setPaints(layers, { alpha, visible })` draws a stack of paints above the base graphics (`PaintStack`, `render/paint-stack.ts`): `shape` layers (a fill or stroke traced into a `Graphics`) and `image` layers (an asset fitted with `contain`/`cover`, `render/fit-image.ts`, masked by an outline), so images can sit between fills and under strokes. Nothing outside the element folders knows how an element looks.

## Modules

A feature is **one folder with one register file**: `products/<product>/modules/<name>/` holds its engine code (plain TS, the element folder's files, its tool, options type, agent tools), a `ui/` folder (React) and `<name>.module.ts`, which plugs it into every place it needs. Built-ins and plugins use the same API; only the module file and `ui/` may use React (ESLint).

- **The API** (`shared/core/modules/`): `definePoint<T>(id, { keyOf? })` is an `ExtensionPoint<T>`, a typed token exported next to the code that reads it (keyed points throw on a duplicate key, naming both modules). `defineModule({ id, requires?, after?, register(host) })`; `register` calls `host.contribute(point, ...items)`. `createModuleHost(modules)` sorts them (`requires` must be loaded, `after` only orders; cycles throw), runs every `register` and is read-only afterwards (`host.get(point)`, `host.find(point, key)`).
- **Canvas points** (`canvas/modules/`, `createCanvasPoints<O>(product)`, the board's `boardCanvas`): `kinds`, `tools` (`{ id, create(ctx), keys }`), `hostCommands` (`{ id, label, keys }`), `keybindings`, `options` (defaults of the options a module owns; given twice throws), `scopes`, `guides` and `rulerFrame` (one module each), `links`, `resolveElements`, `withMembers`, `alignTarget` (one module), `onRemove`, `prepareCopies`, `pasteText`, `pasteImage`. `composeProduct(id, host, points)` turns them into a plain `CanvasProduct`: keybindings over `BASE_KEYBINDINGS` (a command bound twice throws), hooks chained in module order, the first paste that returns an element wins. So the order of modules matters: `text` is `after: ["embed"]` so a pasted link is a card before it's text, `er` is `after: ["section"]` (a section takes its contents, then ER elements their attributes) and `connector` is `after: ["er"]` (connectors are routed once ER boxes are placed). `sticky` and `geo` `requires: ["connector"]` for their quick-connect dots, and `db` requires `sticky` (DBML notes).
- **Editor points** (`canvas-ui/modules/`, `createEditorPoints(product)`, the board's `boardEditor`): see Editors. **Board points:** `boardAgentTools` and `boardMigrations` (`board-points.ts`; a migration brings an older file's document up to date when it opens), `boardLibrary` (`ui/components/library/library-points.ts`). A module can define points of its own for others to extend.
- **Options:** each module declares the options it owns (`StickyToolOptions`, `DbToolOptions`) and `BoardToolOptions` extends them; a plugin augments it (`declare module "@board" { interface BoardToolOptions extends MyOptions {} }`) and contributes the defaults.
- **The board's modules** are listed in `products/board/ui/modules/board-modules.ts`: `core` (the select and hand buttons, the agent tools that work on any element, in `agent/`), `library` (the library's command and built-in content), and one per feature. Plugins call `registerBoardModule(module)` before a board opens; the modules load on first use (`getBoardModules()`, `getBoardProduct()`, `getBoardEditorModules()`). New board features are written as modules.
- Example: `modules/sticky/sticky.module.ts` contributes the kind, the tool with its `S` key, the `stickyColor` default, the tool entry (toolbar position; it's listed in the library too) and the color panel (for the tool and for selected notes).
- **Plugins** are modules installed outside the source (guide: `docs/plugins.md`, example: `examples/plugins/callout/`). A plugin is a folder with `plugin.json` (`readPluginManifest`, `PLUGIN_API_VERSION` in `shared/core/plugins/`) and one ES module with no imports, whose default `activate(api)` returns modules; `api` is the `PluginApi` (`app/plugins/create-plugin-api.ts`: the module API, kind bases, canvas-ui chrome, the app's React, the board's points and the design's (`api.design`: points, node base, panel blocks, hooks); wrapped by `strictApi` so reading a name it doesn't have throws, naming it, while extension points stay the same objects).
  - **On disk:** `PluginStorage` (`shared/core`, `pluginStorage` in `@platform`): copied plugins in `<appData>/plugins/<id>/`, development folders linked in `plugins/index.json`.
  - **Loading:** `app/main.tsx` awaits `loadPlugins()` (`app/plugins/`) before rendering. Each enabled and trusted plugin is imported from a `blob:` URL (5 s timeout); `activate` returns modules for the one product in its manifest's `products`, or `{ board, design }`, registered with `registerBoardModule`/`registerDesignModule(module, { plugin })`. Plugin modules are **optional** for `createModuleHost` (`ModuleLoadOptions`): one that throws, misses a `requires`, collides on a key or loops is left out with its dependents and reported; `getBoardProduct` recomposes without plugins if composing fails. Built-in errors still throw.
  - **State:** `usePluginsStore` (`shared/stores/plugins-store.ts`): `enabled` and `trusted` are saved; what was found and each `PluginStatus` is not. Settings › Plugins (`pages/settings/sections/plugins/`) installs, links, removes, asks for trust before the first run, and offers a reload.
  - **MCP:** the agent server is built on the first request (`use-agent-server.ts`), so plugin tools are listed. `createAgentTools` leaves out a tool whose name is taken, and `list_plugins` (`agent/plugin-tools.ts`, `AgentHost.plugins`) reports the plugins and their tools (`ModuleHost.ownerOf`).

## Agent (MCP) server

Agents (Claude Code, Cursor, …) connect to the running app at `http://127.0.0.1:47821/mcp`. If that port is taken the server tries the next nine, and the URL is written to `mcp.json` in the app data folder. Access is on by default, with no auth: only loopback, with Host and Origin checked against DNS rebinding.

- **Rust is only the transport** (`src-tauri/src/mcp/`): stateless Streamable HTTP (POST only). Each body is emitted to the webview as `mcp://message` and answered through the `mcp_reply` command (30 s timeout). `mcp_status` and `mcp_set_enabled` back the UI.
- **The protocol is TypeScript.** `shared/core/mcp/handle-mcp-message.ts` is a small hand-written JSON-RPC handler (`initialize`, `ping`, `tools/list`, `tools/call`). It reaches the platform through the `AgentChannel` interface (`shared/core/agent-channel.types.ts`, `platform/tauri-agent-channel.ts`), and `agentChannel` is `null` outside Tauri.
- **The board's tools are contributed by modules** to `boardAgentTools` (`board-points.ts`) as groups (`BoardAgentToolGroup`: `tools({ kinds })`), one group per file (`agent/`: `board-read-tools`, `shape-edit-tools`, `create-shapes-tool`, `arrange-tools`, `er-tools`, `view-tools`, `export-tools`, `file-tools`, `sticker-tools`; the db module's `db.agent-tools.ts`). `createAgentTools(modules, kinds)` collects them for `app/mcp`. Tools reach a board's facades through `board.engine.service(DB_SCHEMA | ER_MODEL)`. A tool is an `AgentTool<AgentHost>` and gets the `AgentHost` (the open board, recent files, opening a board). Every editing tool wraps its writes in `asUndoStep(engine.doc, …)` so one call is one Ctrl+Z, and builds or validates everything before writing. Element tools go through the kinds (the canvas `buildElement`, `agentPatches`, `summarizeElement` with `engine.kinds`). `update_shapes` runs `agentPatches` (`canvas/agent/`): each patch is checked against `patchableFields` and the stored field types, a new `w`/`h` goes through `kind.resize` (`resizePatch`: proportions, minimums, a table's grid), the kind's `completePatch` validates the rest, and a moved element takes its `engine.withMembers(…, "move")` members along. `set_board_info` (`board-info-tools.ts`) sets the title and description, which `get_board` and the file tools return. `duplicate_shapes` is `engine.duplicateElements` (Ctrl+D's copy, with `prepareCopies`). The context menu's actions have tools that take ids and leave the selection alone: `reorder_shapes` (`engine.reorderElements`), `lock_shapes` (`engine.setLocked`), `copy_as_png` (`engine.copyAsPng(ids)`) and `export_shapes` (`engine.exportElements` with `ExportOptions.ids`, written by `AgentHost.writeFile`, `writeExportFile` in `@platform`, to a path or next to the board's file). `view_board` returns the board as a PNG: a tool returning a `ToolImage` (`shared/core/mcp`) is sent as MCP image content. `apply_er_text` creates entities a relation names (`createMissing`), as the DBML tools create missing tables. The MCP names still say "shapes" (`create_shapes`, …) so agents' setups keep working.
- **The design's tools are contributed by its modules** to `designAgentTools` (`design-points.ts`, `DesignAgentToolGroup`), each from its own folder: the core module's `modules/core/agent/` (`get_design`, `list_nodes`, `get_nodes`, `get_design_selection`, `set_design_info`, `create_nodes`, `update_nodes`, `delete_nodes`, `duplicate_nodes`, `select_nodes`, `reorder_nodes`, `lock_nodes`, `align_nodes`, `distribute_nodes`, `tidy_up_nodes`, `view_design`, `export_nodes`, `copy_nodes_as_png`, `zoom_design_to_fit`, `zoom_to_node`, `undo_design`, `redo_design`, `list_recent_designs`, `open_design`, `new_design`, `save_design`), and `frame.agent-tools.ts` (`list_frame_presets`, `add_preset_frame`), `group.agent-tools.ts` (`group_nodes`, `ungroup_nodes`), `layers.agent-tools.ts` (`get_layer_tree`), `pages.agent-tools.ts` (`list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`), `vector.agent-tools.ts` (`convert_to_vector`, `shapeToVector`, shared with the edit mode), `image.agent-tools.ts` (`add_image`, a picture file read with `DesignAgentHost.readFile`, `readLocalFile` in `@platform`) and `text.agent-tools.ts` (`list_fonts`). The plumbing is `products/design/agent/` (`DesignAgentHost`, `requireDesign`, `requireNodes`, `createDesignAgentTools`, `DESIGN_AGENT_INSTRUCTIONS`). `create_nodes` builds through the kinds: a `creatable` `DesignNodeKind` gives `nodeFromSpec(spec, index, context)` (a `NodeBuildContext`: the tool options and `nameFor(base)`; `BoxShapeKind` makes any box shape, kinds add their `specProperties`), `buildNode` adds what every node takes (`applyNodeSpec`: name, visibility, opacity, `fill`/`fills`, `stroke`/`strokes`, `strokeWeight`, paints checked by `readPaints`), and the tool puts it in the container under it (`containerAt`) or the `parent` given (`checkParent`). `update_nodes` is `agentPatches`; `DesignNodeKind.completePatch` checks the shared fields (`checkNodePatch`, `parentId` included) and kinds check theirs (a text lays out again, a line's `points` and a vector's `network` re-wrap their bounds). Both products share `canvas/agent/` (`AgentFile`, `AgentRecentFile`, `AgentToolGroup`, `collectAgentTools`, `exportPath`, `elementSpec`, and `arrangeTools`, which makes each product's `align_*`, `distribute_*` and `tidy_up_*` tools: the board's `align_shapes`, … are in `agent/arrange-tools.ts`).
- **The app wires it up** in `app/mcp/` (`useAgentServer`, mounted by `<AgentServer />` in the providers): one server with the board's and the design's tools (one set of names, so neither shadows the other) and both products' instructions; `agentHost` implements `AgentHost` and `DesignAgentHost`. The open board and design register themselves for agents with `useAgentBoard` (`products/board/ui/agent/`) and `useAgentDesign` (`products/design/ui/agent/`), both `useAgentFile` on a `createActiveFile` (`canvas-ui/agent/`). The on/off setting is `shared/stores/agent-server-store.ts`, and `shared/agent-server/` is the menu in the top bars and the Settings panel (switch, URL, "Connect an agent…"), which open `ConnectAgentDialog` (`connect-agent-dialog/`): a grid of agent apps with their logos (`simple-icons`, Lucide where there's none), "Other AI tools", one app's setup (snippet, where it goes, "Add to …") and "Install manually" (the default settings: URL, transport, the generic JSON). The apps are data, `AGENT_CLIENTS` (`agent-clients.ts`: Claude Code, Codex, Cursor, VS Code, Antigravity, Gemini CLI, Claude Desktop through `mcp-remote`, Windsurf, and under `more` Zed and opencode; `GENERIC_AGENT_CLIENT` is the manual JSON); Cursor and VS Code have a one-click `installLink`, whose `cursor://`/`vscode:` schemes are allowed in the capabilities.

## Editors (React)

- **Shared host (`canvas-ui/`):** `useCanvasEngine(containerRef, product, document)` creates and mounts an engine into a container div; the canvas theme is resolved from CSS tokens via `readCanvasTheme()`. The engine is provided through `EngineContext`, and chrome components use `useEngine()` and `useEngineState(selector)`, selecting primitives or stable references so each one re-renders only for its slice. Code is edited with `CodeEditor` (`shared/ui/components/code-editor/`, CodeMirror 6: line numbers, bracket matching, `completions`, an `errorLine` and a banded `highlight` range; text set from outside starts a fresh state, so its undo only covers typing). The generic chrome is here too (`FloatingPanel`, `ToolButton`, `OptionButton`, `ColorSwatch`, `ZoomControls`, `ZoomMenu`, `HistoryControls`, and `CommitInput`/`CommitTextarea`/`useCommitField` in `components/commit-field/`: text that writes on blur or Enter, one undo step per edit). Color choices use `ColorPalette`: the palette's swatches plus `CustomColorSwatch`, which opens `ColorPicker` (the system color chooser and a hex field) for any other color. Options panels use it, not their own swatch lists.
- **Tool entries:** every tool the editor shows is a `ToolEntry` on the `tools` point: its `icon` (`ExtensionIcon`), its name and description (an element tool is named by its kind through `element`, read with `toolInfo`, which uses `engine.elementInfo`; other tools give `label` and `description`), and where it's placed. `toolbar: { group, order, menu? }` puts a button on the main toolbar (group 0 is select and hand, group 1 the tools that add elements; built-ins are spaced by 10); without it, the tool isn't on the toolbar. Tools with the same `menu` share one button (`ToolMenuButton`, `toolbarItems`): it shows the active tool or the one picked last, and its chevron lists them all with their shortcuts (the design's shapes). `library` lists it in the library: tools that create an element are listed by default (`library: false` opts out), with `section`, `order` (default: its toolbar position) and `keywords`. `subTools` keep a button active for tools picked from its panel (the eraser). Helpers: `toolbarGroups`, `sortedTools` (shortcut lists), `inLibrary`.
- **Module chrome (`canvas-ui/modules/`):** an editor provides its modules with `EditorModulesContext` (`{ host, points }`), and the generic pieces read its `EditorPoints`: `ModuleToolbar` (the `tools` entries with a `toolbar` placement, in groups), `ModuleToolOptions` (`toolPanels` by tool, or `selectionPanels` by the selection's type with the select tool), `ModuleSlot` (`sidePanels`, `topBar`), `ModuleSession` (runs the `sessionHooks` and draws the `overlays`) and the context menu (`contextMenu` groups after the built-in ones). Icons are an `ExtensionIcon` (a Lucide icon or `{ svg }`, `ExtensionIconView`).
- **Board editor (`products/board/ui/`):** `BoardEditorPage` (`/board/:id`) loads the document and mounts the engine with `getBoardProduct()`. `BoardSession` provides the engine, the file and `getBoardEditorModules()`, and renders `ModuleSession` and `BoardChrome`, which places the module slots. Panels read the schema with `useBoardSchema()` (the `DB_SCHEMA` service) and `useDbQuery`/`useDbTable`/`useDbEnum` (`modules/db/ui/schema/`), which re-read only when the schema changes. The database panel (`modules/db/ui/db-panel/`, with the shared DBML `ui/components/source-editor/`: `SourceEditor` applies text while typing, shared with the ER panel's Text tab, and colors it with the `languages/` `dbmlLanguage` and `erLanguage`, small `StreamLanguage`s that never fail on half-typed text, and suggests with `completions/`: `dbmlCompletions` (keywords, column types and enums, settings, `table.column` ref targets, from the board schema plus names the text defines) and `erCompletions` (keywords, settings, the diagram's entity and relation names)) shows the selected table or enum (`selectedId` + `selectionTypes` from `EngineState`), or the whole schema from the top bar's button (`modules/db/ui/schema-button.tsx`, state in `ui/stores/board-panel-store.ts`); `.dbml` import/export goes through `@platform`. The ER panel (`modules/er/ui/er-panel/`) works the same way with the board's `ErModel` (`useErModel` is the `ER_MODEL` service; `useErQuery`, `useErSelection` in `modules/er/ui/model/`): it opens when an ER element is selected and shows that element's diagram, as a form for the selected element or as text. Board components that read or set tool options use `useBoardEngine()` / `useBoardState()` (`board-engine-context.ts`), typed with `BoardToolOptions`. The tool options panels (in each module's `ui/`) are contributed to `toolPanels`/`selectionPanels`.
- **Never put canvas elements in React state.** React only hosts the canvas and draws the UI around it.
- **Files:** every product's files go through `canvas-ui/file/`: `useCanvasFileLoader(id, { noun, open, create })` loads the `CanvasDocument` from `Storage` (or starts an empty one for a new id), `useCanvasFileSaver(id, engine, info, format)` saves it (a `CanvasFileFormat`: file type, noun, untitled name, `encode`) and is provided as `CanvasFileContext` (`useCanvasFile()`, read by `SaveIndicator` and `DocumentInfoPopover`, also in `canvas-ui/file/`), and `useCanvasThumbnail` takes the preview. A file is a 4-byte magic, a u32 format version and a Yjs update (`encodeCanvasFile`/`decodeCanvasFile`, `canvas/file/`): `CCBD` for `.cboard` (`products/board/file/board-file.ts`; the board's wrappers are `useBoardLoader`, `useBoardSaver`, `BOARD_FILE_FORMAT` in `products/board/ui/file/`), `CCDS` for `.cdesign` (`products/design/file/design-file.ts`, `useDesignLoader`, `DESIGN_FILE_FORMAT`). `TauriStorage` keeps a recent-files index (id → path) in the app data folder. Ctrl+S / Ctrl+Shift+S are engine commands that run the host's handlers (`engine.handleHostAction("save", …)`).
  - **Autosave** (`useCanvasAutosave`, driven by `useCanvasFileSaver`): 1.5 s after changes stop (at most every 10 s while editing), and once more when the editor closes. A board with no file is autosaved as a **draft** (`storage.saveDraft`: `<appData>/drafts/<id>.cboard`, `FileInfo.draft`, badged on Home); Save asks where to put it and the draft file is removed (`storage.save`), forgetting a draft deletes it, and clearing the recents keeps drafts. Revisions counted per change keep the board dirty when it changes mid-save. The top bar's `SaveIndicator` shows a cloud while saving and a checked cloud for 3 s after (`saved` in the file context); the unsaved dot shows only when autosave is off or failed. The setting is `shared/stores/autosave-store.ts` (on by default, Settings › Files & storage). Closing the window waits for the tasks set with `appLifecycle.onBeforeQuit` (`AppLifecycle` in `shared/core`, `platform/tauri-app-lifecycle.ts`, up to 5 s; it needs `core:window:allow-destroy`): pending autosaves are flushed. Home's previews are pictures of each file (`useCanvasThumbnail`: `engine.thumbnail`, taken when the editor or the window closes, stored with `storage.saveThumbnail` in `<appData>/thumbnails/<id>.jpg`, removed when the file is forgotten); `useFileThumbnail` (`pages/home/`) loads them and reloads when `thumbnail-store` bumps the file's version. Saves pass the document's title and description to `storage.save`/`saveDraft` (`FileMeta`), so the recents show them (a draft is named by its title); the file's name opens `DocumentInfoPopover` to edit them.
  - The index is validated on read (`isFileInfo`), written atomically (temp file + rename) and edited one change at a time (`mutate`); an unreadable one is set aside as `recent-files.corrupt.json` (`storage.takeIndexReset()`). Saves are atomic too.
  - `useRecentFilesStore` holds the recents and the ids of `missing` files (re-checked on window focus), plus `open(path)`, `relocate(id)` and `forget(id)`. Home's cards show missing files with Locate… / Remove, and every card has a ⋯ and right-click menu (`use-file-actions.ts`).
  - Files dropped on the window, picked with "Open with" or passed on the command line arrive through `FileOpenRequests` (`shared/core`, `platform/tauri-file-open-requests.ts`; drops come as `FileDrop`: `DroppedFile`s read on demand plus the client point) and are opened by `app/open-requests/`, which asks first when the open editor is dirty (`unsaved-changes-store`, set by `useCanvasFileSaver`). `cloudy-canvas://` links (the deep-link plugin, scheme in `tauri.conf.json`; installers and the Arch desktop entry register it, dev builds and the AppImage register it at startup) arrive through `AppLinks` (`shared/core/app-links/`, `platform/tauri-app-links.ts`) and are read by `parseAppLink`: `open?path=<file>`, `board/<id>` / `design/<id>` (a recent file), `new/board` / `new/design`, `home`, `settings`; `app/open-requests/open-app-links.ts` follows them. A drop without a `.cboard`/`.cdesign` goes to the open editor's target in `file-drop-store` (registered by `useCanvasFileDrop(engine)` in `canvas-ui`), which adds the files to its canvas.
- **FigJam import** (`products/board/figjam/`, outside the `@board` barrel: loaded only by `import("@board/figjam")` in `importFigJamFile`, `ui/file/`; reading and converting run in a worker, `figjam-import.worker.ts` via `convertFigJamFile`, with the shared `@canvas/figma` reader): `.jam` files ("Save local copy…") opened, dropped or picked in Home's open dialog (`figmaImportOf(path)` in `shared/core`: `fig` → design, `jam` → board) become a new board draft named after the file. `convertFigJam` takes the first page and flattens frames, groups and sections into world coordinates (`convertFigJamNode`, one converter per node type in `convert/`): stickies, shapes with text and connectors keep their looks and text in `nodeGenerationData` parts (`generatedPart`: 0 the body, 1 the text); stickies → `sticky`, shapes → `geo` (by `shapeWithTextType`), texts → `text` (wrapped lines kept from `derivedTextData`), connectors → `connector` (built last, `FigJamOutput.defer`, ends on the elements their nodes became, `FigJamContext`; curved ones straight, labels become texts), sections → `section`, image fills → `image` (FigJam's white border as padding), link preview widgets → `embed`, marker vectors → `stroke`. What was lost is counted and shown in a toast (`toastImportWarnings`, `canvas-ui/file/import-steps.ts`, shared with the Figma import).
- **Settings (`/settings`, `pages/settings/`):** opened from Home's top bar or Ctrl+,. It has About (version from `appInfo()` in `@platform`, `__APP_VERSION__` outside Tauri; the DarkRedgm link opens through `openExternal`, whose URLs are allowed in the capabilities), the Cloudy Studio dedication card (`dedication-card.tsx`), the agents panel (`AgentServerPanel` in `@shared/agent-server`), files & storage, and the board's shortcuts (`BoardShortcutsList` from `@board/ui`, read from the board's modules: toolbar entries, host command labels and the composed keybindings).
- **App icon:** the source is `src-tauri/icons/source/app-icon.svg`; regenerate every size with `pnpm tauri icon src-tauri/icons/source/app-icon.svg`.
- **Library:** the toolbar's last button (Shift+I, the `openLibrary` host command) opens the library panel (`ui/components/library/`): tabs (All, Templates, Lists, Widgets), one search, and sections of cards. Its content is two points, `boardLibrary.sections` and `boardLibrary.items` (sorted by `order`; built-ins in `library-catalog.ts`), plus a card per tool entry that's `inLibrary` (`toolLibraryItems`: its icon, its name and description, picking it switches to the tool; in the `LIBRARY_TOOLS_SECTION` unless its placement names another); an item's `run(engine)` does what picking it does, and `comingSoon` items are shown disabled. Modules contribute new templates, lists and widgets there. Open state is `libraryOpen` in `board-panel-store`.
- **Loading screen:** long tasks the whole window waits for run in `runWithLoading(title, (report) => …)` (`shared/stores/loading-store.ts`); `GlobalLoader` (mounted in the providers) shows `LoadingScreen` (`shared/ui/components/loading-screen/`: the hopping foca watona, `HoppingSeal` in `shared/ui/brand/`, the stage and a progress bar), which `CanvasLoadingOverlay` reuses.
- **Toasts:** report failures with `notifyError(title, error)` or `toast({...})` (`shared/stores/toast-store.ts`), never only `console.error`. The `<Toaster />` is mounted in the providers.
- **Adding a product:** give it points (`createCanvasPoints<O>(id)`, `createEditorPoints(id)`), write its features as modules, compose it with `composeProduct`, and build its `ui/` editor from the `canvas-ui` module chrome, like the board and the design.

## Design (`products/design/`)

Figma-style files, built only from modules (`products/design/ui/modules/design-modules.ts`: `core`, `pages`, `frame`, `rectangle`, `layers`, `assets`, `plugins-tab`; plugins call `registerDesignModule`). Points: `designCanvas`, `designAgentTools` and `designMigrations` (`design-points.ts`) and `designEditor` (`ui/modules/design-editor-points.ts`): the shared editor points plus `leftTabs` (a left panel tab and its rail button), `propertySections` (a properties panel section for the Design or Prototype tab, shown `when(selection)` fits, by capability rather than type) and `mainMenu` (the logo's menu: engine commands, labelled and bound by the keymap, or `run({ engine, navigate })`) `toolSidebars` (what the properties panel shows instead of the sections while a tool is on) and `layerIcons` (icons of layer types no tool creates, e.g. groups). Kinds add `canGoInto(parent, parentKind)`, `layerName(el)` (`layerNameOf`), `strokable` and `imageFills` to the node base. `DesignToolOptions` extends the modules' options (`FrameToolOptions`, `RectangleToolOptions`) and plugins augment it.

- **Nodes** (`modules/core/node/`): every design element is a `DesignNode` (`name`, `parentId`, `visible`, `opacity`, `fills`/`strokes` as `Paint[]`, `strokeWeight`) and its kind extends `DesignNodeKind` (a `BoxKind`: skips hidden nodes when hit, fills the shared defaults, lists its image paints as `assets`; `container` for frames, `fillable` (false for lines)). The kinds form one hierarchy: `BoxShapeKind` (a shape drawn as a box: `createNode(rect, name, index, parentId, options)` and `clickSize(options)`, its defaults' `size` unless overridden, e.g. the frame's preset) is the base of `RectangleKind`, `EllipseKind`, `FrameKind` and `PointsShapeKind` (a shape outlined by `points(el)`, which gives its drawing and hit test: `PolygonKind`, `StarKind`); `LineKind` extends `DesignNodeKind` directly. A paint is a `SolidPaint` or an `ImagePaint` (`assetId`, `scaleMode`: `fill` crops, `fit` shows it all; `imagePaint(assetId)`); the kind's `assets` are its image paints. Factories start from `createNodeBase`; kinds `draw` with `drawPaints(view, node, outline)` (fills, image fills clipped to the outline, then solid strokes, with the node's opacity and visibility, through `view.setPaints`); `traceBox` is a (rounded) box outline. Drawing tools extend `NodeDrawTool<E, S>` (`modules/core/tools/`, a template method: the press/drag/click gesture past `DRAW_THRESHOLD_PX`, naming ("Rectangle 3", `nextLayerName`), adding at the top, placing it in the frame under it with `parentFor` (`core/tree/parent-for.ts`), selecting it and returning to select, in one undo step); a subclass gives the shape `S` a drag or click makes (`dragShape`, `clickShape`, `createNode`, `shapePatch`). `BoxDrawTool` is the concrete tool for any `BoxShapeKind` (`new BoxDrawTool(ctx, kind)`: id from `kind.tool`, name from `kind.label`), so box shapes have no tool classes of their own; `LineTool` draws between two ends.
- **The layer tree** (`modules/core/tree/`): nodes store `parentId`; coordinates stay in world units. The core module gives the canvas `treeOrderKeys` (parents draw before their children, siblings by `index`), `withDescendants` (`withMembers`: a frame moves and deletes with what it holds), `reparentMoved` (`onMoved`: a dropped node goes into the topmost visible container under its center, `containerAt`) and `prepareTreeCopies`. `DESIGN_TREE` (`DesignTree`: `layers()`, `node`, `ancestors`, with `subscribe`/`getVersion`) is what the Layers tab reads.
- **Pages** (`modules/pages/`): a page is a `page` element (`PageKind`: a record, never drawn or hit; its `index` orders the pages) and every node has `pageId`. `PAGE_SCOPES` is the design's `scopes`, so one page is on screen at a time and new nodes land on it (`createNodeBase` leaves `pageId` empty; `prepareTreeCopies` clears it so pastes go to the page on screen). `DESIGN_PAGES` (`DesignPages`) reads and edits them, one undo step each: `add(after, name?)` ("Page N"), `rename`, `duplicate` (the page and its nodes, `cloneElements`), `remove` (with its nodes; never the last page), `reorder(id, position)` and `moveNodes(ids, pageId)` (with descendants, on top, parents left behind become the top of the page). `ensurePages` (a `designMigrations` entry, also run on new designs by `newDesignDocument`) gives a design without pages "Page 1" and puts unplaced nodes on it. `DESIGN_TREE.layers(page)` reads one page's tree. UI (`modules/pages/ui/`): `PagesSection` at the bottom of the Layers tab (click shows a page, double-click renames, ⋯ renames, duplicates and deletes, rows drag to reorder, "+" adds one after the current), the Page section (its name, zoom), "Move to page" in the selection's context menu (a `ContextMenuSubmenu`: `canvas-ui` context menu items can be submenus of actions), and the `previousPage`/`nextPage` host commands (PageUp/PageDown, in the main menu). Agent tools: `list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`; every other tool works on the page on screen (`get_design` reports `currentPage`). Each page keeps its ruler guides (`PageElement.guides`, `PAGE_GUIDES` is the design's `guides`; duplicated with the page, frames' guides following their copies; a deleted frame's are dropped by `pruneFrameGuides`, an `onRemove`; kept from Figma pages by `figPageGuides`); the core module's `toggleRulers` (Shift+R), `toggleGuides` (Shift+;) and `clearGuides` host commands (`useViewCommands`, remembered in `ui/stores/design-view-store.ts`) are checkbox items of the main menu (`MainMenuItem.checked`), "Snap to guides" is in the `ZoomMenu`, and agents use `list_guides`, `add_guides` (with an optional `frame`) and `remove_guides` (`guides.agent-tools.ts`; `get_design` counts them).
- **Images** (`modules/image/`): pasted or dropped images become a rectangle named "Image" filled with them (`createImageRectangle`, the `pasteImage` hook), at their pixel size shrunk to 80% of the view.
- **Elements:** `frame/` (`FrameKind`: a container with `cornerRadius` and `clipsContent` ("Clip content" in the frame section, on for new frames: `contentClip(el)` is its area, and the core's `treeClips` clips its descendants to where all their clipping frames overlap); at the top of the page it shows its name above it and is hit by it too; its tool, F/A, places the `framePreset` size on click; while it's on, the properties panel shows `FramePresetsSidebar`: `FRAME_PRESET_GROUPS` (Phone, Tablet, Desktop, Presentation, Watch, Paper, Social media), and a preset adds a frame named after it right of the top-level content (`presetFrameRect`, `useAddPresetFrame`), zooms to it and becomes the click size) and `rectangle/` (`RectangleKind`, R).
- **Text** (`text/`): `TextKind` (`text`, `fontFamily` (a family name), `fontSize`, `fontWeight`, `fontStyle`, `lineHeight`, `letterSpacing`, `textAlign`, `verticalAlign`, `autoResize`: `width`/`height`/`none`); its color is its first visible solid fill (`imageFills` and `strokable` are off), its layer is named after its first line (`layerName`) until renamed, and `textSize`/`retypeset` lay it out again after any change (resizing a side fixes the width, the height the size). `TextTool` (T): click for auto width, drag for a fixed width, click a text to edit it. The Typography section has `FontPicker` (`useFontFamilies`, a searchable list of installed and Google families), the face, size, line height, letter spacing, alignment and resizing; its changes become the `textTypography` tool option new texts use.
- **Groups** (`group/`): `GroupKind` draws nothing and isn't hit; `resolveGroups` (`resolveElements`) wraps its children, `groupSelectTarget` (the engine's `selectTarget`) makes a click select the outermost group not yet entered (double-click enters, Ctrl/Cmd+click goes to the layer), `pruneEmptyGroups` (`onRemove`, `onMoved`) removes emptied groups, and the `group` (Ctrl+G) and `ungroup` (Ctrl+Shift+G) host commands (`groupNodes`, `ungroupNodes`, run by `useGroupCommands`) are in the context menu and the main menu. Children of a node that isn't a `container` stay in it when dragged. A hidden frame or group hides what it holds (an empty clip from `treeClips`).
- **Sections** (`section/`): `SectionKind` (Shift+S, in the toolbar's `frames` menu with Frame): a labeled area (name pill) that holds frames and only goes into sections (`canGoInto`).
- **Vector networks** (`core/network/`, Figma's model): `VectorNetwork { vertices, segments (start, end, tangentStart, tangentEnd: relative bezier handles), regions (loops of segment indices, filled) }`. `bezier.ts` (`pointAt`, `splitAt`, `nearestT`, `bendThrough`, `flatten`), `network-curves.ts` (`segmentCurve`, `loopCurves`, …), `network-geometry.ts` (`networkBounds`, `hitSegment`, `vertexAt`, `insideRegion`), `network-faces.ts` (`networkFaces`: the areas the segments enclose, by a half-edge walk ordered by leaving angle, outer faces dropped by their sign; `faceAt`), `network-trace.ts` (`traceStrokes` chains through two-segment vertices, `traceRegions`; holes are filled for now), pure edits in `network-edits.ts` (`moveVertices`, `setTangent` (mirrored), `splitSegment`, `addVertex`, `connect` (closing a loop adds a region), `removeParts` (heals two-segment vertices), `cutSegment`, `bendSegment`, `toggleSmooth`, `toggleRegion`), `network-shapes.ts` (`rectNetwork` with rounded corners, `ellipseNetwork`, `polygonNetwork`, `polylineNetwork`) and `placeNetwork`/`scaleNetwork`. `BoxShapeKind.vectorNetwork(el)` is a shape's outline (rectangle, ellipse, polygons and stars; `null` for frames and sections). `drawPaints` takes `{ fill, stroke }` outlines.
- **Vectors** (`vector/`): `VectorKind` (`network`; old pencil `points` become a chain in `fillDefaults`): regions filled, segments stroked, hit near a segment or inside a filled region, stretched when resized. `PencilTool` (Shift+P, a `FreehandTool`) draws chains; the pen and the pencil share the toolbar's `draw` menu. **Edit mode** (`vector/edit/`): `editVector` (the `editElement` hook) starts it on a vector, or first turns a shape with a `vectorNetwork` into a vector with the same id and look (one undo step). `VECTOR_EDIT` (`VectorEditSession`) holds the edited vector and the selected points and segments. Every edit tool extends `VectorEditTool` (the overlay `drawVectorOverlay` as a guide, `partAt` for handles, points and segments, `write`/`commit` through `placeNetwork`, only Enter (Done) leaves, Esc lets go of the selected points, V is Move points and other tool shortcuts wait, Delete removes parts, Ctrl+A selects all points): `VectorMoveTool` (`vector-move`: pick, Shift, marquee, drag points, segments and handles, Alt breaks the mirror, a click away lets go of the points), `PenTool` (`pen`, P: starts a vector outside the mode; adds points joined to the selected end, pulling handles while dragging; splits segments; joins points, closing loops into regions; Esc lets go of the end), `VectorBendTool` (curve a segment through the pointer, click a point to toggle smooth), `VectorBucketTool` (`vector-bucket`: click an enclosed area to fill or unfill it; a vector without fills gets the default gray) and `VectorCutTool`. `VectorEditToolbar` (Move, Pen, Bend, Paint bucket, Cut, Done = Enter) is contributed to `toolbars`.
- **Turning and flipping** (design): nodes are `rotatable` (`fillDefaults` gives `rotation: 0`); `DesignNodeKind.turnOf(el)` is the angle the panel shows (a line's runs along its ends) and `flip(el, axis, at)` mirrors it across a line (`flipPlacement`: the far corner mirrored, the turn negated; kinds that aren't `symmetricVertically`, polygons and stars, turn half round when flipped top to bottom; vectors mirror their network, lines their ends, groups leave it to their children). `flipNodes` (`core/transform/`) runs it on the selection's roots and members; the core module's `flipHorizontal` (Shift+H) and `flipVertical` (Shift+V) host commands (`useFlipCommands`), the Transform main menu and the selection's context menu offer the turns and flips, and the Position section's `RotationRow` has the angle field (each layer turns round its middle to it) and the buttons. Groups are never turned themselves (`resolveGroups` wraps their children's `elementBounds`; turning one turns its children). `placeNetwork` takes the node's `rotation`, so vector edits stay put; vector edit mode maps through it (`local`, `world`, `localOffset`). A turned frame clips along its turned edges (`contentClip` passes the rotation); inside another clipping frame the nearest clip alone applies. `containerAt` checks the turned area. Agents: `rotation` in `create_nodes` and `update_nodes` (turned round the corner through `kind.rotate`, `checkNodePatch`; a group refuses it), `rotate_nodes` and `flip_nodes` (`node-transform.agent-tools.ts`), and summaries carry `rotation`. The Figma import keeps turns (`placementOf` in `canvas/figma`); only mirrored or skewed layers are straightened or become vectors.
- **Shapes** (one module each, all in the toolbar's `shapes` menu): `ellipse/` (`EllipseKind`, O, hit inside the ellipse), `polygon/` (`PolygonKind`, `pointCount` sides) and `star/` (`StarKind`, `pointCount`, `innerRadius`), both `PointsShapeKind`s whose corners come from `pointsInBox` (`core/node/shape-points.ts`), each with its section, and `line/` (`LineKind`: `points` are its two ends relative to (x, y), `startCap`/`endCap` `none` or `arrow`; `boxed = false`, not resizable, `fillable = false` (the Fills and Layout sections hide), hit near the segment, its ends drag with `LineEndDrag`; `LineTool` is both the line (L) and arrow (Shift+L) tools, Shift snaps to 45°; the Line section sets the caps).
- **Editor** (`ui/`): `DesignEditor` mounts the engine in a container between the docked panels (`design-layout.ts`, `CANVAS_INSET`, `data-product="design"` for the canvas tokens) that never remounts; `DesignSession` provides the engine, `CanvasFileContext` and the modules; `DesignChrome` places `DesignRail` (main menu + `leftTabs`), `LeftPanel` (file name, the active tab), `PropertiesPanel` (history, agents, Export, Design/Prototype tabs of `propertySections`, `ZoomMenu`) and, laid exactly over the canvas, the context menu, `ModuleSession` and the toolbar. Panels read the selection with `useSelectedNodes` and write through `useEditNodes`/`useMoveNodes` (`ui/hooks/`, one undo step each); their building blocks are `ui/components/panel/` (`PanelSection`, `PropertyGrid`, `FieldBox` (the compact field's look), `NumberField`, `HexInput`, `PercentInput`, `PaintField`, and the fields bound to the selection, `NodeNumberField`, `NodeSelectField`, `NodeCheckbox`: `read(node)`/`patch(value)`, "Mixed" through `sharedValue`, one undo step). Section `when`s use `ofType(...types)`, `allKinds(can)`, `someNodes`, `noNodes` (`ui/modules/section-filters.ts`). A `PaintField`'s swatch opens `PaintPicker` (`ui/components/paint-picker/`, Figma's paint picker): tabs per paint kind (Solid and Image work; Linear, Radial, Angular, Diamond and Pattern are disabled for now; strokes can't be images), `SolidEditor` (the `canvas-ui` color controls in `components/color/`: `SaturationArea`, `ColorSlider` for hue and opacity, `EyedropperButton` where the browser has one, `hexToHsv`/`hsvToHex`; hex and opacity fields; "On this page" and "Recent" swatches, `paint-recents-store`) and `ImageEditor` (Fill/Fit, a preview through `useAssetUrl`, "Choose image…" with `pickImageFiles` from `@platform`, stored with `doc.addAsset`). A drag in the picker reports `{ done: false }` steps, which `useEditNodes(…, { checkpoint: false })` joins into one undo step. The core module's sections: Page, Position (align, X/Y counted from the corner of the container each layer is in, `positionOrigin`, as in Figma; agents keep world coordinates), Layout (W/H, keep proportions, swap them: portrait ↔ landscape), Appearance (opacity, corner radius when every node has one), Fills, Strokes, Export, and the Prototype placeholder. Tab state is `ui/stores/design-panel-store.ts` (persisted).
- **Figma import** (`figma/`, outside the `@design` barrel: loaded only by `import("@design/figma")` in `importFigmaFile`, `ui/file/`, with `fflate` and `fzstd`; reading and converting run in a worker, `figma-import.worker.ts` via `convertFigmaFile`, which reports progress; `figmaDesignDocument` then adds everything in one transaction, `doc.addAllUntracked`; callers use `importFigmaWithLoading`, which shows the global loading screen): `.fig` files ("Save local copy…") opened, dropped or picked in Home's open dialog (`isFigmaPath`/`isOpenablePath` in `shared/core`, `openCanvasFileDialog({ figma: true })`) become a new design draft named after the file. reading the file is shared with FigJam's import in `src/canvas/figma/` (`@canvas/figma`, a deep import outside the `@canvas` barrel so `fflate`/`fzstd` stay lazy): `kiwi/` decodes Kiwi by interpreting the schema the file carries (no generated code), `container/` (`readFigFile`) unzips, reads the prelude (`kind`: `fig-kiwi` is `design`, `fig-jam.` is `figjam`; Slides are refused) and inflates the chunks (deflate or zstd), `nodes/` holds the node types, `buildFigTree`, the matrices, `FigImportContext` (blobs, images as assets, `ImportWarnings`) and `worker/` runs an import in a worker (`runFigmaWorker`, `serveFigmaWorker`); `convert/` (`convertFigma`) builds the node tree by guid (`buildFigTree`, siblings by position), expands instances (`resolveFigNode`: the component's nodes with `symbolOverrides`, `derivedSymbolData` and text/visibility properties by guid path, nested instances included), and maps nodes to elements in world coordinates (`convertChildren`): pages, frames (components and instances), groups, sections, box shapes, lines, vectors (the network blob is Figma's model, with the transform applied), texts (first style). Boolean operations, rotated shapes and unknown layers become vectors of Figma's precomputed outline (`pathToNetwork`); gradients become their first color; what was lost is counted (`ImportWarnings`) and shown in a toast. Prototype and Dev Mode data are ignored.
- Not yet: gradients, image crop/tile, mirrored image fills and text, auto-layout, group opacity and resizing, text strokes and decorations, region holes, the lasso and vector eraser.

## Code conventions

- **Small, single-purpose files:** one component, tool, layer or helper per file, re-exported through a folder `index.ts`. Split a file once it mixes concerns or grows past ~200 lines. Reuse the shared helpers before writing new ones:
  - `canvas/utils`: `Store`, `Emitter`, `Disposables`, `FrameScheduler`, `Registry`, `debounce`, `clamp`/`mod`.
  - `canvas/geometry.ts` (`roundPoint`, `roundRect`, `fitInView`, `rectCenter`, …) and `canvas/tools/drag-threshold.ts` (`pastThreshold`, `MOVE_THRESHOLD_PX` for dragging existing things, `DRAW_THRESHOLD_PX` for creating tools).
  - Text fields that commit on Enter/blur and revert on Escape: `useCommitField` + `commitFieldProps(field)` (`canvas-ui/components/commit-field/`), never hand-written key handlers.
  - `shared/core/keyboard.ts`
  - `shared/ui/layout`: `AppHeader`, `PageContainer`.
  - `shared/ui/hooks`
  - `canvas-ui` for editor chrome.
- **Types go in sibling `<file>.types.ts` files:**
  - Every `interface` and `type`, including component props, goes in a `.types.ts` file next to its code, and is imported with `import type`.
  - Barrels re-export them with `export type`.
  - Vendored shadcn primitives in `src/shared/ui/components/ui/` are exempt and stay as generated.

## Design system

- **Tokens** live in `src/shared/ui/styles/tokens.css` and are mapped to Tailwind in `src/app/styles.css`. Tailwind's default colors and radii are reset, so only design-system values exist.
  - Components use **semantic tokens only** (`bg-surface`, `text-muted-foreground`, `bg-primary`, …). They never hard-code colors or use the palette scales (`ice`, `seal`, `blush`, `sand`, `lilac`).
  - Canvas colors are tokens too (`--canvas-*`).
  - Code colors are tokens too (`--syntax-*`, read by the `CodeEditor` theme).
  - Document content colors (sticky/marker palettes in `products/board/palette.ts`) are data saved with the file, not theme tokens.
- **Sharp shapes:** the user dislikes rounded styles.
  - Radii are 4px for controls (`rounded-md`) and 6px for cards and menus (`rounded-card`/`rounded-lg`), with 8px as the maximum.
  - No pills.
- **Roles:** primary = ice blue, secondary = seal gray, accent = blush peach (use sparingly), board = sand, design = lilac. The mascot/logo is a "foca watona" (spotted seal) peeking over a canvas (`src/shared/ui/brand/`).
- **Light theme only for now.** `FORCE_LIGHT_THEME` in `src/shared/stores/theme-store.ts` (mirrored in the `index.html` bootstrap script) disables dark mode. The `.dark` tokens and the theme plumbing are kept for later.
