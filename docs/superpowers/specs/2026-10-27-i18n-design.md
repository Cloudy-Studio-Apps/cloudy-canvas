# Translations (i18n) — design

English is the source language; Spanish is the first translation. No right-to-left support for now.

## Decisions

- **The language follows the operating system** (`navigator.languages`), unless the user picks one in
  Settings → Language: `System` (default), `English`, `Español`. An OS language we don't have falls
  back to English.
- **The change applies on the next launch.** The locale is set once at boot, before any feature code
  runs, so `t()` is a plain function: no hooks, no re-rendering, and engine code (plain TS) can call
  it, including in top-level constants like a module's command labels.
- **Every folder that shows text owns its strings**: a module, a page or an area (`canvas-ui`,
  `shared/ui/kit`, …) has `locales/en.json` and `locales/es.json` next to a `<name>.i18n.ts` that
  creates its translator:

  ```ts
  import en from "./locales/en.json";
  import es from "./locales/es.json";
  export const t = defineMessages({ en, es });
  ```

- **Keys are grouped.** The JSON nests objects for related strings; a key is the dot path to a
  string: `t("panel.add.active")`. A top-level string is just `t("title")`. Keys are type-checked
  against `en.json` (autocomplete, typos fail `pnpm typecheck`); a path that ends at a group, not a
  string, is a type error.
- **Variables**: `{name}` in the text, `t("gap", { size: 8 })`.
- **Plurals**: sibling keys `<key>_one` / `<key>_other` (any `Intl.PluralRules` category), called as
  `t("<key>", { count })`.
- **Fallback**: a string missing in Spanish shows the English one; a missing key (only possible
  through a plugin's untyped keys or a cast) shows `⟦panel.add.active⟧` and warns once in dev, and
  the plain key `panel.add.active` in production. `scripts/check-locales.mjs`, part of `pnpm lint`, keeps `es.json`
  complete, so neither should reach users.
- **Generic words** (Cancel, Save, Delete, Close, …) live once, in `@shared/core`'s `tCommon`.
- **Plugins** get `defineMessages` and `getLocale` in `api.core`; they read their own JSON with
  `api.plugin.readText`.
- **Stays English**: MCP tool names and descriptions (agents read them), ids, element types, file
  formats, key-cap labels (`"A"`), the brand name, and developer-facing messages (thrown `Error`s,
  `console`).

## Out of scope

Right-to-left layouts, live switching without a restart, more languages, an ESLint rule against
literal strings (worth adding once the migration is done), translation-management tooling.
