# Projects and Libraries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Projects (real folders with a `.cproject`, a project home, folders, trash) and per-project libraries (styles and assets every board and design in the project uses, kept in sync both ways).

**Architecture:** Plain-TS model and interfaces in `shared/core/projects/` (manifest, folder operations, registry), Tauri implementations in `platform/`, pages in `pages/projects/` and `pages/project/`. The library engine is plain TS in `canvas/libraries/` (a library is a Yjs document like a file; its records are mirrored into each file's `"tokens"`/`"assets"` maps with the library's ids and a `libraryId` tag, so bindings and the token sync don't change). `canvas-ui/libraries/` connects an open editor to its project's libraries (the library hub); the design and the board show and edit them through their existing panels.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), React 19, Zustand, Yjs, Tauri 2 (`@tauri-apps/plugin-fs`, `plugin-dialog`, `plugin-opener`), Tailwind v4 + shadcn kit, i18n en/es.

**Spec:** [`docs/superpowers/specs/2026-11-08-projects-design.md`](../specs/2026-11-08-projects-design.md). Mockups: `docs/prototype/projects-home-v3.html`, `docs/prototype/projects-assets.html`.

## Global Constraints

- **No test framework.** Every "verify" step is `pnpm lint && pnpm typecheck && pnpm format:check` (all three pass). Never run `tauri dev`, cargo or builds unless the user asks. Format only the files you touched (`pnpm exec prettier --write <files>`), never the whole repo: other sessions have uncommitted work.
- All work on `master`, no branches. Commit messages have **no** `Co-Authored-By` line. Stage only the task's files.
- Layering (CLAUDE.md rules 3–8): `shared/core` and `canvas/` are plain TS, never import React, `@platform`, `@tauri-apps/*`, `@shared/stores`, `@shared/ui`, `@canvas-ui`. Platform access goes through interfaces in `shared/core`, implemented in `platform/`. `src-tauri/` only gets a transport command (Task 2).
- Ids from `createId()`. Every `interface`/`type` in a sibling `.types.ts`. Files ~200 lines max, one concern each, re-exported by the folder's `index.ts`.
- UI: semantic tokens only, radii 4/6/8px, no pills; the kit (`@shared/ui/kit`) and `@canvas-ui` pieces before new components; `useCommitField` for rename fields; `useRowDrag` for drag-to-move (never HTML5 `draggable`); failures through `notifyError`/`toast`.
- All user text through the folder's `t` with `locales/en.json` and `locales/es.json` (Spanish complete); generic words via `tCommon`.
- Every user-facing task adds its entry to the unreleased section of `CHANGELOG.md` and `CHANGELOG.es.md` (New / Novedades), written for users, no internal names.
- Every changed folder's `README.md` is updated in the same task; new folders get one.
- Reserved names and paths (verbatim from the spec): project data folder `.cloudy/`, libraries in `.cloudy/libraries/<name>.clib` with images and SVGs in `.cloudy/libraries/<name>.assets/<id>.<ext>`, trash in `.cloudy/trash/`, project file `<Project name>.cproject` at the project root. Default projects folder `~/Documents/Cloudy Canvas/`.
- Desktop only: on Android and in the browser build the Projects button and pages are hidden (`isAndroidPlatform()`, `isTauri()`).

## Review Focus

1. **A project folder moved or renamed outside the app** while files point at it: opening a file must find it again (registry → search up for a `.cproject` with the same id → dialog), never show broken colors. Test owner: Task 8, step "missing project".
2. **Name collisions on disk**: a new folder, a moved file, a restored trash item or a new library whose name exists already gets " 2", " 3"…; a folder named `.cloudy` (any case) is refused. Owner: Task 1 (`uniqueName`, `isReservedName`), used by Tasks 5, 6, 9.
3. **Edits to library items from places that mustn't write them**: a live guest, a file whose project is missing, and an undo that crosses a library catch-up. The library file never takes those writes; the file shows the library's value again. Owner: Task 8.
4. **A crash or a second write during a save** of `.cproject`, `.clib` or the trash index leaves the old file intact (temp file + rename, writes queued per path). Owner: Task 2 (`writeAtomic`), Task 7.
5. **Big projects**: a scan of a folder with hundreds of files and nested folders doesn't freeze the project home (scan is async, folders read lazily for the tree's closed branches, sizes computed off the first paint). Owner: Task 5.
