# Module conventions, phase 1 (Rules) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `CLAUDE.md` becomes a short rules file (target ~15 KB, at most 20 KB); every description in
it moves, word for word, to a `README.md` next to the code it describes; the module conventions are
written once in `docs/modules.md`. No code changes.

**Architecture:** A move, not a rewrite. Each descriptive bullet of `CLAUDE.md` is cut and pasted,
unchanged, into the `README.md` of the folder it's about (the Mapping below), so a script can prove
nothing was lost. Only the rules are rewritten, into a numbered list at the top of `CLAUDE.md`, with a
"Transition" table (rules the code doesn't follow yet, and the phase that fixes each) and a "Where to
look" section (read the README of the folder you change and of its parents).

**Tech Stack:** Markdown, Prettier (`printWidth` 100, prose not rewrapped), a throwaway Python check
script in the scratchpad.

**Spec:** `docs/superpowers/specs/2026-10-25-module-conventions-design.md` (§2, §4, §5, §9, §10, §12
phase 1, §13, §15, §16.1).

## Global Constraints

- No source file changes: nothing under `src/` or `src-tauri/` but new or appended `README.md` files;
  nothing under `examples/` or `scripts/`.
- Descriptive lines move **verbatim** (same text, same order within a bullet, sub-bullets with their
  parent). A README gets a `# ` title and a one-line purpose; moved bullets go under `## ` headings
  named after their lead-in.
- A rule appears **once**, in `CLAUDE.md`. READMEs describe; they don't repeat rules.
- `CLAUDE.md` ≤ 20 KB. The `@CONTEXT` line is **removed** (the `CONTEXT.md` file itself stays).
- Terms are the spec's: **core module**, **feature**, **plugin** (packaging), **agent** (who calls),
  **MCP tool** (what it calls); plugin API stays **v1**.
- The rules describe the **target** (spec §4); the Transition table says where the code doesn't match
  yet. Nothing in `CLAUDE.md` may tell an agent to rename existing files before their phase.
- `docs/` keeps only cross-folder material: `modules.md`, guides, roadmaps, specs, plans. No
  `docs/architecture/`.
- No commits or branches (the user's). Verification: the check script, `pnpm format:check`,
  `pnpm lint`, `pnpm typecheck`.

## Review Focus

1. **A description silently dropped** (a sub-bullet left behind, a paragraph between bullets): the
   check script lists every old line not found in a new file; zero unexplained misses.
2. **An agent reads the new rules before phase 2 and creates `x.mcp.ts` beside `x.agent-tools.ts`:**
   each Transition row says "until phase N, follow the existing pattern here".
3. **An agent never opens the README** of the folder it edits: rule "read the folder's README and its
   parents' before changing code there" is in the Rules, and every README a rule depends on is
   linked from `CLAUDE.md`'s Where to look.
4. **Prettier changing moved text** (`Ctrl+\\`, `*` in globs, numbered lists): after
   `prettier --write`, the check runs again and still finds every line.
5. **Rules embedded in descriptive bullets lost in the cut** (per-product registries, content only in
   the Yjs doc and edits through `CanvasDocument`, never branch on `el.type`, keybindings the single
   source of shortcuts, never canvas elements in React state, toasts not `console.error`): each has a
   numbered rule.

### Task 4: The new `CLAUDE.md`

**Files:** Modify: `CLAUDE.md` (rewritten)

- [ ] **Step 1: Write `CLAUDE.md`** with exactly these sections, in order:
  1. The first two paragraphs, unchanged.
  2. `## Commands`, unchanged (the sh block and the paragraphs after it).
  3. `## Rules`: one numbered list, each item a rule in one to three lines, linking where detail
     helps. Groups, as bold lead-ins:
     - **Before you change code:** read the `README.md` of the folder you change and of its parents
       up to `src/`; when you change how something works, update that README in the same change.
     - **Verify:** `pnpm lint`, `pnpm typecheck`, `pnpm format:check` only; no builds, cargo or
       browser checks unless asked.
     - **Layering:** the old `### Layering` bullets as rules (aliases in both `tsconfig.json` and
       `vite.config.ts`; engine code plain TS; lower layers never import higher; products never import
       each other; platform through `shared/core` interfaces; logic in TS, not Rust; ids from
       `createId()`; Zustand stores hold app UI state only).
     - **Engine:** registries per product; content only in the Yjs doc, every edit through
       `CanvasDocument`, `doc.checkpoint()` before a user action; never branch on `el.type`, ask the
       kind; read geometry from the scene; shortcuts only in keybindings, read with
       `engine.keymap.label`; never canvas elements in React state.
     - **Modules:** tiers → `docs/modules.md#tiers`; anatomy and suffixes → `#module-anatomy`; the
       import rules → `#import-rules`; a feature uses only what a plugin could; new functionality is a
       module.
     - **MCP:** tools in `.mcp.ts` files (`#mcp-files`); "agent" is who calls, "MCP tool" what it
       calls; every editing tool is one `asUndoStep`.
     - **Code:** the old `## Code conventions` as rules (small files, split past ~200 lines, reuse the
       listed helpers, `useCommitField`, the kit before a new component, types in `.types.ts`).
     - **UI:** semantic tokens only, never palette scales; radii 4/6/8 px, no pills; every color
       through the one picker; failures toast with `notifyError`, never only `console.error`.
  4. `## Transition`: "Until a row's phase is done, follow the existing pattern in that part of the
     code.", then a table `Rule | Code today | Fixed in phase`: `.mcp.ts` files, `canvas/mcp`,
     `products/*/mcp` (2); features' points in their module (3); `.module.ts` ≤ ~100 lines (4);
     import rules, module READMEs complete (5); shared UI pieces (5a); `defineDesignMode` (5b);
     plugin API as barrels, `host.require` (6).
  5. `## Where to look`: the `## Project structure` tree, unchanged; then a table `Topic | README`
     with the main ones (`src/canvas/`, `src/canvas/elements/`, `src/canvas-ui/`,
     `src/products/board/`, `src/products/design/`, `src/app/mcp/`, `src/app/plugins/`,
     `src/shared/ui/`) and the `docs/` files (`modules.md`, `plugins.md`, `collaboration.md`,
     `er-language.md`, `performance-roadmap.md`).
     No `@CONTEXT` line.
