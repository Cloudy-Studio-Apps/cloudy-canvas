# 3D Models Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put FBX, OBJ and GLB/glTF models on Board and Design canvases as elements that show a saved picture at rest, go live in 3D only while edited, and can be converted to a plain PNG for good.

**Architecture:** Plain-TS model data, asset tracking, the asset sweep and the edit lock live in `src/canvas/model3d/`; everything that touches three.js (loading, the picture bake, the live overlay, the shared panel) lives in `src/canvas-ui/model3d/` behind dynamic `import()`. Each product adds a `model3d` feature module with its kind, convert, panel wiring and MCP tools. Engine-side code that needs three.js (MCP tools, the file-import hook) gets it injected as a `ModelBaker` from the module's `.module.ts`.

**Tech Stack:** TypeScript (strict), three.js (`three` + `@types/three`; `GLTFLoader`, `GLTFExporter`, `OBJLoader`, `MTLLoader`, `FBXLoader` from `three/examples/jsm/…`), React 19, Zustand, Yjs.

**Spec:** [docs/superpowers/specs/2026-10-30-3d-model-element-design.md](../specs/2026-10-30-3d-model-element-design.md). Read it before any task; this plan only records the decisions the spec left open.

## Global Constraints

- Verification is `pnpm lint`, `pnpm typecheck` and `pnpm format:check` only. No test framework; don't run `tauri dev`, cargo or builds.
- `three` is imported **only** through dynamic `import()` from `src/canvas-ui/model3d/`. Nothing in `src/canvas/` or `products/*` engine side imports it, not even as a type (use the plain-TS types from `canvas/model3d`).
- No live 3D on the canvas when nobody is editing. At most one live model per editor.
- Size warning threshold: `MODEL_SIZE_WARNING_BYTES = 10 * 1024 * 1024`, counting the model plus its textures. Warns only, never blocks.
- Supported model extensions: `glb`, `gltf`, `obj`, `fbx`.
- Every 3D-owned asset id is `` `model3d:${createId()}` `` (model, `.mtl`, textures, pictures). The prefix is how the sweep knows what it may remove.
- Picture: transparent PNG, `PICTURE_SCALE = 2` × the element's box, longest side capped at 4096 px, never theme-dependent.
- Live view is released `LIVE_RELEASE_DELAY_MS = 4000` after finishing.
- UI: kit `NumberInput`/`Field`/`Section`, `ImageChooseButton`/`chooseImageAsset`, `AppDialog`, `ToolButton`; semantic tokens, radii ≤ 8px, no raw `<button>`/`<input>`; all text through `t` (en + es); errors through `notifyError`.
- All rules in `CLAUDE.md` and `docs/modules.md` apply: types in `.types.ts`, files under ~200 lines, module files under 120 lines, READMEs updated in the same commit.
- Commits on `master`, no `Co-Authored-By` line.

## Review Focus

1. **Undo after Convert, then save mid-session.** The sweep must never run on autosave, only on open and on the editor's final save, so Ctrl+Z after Convert still finds the model. Pinned in Task 1, step 4.
2. **Copies and converted pictures share assets.** Deleting one copy, or converting one copy, must keep the model for the others; a converted image's picture id starts with `model3d:` and must survive the sweep. Pinned in Task 1, step 2 (the sweep counts every kind's `assets(el)` plus `modelAssets(el)`).
3. **Esc and scroll while live.** Esc finishes the edit (not leaving a mode or clearing anything else); the wheel over the live view zooms the model, never the canvas. Pinned in Task 6, step 3.
4. **A model pasted into another file** (the clipboard carries only the picture). Edit and the panel's view fields are disabled with a notice; Convert to PNG still works. Pinned in Task 7, step 2 (`hasModelData`).
5. **Read-only documents and someone else's live edit.** Edit, the panel and the MCP edit tools refuse: read-only through the document, "being edited" through the lock, both checked before any write. Pinned in Task 2 (lock) and Task 8/9 MCP steps.

### Task 3: Loading models (three.js)

**Files:**

- Modify: `package.json` (`pnpm add three` and `pnpm add -D @types/three`)
- Create: `src/canvas-ui/model3d/` with `index.ts`, `README.md`, `model3d.i18n.ts`, `locales/en.json`, `locales/es.json`, and `load/`: `index.ts`, `load-three.ts`, `parse-model.ts`, `resolve-textures.ts`, `import-model.ts`

**Interfaces:**

- Consumes: Task 1 types.
- Produces:
  - `loadThree(): Promise<ThreeKit>` — the one place with `import("three")` and the loader imports, memoized.
  - `interface ImportFile { name: string; path: string | null; data: Uint8Array }`
  - `interface ModelImport { format: ModelFormat; fileName: string; model: Uint8Array; mtl: Uint8Array | null; slots: ImportedSlot[]; totalBytes: number; aspect: number }` with `ImportedSlot = { name: string; file: string | null; embedded: boolean; data: Uint8Array | null }`
  - `importModel(main: ImportFile, others: readonly ImportFile[], readSibling: ((name: string) => Promise<Uint8Array | null>) | null): Promise<ModelImport>` — throws `Error` when the file can't be parsed.
  - `isModelFileName(name: string): boolean`
  - `interface LoadedModel { object: unknown; dispose(): void }` and `loadModel(source: ModelSource): Promise<LoadedModel>` where `ModelSource = { model: Uint8Array; mtl: Uint8Array | null; format: ModelFormat; textures: ReadonlyMap<string, Uint8Array> }` (slot name → image bytes). Add `ModelSource` to `canvas/model3d` types, since engine code builds it.

Decisions:

- `.gltf` is re-packed to GLB on import (`GLTFExporter`, `binary: true`) after resolving its external `.bin`/images through the same name matching; `model` is then GLB bytes, `format` stays `"gltf"` for display.
- Slots: one per material name. GLB and FBX embedded maps → `embedded: true`. OBJ with `.mtl` → its materials, `file` = the `map_Kd` file name. OBJ without `.mtl` → one slot named `"Model"`.
- Texture order (spec): embedded; then `readSibling(file)` (desktop: `readLocalFile` of the model's folder + name, any failure → `null`; `null` when `path` is null); then `others` matched by file name, case-insensitive; else `data: null` (gray, listed as missing).
- `aspect` is the fitted framing's width / height at `DEFAULT_MODEL_VIEW` (Task 4's framing function).
- `loadModel` applies each slot's texture by material name as the material's `map`; missing ones get a neutral gray `MeshStandardMaterial`.

- [ ] **Step 1:** Add the dependency; write `loadThree` with dynamic imports only.
- [ ] **Step 2:** Write `parseModel`, `resolveTextures`, `importModel`, `loadModel` as above.
- [ ] **Step 3:** README (the formats, texture order, the gltf re-pack, the lazy rule). Locale files can start with the strings the later tasks need under `import.*`.
- [ ] **Step 4:** Check the lazy rule: `pnpm lint && pnpm typecheck`, then `grep -rn "from \"three" src` shows only dynamic imports (or `import type`) under `src/canvas-ui/model3d/`. Commit `feat(model3d): load FBX, OBJ and glTF models`.

### Task 6: The live overlay and the edit session

**Files:**

- Create: `src/canvas-ui/model3d/live/`: `index.ts`, `model-edit-store.ts` (+ `.types.ts`), `model-live-view.tsx` (+ `.types.ts`), `use-live-renderer.ts`, `use-orbit-drag.ts`, `finish-model-edit.ts`

**Interfaces:**

  - `useModelEditStore`: `{ id: string | null; status: "idle" | "loading" | "live"; draft: ModelView & { textures: ModelTextureSlot[] } | null; start(id, data: ModelData): void; change(patch: Partial<draft>): void; stop(): void }`.   - `finishModelEdit(engine, id, data, draft): Promise<void>` — bakes the picture at the element's current box, adds it as a new asset, then writes `{ angle, zoom, textures, pictureAssetId }` in **one** `asUndoStep`. If nothing changed, writes nothing. The old picture stays until the sweep.

Behavior (spec "Editing"):

- Edits change only the draft (no document writes while live); the whole session is one undo step at finish.
- Dragging rotates (x from vertical drag, y from horizontal, 0.5° per px); the wheel over the view zooms the model within `ZOOM_RANGE` and `preventDefault`s so the canvas doesn't zoom.
- Esc (captured on the overlay while live) and the element leaving the selection both finish. Finishing releases the lock immediately, shows the new picture immediately, and disposes the renderer, geometry and textures `LIVE_RELEASE_DELAY_MS` later unless the same model is reopened.
- `status: "loading"` shows a spinner from the kit over the element while `loadModel` runs.
- Starting checks `MODEL_EDIT_LOCKS.assertFree` and `doc` not read-only (toast and don't start otherwise), then `lockLocal(id)`.
