# Live sessions: UI

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md)._

## Live sessions

- **Live sessions** (people editing together; guide: `docs/collaboration.md`): the person sharing a file **is** the server, and guests connect to their app peer to peer; when the host stops or quits, the guests' editors close and nothing stays on their computers. Desktop only.

## UI

- **UI** (`canvas-ui/share/`): `ShareButton` (both top bars; a `LiveBadge` for guests) opens `ShareDialog` (`StartSharing`, then `HostingPanel`: the link, `GuestRow`s with Direct/Via relay, role and Remove, Stop sharing); `LiveSessionLayer` (both chromes) shows `ShareKnocks`. `startSharing`/`stopSharing`/`useHostedSession` hold the one hosted session (quitting stops it, `appLifecycle.onBeforeQuit`); `sharingState` (`sharing-state.ts`, no dependencies) says which file is shared and its session's awareness, so the app shell follows it without loading the sharing code (`watchHostedTabs`, `app/tabs/`, marks that file's tab `hosting`), and `endSharing(fileId)` ends the session if it shares that file, with a toast saying so. `useHostedFile(file, engine)` marks the file context `live` (`LiveFile`: `side`, `role`, `host`). On desktop the session outlives the editor: its tab keeps the document connected in the background (the app autosaves it meanwhile) and the session ends when the user stops it or the tab closes (`closeTab`); where there are no tabs (Android) it ends when the editor closes. Guests: `/join/:ticket` (`pages/join/`: the name asked once, the waiting screens, `useHeldGuest`, which keeps one `ShareGuest` across remounts until `handOverGuest` gives it to a file tab, the missing-plugins notice), then, once live, a file tab (`openLiveTab`: `fileId` `live:<fileId>`, the tab's `live`; a session already open in a tab is shown instead and the new guest leaves). The tab owns the guest: closing it leaves the session, and a session that ends closes its tab with a toast saying why. `ReconnectingBanner` shows over a joined tab's editor while the host is being reached again. Its editor is `BoardEditor`/`DesignEditor` reading the tab's `live` (`loadCanvasFile` takes the session's Y.Doc, `LiveBoardSession`/`LiveDesignSession` with `useLiveGuestFile`: the host's file id and name, never saved, no thumbnail or recents, read-only for viewers). Home's top bar has Join (paste a link). The name is asked once when the app starts without one (`NamePrompt`, `shared/profile/`, mounted in the providers), prefilled with `randomPersonName()` (`shared/core/presence/`: "Sleepy Puffin"), which is kept if the dialog is dismissed. Session hooks that write derived data run on the host only (`useEmbedPreviews`).

## Presence

- **Presence:** awareness states are `{ user: ShareIdentity, presence: CollaboratorState }` (`RoomPresence`); `useRoomPresence` (from `useHostedFile` and `useLiveGuestFile`) publishes the user's pointer (`clientToWorld`), view, selection and page at most every 50 ms (as its editor goes, on desktop, the user stays in the room with the pointer, the selection and any live 3D edit cleared, since the tab keeps the session; an awareness already gone, or Android, clears the state) and the others are mirrored into the collaborators store (`mirrorRoomPresence`; on desktop by the app for as long as the session lasts, `watchRoomPresence` in `app/tabs/`, so a live tab without an editor still shows its people; on Android by `useRoomPresence` while the editor is mounted; stopping a mirror forgets only that room's people), so `CollaboratorLayer`, the stack and following work for people as for agents. Each person's agents on the shared file ride in their state (`RoomPresence.agents`, `RoomAgent`: id, name, app `clientId`, `idleFor` ms rather than a time, `running`, presence; `ownAgentsOn`/`roomAgents` in `room-agents.ts`, re-sent only when the user's own agents change, so an awareness heartbeat repeats the same `idleFor` and `mirrorRoomPresence` doesn't count that as activity): the others mirror them as `kind: "agent"` collaborators (`room:<client>:<agent id>`) drawn in the owner's colour with the app's logo, with `Collaborator.owner` (`collaboratorTitle`: "Claude Code · Sleepy Puffin" in cursors, outlines, the stack and the follow bar) and `permissions.undo: false` (only the owner undoes them). The Agents menu lists only this app's own (`AGENT_SOURCE`, `CollaboratorList`'s `source`). A viewer's agents can read: on a read-only document an actor document's writes throw `ReadOnlyDocumentError` (`canvas/document/`), and `get_board`/`get_design` report `editable: false`.

## Testing on one machine

- Testing on one machine: a debug build started with `CLOUDY_INSTANCE` set skips the single-instance plugin (`second_instance_allowed`, `src-tauri/src/lib.rs`).
