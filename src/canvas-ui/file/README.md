# Files

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md)._

## Files

- **Files:** every product's files go through `canvas-ui/file/`: `loadCanvasFile(id, { noun, open, create, kinds }, live)` loads the `CanvasDocument` from `Storage` (or starts an empty one for a new id, or takes a joined live session's Y.Doc), and the caller owns it: each product's `TabLoader` (`boardTabLoader`, `designTabLoader`) calls it for a file tab, which owns the document from then on, so editors never destroy it (`useCanvasFileLoader` is the same as a hook, destroying it on unmount, for a host that isn't a tab); `useCanvasFileSaver(id, engine, info, format)` saves it (a `CanvasFileFormat`: file type, noun, untitled name, `encode`; each write is `saveCanvasDocument({ id, doc, info, format, dir, path? })`, `save-canvas-document.ts`: the document encoded at once, then written after the writes already in line for that file id, whoever made them, so one file never has two writers, to `path` when given, else the file it was saved in (or the one the write before it made), else a free untitled name in `dir`, else its draft, with the title, description and project id, and the recents updated; the app's document autosave for a hosted tab with no editor uses it too, `app/tabs/`) and is provided as `CanvasFileContext` (`useCanvasFile()`; `isNew` while the file was opened without a saved one, as from Home; read by `SaveIndicator` and `DocumentInfoPopover`, also in `canvas-ui/file/`), and `useCanvasThumbnail` (called by the saver) takes the preview. The saver also reports to its tab (`TabContext`, `canvas-ui/tabs/`): whether it's `unsaved` (dirty: changes nothing will save, or an autosave pending; the tab's dot), the file it was just saved in (`reportInfo`: the first save, Save as, a draft becoming a file, so the tab's `load.info` follows it and an editor mounted again on the document never takes it for new and saves a second copy into `?dir`) and its name (title, else file name); and it registers the tab's handle (`tabHandles`: `save`, `flush` the pending autosave, `finish` the closing work, `capture`, `needsSave`: changes nothing will save, read from refs so it's right straight after a save). `isNew` is fixed when the editor mounts. A file is a 4-byte magic, a u32 format version and a Yjs update (`encodeCanvasFile`/`decodeCanvasFile`, `canvas/file/`): `CCBD` for `.cboard` (`products/board/file/board-file.ts`; the board's wrappers are `boardTabLoader`, `useBoardSaver`, `BOARD_FILE_FORMAT` in `products/board/ui/file/`), `CCDS` for `.cdesign` (`products/design/file/design-file.ts`, `designTabLoader`, `DESIGN_FILE_FORMAT`). `TauriStorage` keeps a recent-files index (id → path) in the app data folder. Ctrl+S / Ctrl+Shift+S are engine commands that run the host's handlers (`engine.handleHostAction("save", …)`).
  - **Autosave** (`useCanvasAutosave`, driven by `useCanvasFileSaver`): 1.5 s after changes stop (at most every 10 s while editing; `autosave-delays.ts`), and once more when the editor closes. A board with no file is autosaved as a **draft** (`storage.saveDraft`: `<appData>/drafts/<id>.cboard`, `FileInfo.draft`, badged on Home); Save asks where to put it and the draft file is removed (`storage.save`), forgetting a draft deletes it, and clearing the recents keeps drafts. Revisions counted per change keep the board dirty when it changes mid-save. The top bar's `SaveIndicator` shows a cloud while saving and a checked cloud for 3 s after (`saved` in the file context); the unsaved dot shows only when autosave is off or failed. The setting is `shared/stores/autosave-store.ts` (on by default, Settings › Files & storage). Closing the window waits for the tasks set with `appLifecycle.onBeforeQuit` (`AppLifecycle` in `shared/core`, `platform/tauri-app-lifecycle.ts`, up to 5 s; it needs `core:window:allow-destroy`): pending autosaves are flushed. `useCanvasAutosave` also runs `engine.sweepAssets()` (unused 3D data) when the editor opens and in its final work, never in the debounced autosave. The final work (`closing-work.ts`) runs once per engine, when its document goes: the window quits, the tab closes or hibernates (the tab handle's `finish`), or the editor closes otherwise, whichever comes first: it awaits the engine's `onBeforeSave` tasks (`engine.finishBeforeSave()`, at most 3 s: a live 3D edit writing itself), then sweeps; the closing save and the save quit task await it, and the closing save is forced when only that work changed the document (the change count stops with the editor). An editor that unmounts while its document stays (its tab dropped to `document` by the memory policy: `keepsDocument`, passed by the saver) only awaits the `onBeforeSave` tasks before its closing save, never sweeping, since the undo history still lives and may need those assets. The work and save started at unmount are the handle's `closed()`, which the memory policy awaits before destroying a hibernating tab's document. Home's previews are pictures of each file (`useCanvasThumbnail(id, engine, saved)`: `engine.thumbnail`, only when the document changed since the last one, taken after a manual save, when the quit dialog opens, before a background tab's editor is taken away by the memory policy (`tabLeaveGuard`, `canvas-ui/tabs/`: with tabs, going Home or switching no longer closes the editor), when a tab closes, and as the editor's `onClose` task and a quit task (skipped when already taken); it returns `capture`, stored with `storage.saveThumbnail` in `<appData>/thumbnails/<id>.jpg`, removed when the file is forgotten); `useFileThumbnail` (`pages/home/`) loads them and reloads when `thumbnail-store` bumps the file's version. Saves pass the document's title and description to `storage.save`/`saveDraft` (`FileMeta`), so the recents show them (a draft is named by its title), and the project id of its link (`doc.projectLink()`), so the recents know the file's project (`useRecentProject` also records it with `storage.setProject` as soon as a saved file opens or its link changes); the file's name opens `DocumentInfoPopover` to edit them.
  - **New files made in a project** open with `?dir=<absolute folder>&project=<project id>` (from the project home); the route's search params are kept by the file's tab (`params`, read with `useTabParam`, `canvas-ui/tabs/`). The saver reads `dir` once when the file is new: its first save, autosave included, goes to `<dir>/<untitled name>.<ext>` (numbered when taken, `freeFilePath`) without asking and without a draft; Save as still asks. `useProjectLibraries` gives the document its project link from `project`.
  - The index is validated on read (`isFileInfo`), written atomically (temp file + rename) and edited one change at a time (`mutate`); an unreadable one is set aside as `recent-files.corrupt.json` (`storage.takeIndexReset()`). Saves are atomic too.
  - `useRecentFilesStore` holds the recents and the ids of `missing` files (re-checked on window focus), plus `open(path)`, `relocate(id)` and `forget(id)`. Home's cards show missing files with Locate… / Remove, and every card has a ⋯ and right-click menu (`use-file-actions.ts`).
  - Files dropped on the window, picked with "Open with" or passed on the command line arrive through `FileOpenRequests` (`shared/core`, `platform/tauri-file-open-requests.ts`; drops come as `FileDrop`: `DroppedFile`s read on demand plus the client point) and are opened by `app/open-requests/`. On desktop opening never leaves a file (it's a new tab), so it doesn't ask; on Android it asks first when the open editor has changes nothing will save (`unsaved-changes-store`, set by `useCanvasFileSaver` only there).
  - **Quitting asks.** On desktop the app's one guard asks for every tab (`AppCloseGuard`, [app/tabs/](../../app/tabs/README.md)): the window's ✕ (`appLifecycle.onCloseRequest`; the updater's `runQuitTasks` doesn't ask) flushes every mounted tab's pending autosave and takes their previews, then quits, or asks once when some tab has changes nothing will save (autosave off or failing): Save all and quit · Quit without saving · Cancel (`SaveChangesDialog`, `close-dialog/`). Closing a tab asks the same for that file (`CloseTabDialog`: Save · Don't save · Cancel; `closeTab`, `app/tabs/`), otherwise it runs the tab's `finish` (the engine's last writes and the pending autosave, while the document is still there) and closes. Hibernated tabs and live guests have no handle and nothing to save. Each editor's quit tasks still run after the guard. Where there are no tabs (Android) `CloseFileGuard` (`close-dialog/`, mounted by every file session, doing nothing on desktop and for live guests) asks instead, as before: `CloseFileDialog`: Quit · Cancel, or, with changes nothing will save, Save and quit · Quit without saving · Cancel (`file.save()` returns whether it wrote), taking the preview (the tab's `capture`) as it opens. Leaving the editor inside the app (Back to home) doesn't ask; the preview is the editor's `onClose` task. `cloudy-canvas://` links (the deep-link plugin, scheme in `tauri.conf.json`; installers and the Arch desktop entry register it, dev builds and the AppImage register it at startup) arrive through `AppLinks` (`shared/core/app-links/`, `platform/tauri-app-links.ts`) and are read by `parseAppLink`: `open?path=<file>`, `board/<id>` / `design/<id>` (a recent file), `new/board` / `new/design`, `home`, `settings`; `app/open-requests/open-app-links.ts` follows them. A drop without a `.cboard`/`.cdesign` goes to the open editor's target in `file-drop-store` (registered by `useCanvasFileDrop(engine)` in `canvas-ui`), which adds the files to its canvas. On macOS, Cmd+Q closes the window through `src-tauri/src/mac_menu.rs`, because the default Quit item never asks; Quit from the Dock menu and logging out still end the app directly, so only autosave covers those.
