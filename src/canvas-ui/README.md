# Canvas UI (shared editor pieces)

_How it works. The rules are in the root [CLAUDE.md](../../CLAUDE.md)._

## Shared host

- **Shared host (`canvas-ui/`):** `useCanvasEngine(containerRef, product, document)` creates and mounts an engine into a container div; the canvas theme is resolved from CSS tokens via `readCanvasTheme()` and read again on every theme switch (`onThemeChange` → `engine.setTheme`); exports and thumbnails draw with `readExportCanvasTheme()` (the base theme, `CanvasEngineOptions.exportTheme`, `Renderer.exportBackground`), so files don't depend on the user's theme. The engine is provided through `EngineContext`, and chrome components use `useEngine()` and `useEngineState(selector)`, selecting primitives or stable references so each one re-renders only for its slice. Code is edited with `CodeEditor` (`shared/ui/components/code-editor/`, CodeMirror 6: line numbers, bracket matching, `completions`, an `errorLine` and a banded `highlight` range; text set from outside starts a fresh state, so its undo only covers typing). The generic chrome is here too (`FloatingPanel`, `ToolButton`, `OptionButton`, `ColorSwatch`, `ZoomControls`, `ZoomMenu`, `HistoryControls`, and `CommitInput`/`CommitTextarea`/`useCommitField` in `components/commit-field/`: text that writes on blur or Enter, one undo step per edit). **Every color in the app is picked with one picker, Figma's:** `ColorControls` (`components/color/`: `SaturationArea`, hue and opacity `ColorSlider`s, `EyedropperButton`, `HexInput`, `PercentInput`; `opacity` optional; drags report `{ done: false }` then `{ done: true }`) and `ColorPicker` (it plus the app's recent colors, `shared/stores/color-recents-store.ts`, and an `extra` slot, e.g. the design's page colors). **`AnchorPicker`** (`components/`): the 3×3 grid that picks a `ScaleAnchor` (`value`, `onChange`, `label` for its radiogroup); the design's scale sidebar uses it. **Element thumbnails** (`thumbnails/`): `ElementThumbnail` (`id`, a blank tile until drawn) and `useElementThumbnail(id)` are small pictures (240 px longest side) of top-level elements: one `ElementThumbnails` queue per engine (`elementThumbnailsOf`) draws each when the app is idle (`whenIdle`), from the views already drawn when the element is on the scope on screen and not turned (`engine.captureArea(rect, { scale, unfaded })`), otherwise exported off screen in its own workspace (`engine.workspace("thumbnails")`, so the user's page never changes). It watches the document only while subscribed, redraws an element 400 ms after something inside it changes (`engine.rootOf`), and keeps the picture when the element only moved with all it holds. The catalog's page rows, options, sidebar and preview strip use it. **Choosing a picture:** `chooseImageAsset(engine, { title, errorTitle? })` (`images/`) asks for one image file (`pickImageFiles`, `@platform`), adds it to the document's assets (`createId`, `doc.addAsset`) and returns its asset id, or `null` when cancelled or unreadable (a toast says so); `ImageChooseButton` is a kit `Button` ("Choose image…", or "Replace image…" with `replace`) that does it and calls `onChoose(assetId)`. The paint picker's image editor and the catalog's Replace use them. **The one color field:** `ColorField` (`components/color-field/`: a swatch opening `ColorPicker`, the hex unless `hex={false}`, the opacity as a percentage when `opacity` is given; `onChange({ color, opacity }, { done })`, typed values reported done) for every color a panel edits (effects, shader parameters, stickers' outlines and edges, variables' values), and `ColorPopover` under it (any trigger, a swatch by default, and `children` under the picker, e.g. a board color's description) where the color isn't in a field row. Both hold the editor's checkpoints (`doc.holdCheckpoints()`) from a drag's first step until it's done, the popover closes or the field goes, so a drag is one undo step whatever `onChange` does; outside an editor they just report. Color choices use `ColorPalette`: the palette's swatches plus `CustomColorSwatch`, which opens `ColorPicker` for any other color, applied live, a drag one undo step (`useScrubUndo`); `labelOf` names swatches. Options panels and side panels use it, not their own swatch lists (the board's sticky, shape fill and outline, section, table header and cell fills, connector, marker, ER entity and DB header colors). The design's paints (`SolidEditor`), gradient stops and effect colors use the same pieces.

## Starters

- **Starters (`starters/`):** `CanvasStarter<E>` is a ready-made start for a new file (`id`, `label`, `description`, a `preview` picture, `order`, `start(engine)`), listed on Home's first run from each product's starters point. `useStartStarter(engine, starters)` is the session hook a product's core runs: on a new file (`useCanvasFile().isNew`) whose link has `?starter=<id>`, it runs that starter's `start` once with its own origin (`doc.runAs`), so the user's undo history doesn't hold it and the first Ctrl+Z doesn't empty the file, then drops the parameter.

## Adding a product

- **Adding a product:** give it points (`createCanvasPoints<O>(id)`, `createEditorPoints(id)`), write its features as modules, compose it with `composeProduct`, and build its `ui/` editor from the `canvas-ui` module chrome, like the board and the design.
