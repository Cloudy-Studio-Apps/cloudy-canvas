# Canvas UI (shared editor pieces)

_How it works. The rules are in the root [CLAUDE.md](../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

## Shared host

- **Shared host (`canvas-ui/`):** `useCanvasEngine(containerRef, product, document)` creates and mounts an engine into a container div; the canvas theme is resolved from CSS tokens via `readCanvasTheme()` and read again on every theme switch (`onThemeChange` → `engine.setTheme`); exports and thumbnails draw with `readExportCanvasTheme()` (the base theme, `CanvasEngineOptions.exportTheme`, `Renderer.exportBackground`), so files don't depend on the user's theme. The engine is provided through `EngineContext`, and chrome components use `useEngine()` and `useEngineState(selector)`, selecting primitives or stable references so each one re-renders only for its slice. Code is edited with `CodeEditor` (`shared/ui/components/code-editor/`, CodeMirror 6: line numbers, bracket matching, `completions`, an `errorLine` and a banded `highlight` range; text set from outside starts a fresh state, so its undo only covers typing). The generic chrome is here too (`FloatingPanel`, `ToolButton`, `OptionButton`, `ColorSwatch`, `ZoomControls`, `ZoomMenu`, `HistoryControls`, and `CommitInput`/`CommitTextarea`/`useCommitField` in `components/commit-field/`: text that writes on blur or Enter, one undo step per edit). **Every color in the app is picked with one picker, Figma's:** `ColorControls` (`components/color/`: `SaturationArea`, hue and opacity `ColorSlider`s, `EyedropperButton`, `HexInput`, `PercentInput`; `opacity` optional; drags report `{ done: false }` then `{ done: true }`) and `ColorPicker` (it plus the app's recent colors, `shared/stores/color-recents-store.ts`, and an `extra` slot, e.g. the design's page colors). Color choices use `ColorPalette`: the palette's swatches plus `CustomColorSwatch`, which opens `ColorPicker` for any other color, applied live, a drag one undo step (`useScrubUndo`); `labelOf` names swatches. Options panels and side panels use it, not their own swatch lists (the board's sticky, shape fill and outline, section, table header and cell fills, connector, marker, ER entity and DB header colors). The design's paints (`SolidEditor`), gradient stops and effect colors use the same pieces.

## Adding a product

- **Adding a product:** give it points (`createCanvasPoints<O>(id)`, `createEditorPoints(id)`), write its features as modules, compose it with `composeProduct`, and build its `ui/` editor from the `canvas-ui` module chrome, like the board and the design.
