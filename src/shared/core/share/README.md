# Live sessions: transport and protocol

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

## Transport

- **Transport** (`ShareTransport`, `shared/core/share/share-transport.types.ts`; `shareTransport` in `@platform`, `null` in the browser): `host(relay, handlers)` / `join(addr, relay, handlers)` give a `ShareConnection` (`send`, `closePeer`, `peerPath` `direct`/`relay`, `stop`, which leaves a later session alone), frames reported to `ShareTransportHandlers` (`connected`, `frame`, `closed` `closed`/`lost`); `testRelay`. The desktop's is `TauriShareTransport` over `src-tauri/src/share/`: iroh 1.x (QUIC dialed by public key, hole punching, relay fallback, end to end encrypted), a fresh key per session, ALPN `cloudy-canvas/share/1`, length-prefixed frames on one bi-stream per peer, frames to the webview on a raw `Channel` prefixed with the peer number (u32 BE), `share://connected`/`share://closed` events with the webview's session id; commands `share_host`, `share_join`, `share_send` (raw body, `session`/`peer` headers), `share_close_peer`, `share_peer_path`, `share_stop`, `share_relay_test`. Relays: the official one the build was made with (`BUILT_IN_RELAY`, `shared/stores/built-in-relay.ts`, from `VITE_CLOUDY_RELAY_URL`/`VITE_CLOUDY_RELAY_TOKEN`: `.env.local`, or the `CLOUDY_RELAY_URL`/`CLOUDY_RELAY_TOKEN` secrets in the release workflow), used alone, or n0's public ones. Release builds always host through the official one (`hostingRelay`); `startHost` (`canvas-ui/share/start-host.ts`) starts the session again through n0's when it doesn't come online, and `useRelayStatusStore` (`builtInDownSince`, this run only; skipped for 5 minutes) makes Settings › Collaboration show `RelayDownNote` and the share dialog's `RelayNote` say so. Only development builds (`RELAY_CHOICE_IN_SETTINGS`) let Settings pick the relay (`useCollaborationStore`: `relayChoice` built-in, public or the user's own `customRelay`, e.g. `server/relay/`). The link carries the host's relay, so guests need no setup.

## Protocol

- **Protocol** (`shared/core/share/protocol/`, `SHARE_PROTOCOL`): a frame is a tag byte then a control message as JSON (`ShareControl`: `hello` with the secret, identity and a `rejoin` key; `waiting`, `admitted` with role, `SharedFileInfo` (product, the host's `fileId`, name, plugins), host and rejoin key; `denied`, `role`, `removed`, `ended`; checked field by field, `decodeFrame`), a y-protocols sync message or an awareness update. Links are `cloudy-canvas://join/<ticket>` (`shareLink`, `readShareTicket`: base64url JSON of the host's address, relay and a 32-byte secret, `createShareSecret`); `parseAppLink` gives `{ action: "join" }`, followed to `/join/:ticket`.
