# Board editor

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md)._

**Public API.** `ui/index.ts` (`@board/ui`) is the editor's public API as well as its entry: `useBoardEngine`/`useBoardState`, `useBoardPanelStore`, `components/board-colors`, `components/source-editor`, `ui/modules` (points, mode helpers). Built-in modules import those pieces by their path (importing `@board/ui` from a module would loop through the module list), and plugins get them as `api.board`, with the engine barrel. `scripts/check-public-api.mjs` fails when a feature imports a piece this barrel doesn't export.

## Board editor

- **Board editor (`products/board/ui/`):** `BoardEditorPage` (`/board/:id`) loads the document and mounts the engine with `getBoardProduct()`. `BoardSession` provides the engine, the file and `getBoardEditorModules()`, and renders `ModuleSession` and `BoardChrome`, which places the module slots. Panels read the schema with `useBoardSchema()` (the `DB_SCHEMA` service) and `useDbQuery`/`useDbTable`/`useDbEnum` (`modules/db/ui/schema/`), which re-read only when the schema changes. The database panel (`modules/db/ui/db-panel/`, with the shared `ui/components/source-editor/`: `SourceEditor` applies text while typing, shared with the ER panel's Text tab, colored by a language and suggesting with a completion source it's given. The editor knows no language: `createSourceLanguage` (`languages/`) makes a small `StreamLanguage` that never fails on half-typed text, and `completions/` has the helpers to write a completion source (`readSourceContext`, `definedNames`, `writtenName`, `completionResult`, `nameOptions`, `startingWith`). The DBML language and completions are the db module's (`modules/db/ui/source/`), the ER ones the er module's (`modules/er/ui/source/`)) shows the selected table or enum (`selectedId` + `selectionTypes` from `EngineState`), or the whole schema from the top bar's button (`modules/db/ui/schema-button.tsx`, state in `ui/stores/board-panel-store.ts`); `.dbml` import/export goes through `@platform`. The ER panel (`modules/er/ui/er-panel/`) works the same way with the board's `ErModel` (`useErModel` is the `ER_MODEL` service; `useErQuery`, `useErSelection` in `modules/er/ui/model/`): it opens when an ER element is selected and shows that element's diagram, as a form for the selected element or as text. Board components that read or set tool options use `useBoardEngine()` / `useBoardState()` (`board-engine-context.ts`), typed with `BoardToolOptions`. The tool options panels (in each module's `ui/`) are contributed to `toolPanels`/`selectionPanels`.

- **Board modes:** a board mode is one `defineBoardMode({…})` object registered with `registerBoardMode(host, mode)` (`ui/modules/`), `canvas-ui`'s `registerEditorMode` with the board's points (the ER mode).
