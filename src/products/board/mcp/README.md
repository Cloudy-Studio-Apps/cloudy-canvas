# Board MCP plumbing

The host the board's MCP tools reach (`AgentHost`, `requireBoard`), the server's instructions
(`BOARD_MCP_INSTRUCTIONS`), `createBoardMcpTools` (collects the modules' groups) and `reportApplied`.
The tools themselves live in their modules: the general ones in `modules/core/mcp/`.

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md)._

## The board's tools are contributed by modules

- **The board's tools are contributed by modules** to `boardMcpTools` (`board-points.ts`) as groups (`BoardMcpToolGroup`: `tools({ kinds })`), one group per file: the core module's general tools in `modules/core/mcp/` (its sides of the topics shared with designs: `file.mcp.ts`, `selection.mcp.ts`, `history.mcp.ts`, `view.mcp.ts`, `clipboard.mcp.ts`, `arrange.mcp.ts`, `style.mcp.ts`; then `board-read.mcp.ts`, `create-shapes.mcp.ts`, `shape-edit.mcp.ts`, `order.mcp.ts`, `export.mcp.ts`) and the features' own (`db.mcp.ts`, `er.mcp.ts`, `sticker.mcp.ts`, `colors/mcp/`, `model3d/mcp/`: `model3d_add`, `model3d_view_set`, `model3d_convert_to_png`, built by `modelTools(modelBaker)`). `createBoardMcpTools(modules, kinds, pluginOf, reserved)` collects them for `app/mcp` with their full names (`collectMcpTools`, see [canvas/mcp](../../../canvas/mcp/README.md#tool-names)); the core module's shared topics declare their topic (`file`, `selection`, `history`, `view`, `clipboard`, `arrange`, `style`) and its shape tools `shapes`. A shared tool's name, description and `inputSchema` come from one constant in `canvas/mcp/shared/` (or `canvas/model3d/mcp/`, or the `canvas/mcp` factories), so the board's and the design's are the same and the server lists one tool for both; the board adds its `run`. Tools reach a board's facades through `board.engine.service(DB_SCHEMA | ER_MODEL)`. A tool is an `McpTool<AgentHost>` and gets the `AgentHost` (the open board, recent files, opening a board). Every editing tool wraps its writes in `asUndoStep(engine.doc, …)` so one call is one step of the agent's own undo history (its workspace's; the user's Ctrl+Z doesn't undo it unless they follow the agent), and builds or validates everything before writing. `selection_get` reads the user's selection (`userSelection()`); `selection_set`, `view_fit`, `view_fit_elements` (`engine.zoomToElements`), `history_undo`/`history_redo` and `pages_switch` act on the agent's own. Element tools go through the kinds (the canvas `buildElement`, `agentPatches`, `summarizeElement` with `engine.kinds`). `shapes_update` runs `agentPatches` (`canvas/mcp/`): each patch is checked against `patchableFields` and the stored field types, a new `w`/`h` goes through `kind.resize` (`resizePatch`: proportions, minimums, a table's grid), the kind's `completePatch` validates the rest, and a moved element takes its `engine.withMembers(…, "move")` members along. `file_info_set` (`file.mcp.ts`) sets the title and description, which `file_get` and the file tools return. `shapes_duplicate` is `engine.duplicateElements` (Ctrl+D's copy, with `prepareCopies`). The context menu's actions have tools that take ids and leave the selection alone: `shapes_reorder` (`engine.reorderElements`), `shapes_lock` (`engine.setLocked`), `clipboard_png_copy` (`engine.copyAsPng(ids)`, with `optionalShapeIds`) and `shapes_export` (`engine.exportElements` with `ExportOptions.ids`, written by `AgentHost.writeFile`, `writeExportFile` in `@platform`, to a path or next to the board's file). `view_snapshot` returns the board as a PNG: a tool returning a `ToolImage` (`shared/core/mcp`) is sent as MCP image content. `er_text_apply` creates entities a relation names (`createMissing`), as the DBML tools create missing tables.
