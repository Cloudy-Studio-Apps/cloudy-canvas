# Board MCP plumbing

The host the board's MCP tools reach (`AgentHost`, `requireBoard`), the server's instructions
(`BOARD_MCP_INSTRUCTIONS`), `createBoardMcpTools` (collects the modules' groups) and `reportApplied`.
The tools themselves live in their modules: the general ones in `modules/core/mcp/`.

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md)._

## The board's tools are contributed by modules

- **The board's tools are contributed by modules** to `boardMcpTools` (`board-points.ts`) as groups (`BoardMcpToolGroup`: `tools({ kinds })`), one group per file: the core module's general tools in `modules/core/mcp/` (`board-read.mcp.ts`, `board-info.mcp.ts`, `create-shapes.mcp.ts`, `shape-edit.mcp.ts`, `arrange.mcp.ts`, `view.mcp.ts`, `export.mcp.ts`, `file.mcp.ts`, `plugins.mcp.ts`) and the features' own (`db.mcp.ts`, `er.mcp.ts`, `sticker.mcp.ts`, `colors/mcp/`). `createBoardMcpTools(modules, kinds)` collects them for `app/mcp`. Tools reach a board's facades through `board.engine.service(DB_SCHEMA | ER_MODEL)`. A tool is an `McpTool<AgentHost>` and gets the `AgentHost` (the open board, recent files, opening a board). Every editing tool wraps its writes in `asUndoStep(engine.doc, …)` so one call is one step of the agent's own undo history (its workspace's; the user's Ctrl+Z doesn't undo it unless they follow the agent), and builds or validates everything before writing. `get_selection`/`get_design_selection` read the user's selection (`userSelection()`); `select_*`, `zoom_*`, `undo`/`redo` and `switch_page` act on the agent's own. Element tools go through the kinds (the canvas `buildElement`, `agentPatches`, `summarizeElement` with `engine.kinds`). `update_shapes` runs `agentPatches` (`canvas/mcp/`): each patch is checked against `patchableFields` and the stored field types, a new `w`/`h` goes through `kind.resize` (`resizePatch`: proportions, minimums, a table's grid), the kind's `completePatch` validates the rest, and a moved element takes its `engine.withMembers(…, "move")` members along. `set_board_info` (`board-info-tools.ts`) sets the title and description, which `get_board` and the file tools return. `duplicate_shapes` is `engine.duplicateElements` (Ctrl+D's copy, with `prepareCopies`). The context menu's actions have tools that take ids and leave the selection alone: `reorder_shapes` (`engine.reorderElements`), `lock_shapes` (`engine.setLocked`), `copy_as_png` (`engine.copyAsPng(ids)`) and `export_shapes` (`engine.exportElements` with `ExportOptions.ids`, written by `AgentHost.writeFile`, `writeExportFile` in `@platform`, to a path or next to the board's file). `view_board` returns the board as a PNG: a tool returning a `ToolImage` (`shared/core/mcp`) is sent as MCP image content. `apply_er_text` creates entities a relation names (`createMissing`), as the DBML tools create missing tables. The MCP names still say "shapes" (`create_shapes`, …) so agents' setups keep working.
