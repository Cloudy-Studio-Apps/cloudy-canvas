# Design MCP plumbing

The host the design's MCP tools reach (`DesignAgentHost`, `requireDesign`, `requireNodes`), the
server's instructions (`DESIGN_MCP_INSTRUCTIONS`, after the shared and the board's parts) and `createDesignMcpTools`. The tools themselves
live in their modules (`modules/*/<name>.mcp.ts` or `modules/*/mcp/`).

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md)._

## The design's tools are contributed by its modules

- **The design's tools are contributed by its modules** to `designMcpTools` (`design-points.ts`, `DesignMcpToolGroup`), each from its own folder: the core module's `modules/core/mcp/` (its sides of the topics shared with boards, one group each with its topic as `prefix`: `file_get`, `file_info_set`, `file_save`, `selection_get`, `selection_set`, `history_undo`, `history_redo`, `view_fit`, `view_fit_elements`, `view_snapshot`, `clipboard_png_copy`, `arrange_align`, `arrange_distribute`, `arrange_tidy_up`, `arrange_scale`, `style_copy`; then `nodes_list`, `nodes_get`, `nodes_create`, `nodes_update`, `nodes_delete`, `nodes_duplicate`, `nodes_reorder`, `nodes_lock`, `nodes_rotate`, `nodes_flip`, `nodes_export`), and `frame.mcp.ts` (`frame_presets_list`, `frame_preset_add`), `group.mcp.ts` (`group_create`, `group_frame_create`, `group_release`), `layers/mcp/layer-tree.mcp.ts` (`layers_tree_get`), `pages/mcp/pages.mcp.ts` (`pages_list`, `pages_switch`, `pages_create`, `pages_rename`, `pages_duplicate`, `pages_delete`, `pages_reorder`, `pages_nodes_move`), `vector.mcp.ts` (`vector_convert`, `shapeToVector`, shared with the edit mode), `image/mcp/add-image.mcp.ts` (`image_add`, a picture file read with `DesignAgentHost.readFile`, `readLocalFile` in `@platform`; `image_replace`) and `text.mcp.ts` (`text_fonts_list`). The plumbing is `products/design/mcp/` (`DesignAgentHost`, `requireDesign`, `requireNodes`, `createDesignMcpTools`, `DESIGN_MCP_INSTRUCTIONS`). `createDesignMcpTools(modules, kinds, pluginOf, reserved)` collects the groups with their full names (`collectMcpTools`, see [canvas/mcp](../../../canvas/mcp/README.md#tool-names)); the `core` module's shared topics declare their topic (`file`, `selection`, …) and its layer tools `prefix: "nodes"`, the other modules' tools take their module id (`frame_presets_list`). A shared tool's name, description and `inputSchema` come from one constant in `canvas/mcp/shared/` (or `canvas/model3d/mcp/`, or the `canvas/mcp` factories), so the board's and the design's are the same and the server lists one tool for both; the design adds its `run`. `nodes_create` builds through the kinds: a `creatable` `DesignNodeKind` gives `nodeFromSpec(spec, index, context)` (a `NodeBuildContext`: the tool options and `nameFor(base)`; `BoxShapeKind` makes any box shape, kinds add their `specProperties`), `buildNode` adds what every node takes (`applyNodeSpec`: name, visibility, opacity, `fill`/`fills`, `stroke`/`strokes`, `strokeWeight`, paints checked by `readPaints`), and the tool puts it in the container under it (`containerAt`) or the `parent` given (`checkParent`). `nodes_update` is `agentPatches`; `DesignNodeKind.completePatch` checks the shared fields (`checkNodePatch`, `parentId` included) and kinds check theirs (a text lays out again, a line's `points` and a vector's `network` re-wrap their bounds). Both products share `canvas/mcp/` (`AgentFile`, `AgentRecentFile`, `McpToolGroup`, `collectMcpTools`, `exportPath`, `elementSpec`, `arrangeTools`, which makes each product's `arrange_align`, `arrange_distribute`, `arrange_tidy_up` and `arrange_scale`, and `copyPropertiesTool`, its `style_copy`; each product's are in its core's `modules/core/mcp/arrange.mcp.ts` and `style.mcp.ts`).
