# Design MCP plumbing

The host the design's MCP tools reach (`DesignAgentHost`, `requireDesign`, `requireNodes`), the
server's instructions (`DESIGN_MCP_INSTRUCTIONS`) and `createDesignMcpTools`. The tools themselves
live in their modules (`modules/*/<name>.mcp.ts` or `modules/*/mcp/`).

_How it works. The rules are in the root [CLAUDE.md](../../../../CLAUDE.md)._

## The design's tools are contributed by its modules

- **The design's tools are contributed by its modules** to `designMcpTools` (`design-points.ts`, `DesignMcpToolGroup`), each from its own folder: the core module's `modules/core/mcp/` (`get_design`, `list_nodes`, `get_nodes`, `get_design_selection`, `set_design_info`, `create_nodes`, `update_nodes`, `delete_nodes`, `duplicate_nodes`, `select_nodes`, `reorder_nodes`, `lock_nodes`, `align_nodes`, `distribute_nodes`, `tidy_up_nodes`, `view_design`, `export_nodes`, `copy_nodes_as_png`, `zoom_design_to_fit`, `zoom_to_node`, `undo_design`, `redo_design`, `list_recent_designs`, `open_design`, `new_design`, `save_design`), and `frame.mcp.ts` (`list_frame_presets`, `add_preset_frame`), `group.mcp.ts` (`group_nodes`, `ungroup_nodes`), `layers/mcp/layer-tree.mcp.ts` (`get_layer_tree`), `pages/mcp/pages.mcp.ts` (`list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`), `vector.mcp.ts` (`convert_to_vector`, `shapeToVector`, shared with the edit mode), `image/mcp/add-image.mcp.ts` (`add_image`, a picture file read with `DesignAgentHost.readFile`, `readLocalFile` in `@platform`; `replace_image`) and `text.mcp.ts` (`list_fonts`). The plumbing is `products/design/mcp/` (`DesignAgentHost`, `requireDesign`, `requireNodes`, `createDesignMcpTools`, `DESIGN_MCP_INSTRUCTIONS`). `create_nodes` builds through the kinds: a `creatable` `DesignNodeKind` gives `nodeFromSpec(spec, index, context)` (a `NodeBuildContext`: the tool options and `nameFor(base)`; `BoxShapeKind` makes any box shape, kinds add their `specProperties`), `buildNode` adds what every node takes (`applyNodeSpec`: name, visibility, opacity, `fill`/`fills`, `stroke`/`strokes`, `strokeWeight`, paints checked by `readPaints`), and the tool puts it in the container under it (`containerAt`) or the `parent` given (`checkParent`). `update_nodes` is `agentPatches`; `DesignNodeKind.completePatch` checks the shared fields (`checkNodePatch`, `parentId` included) and kinds check theirs (a text lays out again, a line's `points` and a vector's `network` re-wrap their bounds). Both products share `canvas/mcp/` (`AgentFile`, `AgentRecentFile`, `McpToolGroup`, `collectMcpTools`, `exportPath`, `elementSpec`, and `arrangeTools`, which makes each product's `align_*`, `distribute_*` and `tidy_up_*` tools: the board's `align_shapes`, … are in `modules/core/mcp/arrange.mcp.ts`).
