# Prototype

Clickable prototypes inside a design: in the Prototype mode a page's top-level frames are screens, layers (and screens themselves) get interactions that link them, and flows say where a prototype starts and which device it plays on. One file can hold an app's flows and a website's side by side.

- **Tier:** feature
- **Requires:** core, pages, frame
- **Contributes:** kinds `PrototypeFlowKind`; designCanvas (`prototype.canvas.ts`): `kinds`, `onRemove` (`prunePrototype`), host command `prototype.toggle` (Shift+E); the Prototype mode (`prototype.mode.ts`: tools `prototype.select` (V) and `prototype.connect` (L), their keys in the mode's `keybindings` (a layer matched first: as tool `keys` the base select tool's V would win and L would take the line tool's in the Design mode), overlays `LinksLayer`, `ConnectHandle` and `DragLine`, service `CONNECT_DRAG`, host command `prototype.addFlow` on Shift+F, the Flows tab, the sidebar); `designEditor.sessionHooks` (`useToggleCommand`), `designEditor.layerBadges` (`InteractionBadge`)
- **Points it owns:** —
- **MCP tools:** —
- **Files:** `model/` (the interaction and flow types, their defaults, defensive readers and `editInteraction`, the devices, screens, `DESIGN_PROTOTYPE` and the pruning), `prototype.constants.ts` (the record type, every trigger, action, animation, … as lists, the limits), `prototype.canvas.ts` (its canvas hooks), `prototype.mode.ts` (the Prototype mode), `mode/` (its select and Connect tools, the connect gesture, `CONNECT_DRAG` and the allowed commands), `ui/` (the Flows tab, toolbar items, sidebar and `ui/sidebar/`: the interaction editor, badge, view store and selection hook, and `ui/canvas/`: the links layer, the connect handle, the drag line and its toast).
- **Not yet:** the player (▶ in the Flows tab is disabled), Smart animate (it needs layers drawn separately), Scroll to and scrolling screens (frames clip their content), Change to (needs components and variants), a Present mode for slides (it will reuse this player), comments and sharing a prototype link (web build).

## How it works

- **Screens** (`model/screens.ts`): a screen is a top-level frame of a design page (`isScreen`: `isFrame(el) && el.parentId === null`). `screensOf(doc, page)` lists a page's in layer order; `screenOf(doc, id)` walks a node's parents up to its screen (the node itself when it's one), `null` when it's on none.
- **Interactions** are an optional node field, `interactions: PrototypeInteraction[]` (`model/interaction.types.ts`): a trigger (`click`, `hover`, `press`, `enter`, `leave`, `drag`, `key` with its `key`, `delay` with its `delay`), an action (`navigate`, `overlay` and `swap` with a screen's id in `to`, `back`, `close`, `link` with its `url`), a `transition` (animation, direction, duration, easing) and, on `overlay` and `swap`, an `overlay` (position, close on a click outside, dim). Any node can have them, a screen included. They're read defensively, as the catalog reads `repeatCopy`: `nodeInteractions(el)` keeps the ones `readInteraction` accepts, `[]` when the field is missing or malformed. `readInteraction` refuses (`null`) a value without an id, with an unknown trigger, action or animation, a `navigate`/`overlay`/`swap` without a string `to`, or a `link` whose `url` isn't `http:`/`https:` (`new URL(url).protocol`); it clamps `duration` to 0–5000 ms and `delay` to 0–60000 ms, fills a missing transition with `DEFAULT_TRANSITION` (`dissolve`, `left`, 300 ms, `ease-out`) and a missing overlay with `DEFAULT_OVERLAY` (`center`, closes outside, dims), and drops fields the trigger or action doesn't use (`key` off `key` triggers, `to`, `url` and `overlay` off the actions without them). `newInteraction(to?)` is a new one: a click that navigates. `writeInteractions(doc, nodeId, list)` writes a node's list in one `doc.update` with no checkpoint (the caller makes the undo step); an empty list clears the field (`interactions: null`, `interactionsPatch`).
- **Flows** are records, like the catalog's brochures: a `prototype-flow` element (`PrototypeFlowElement`: `name`, `page`, `start`, `platform`, `device`, `orientation`, `hints`) whose kind (`PrototypeFlowKind`) isn't creatable, isn't boxed, and draws and hits nothing, so it's never on a page's canvas (`PAGE_SCOPES` shows only nodes). `fillDefaults` gives older records `orientation: "portrait"` and `hints: true` (`PROTOTYPE_FLOW_DEFAULTS`).
- **Devices** (`model/devices.ts`): `PROTOTYPE_DEVICES` lists each platform's device ids, the first its default (mobile `iphone-16`, `iphone-se`, `pixel-9`; tablet `ipad-air`, `galaxy-tab`; desktop `window-mac`, `window-windows`, `window-linux`; web `browser-1280`, `browser-1440`, `browser-fit`). `defaultFlowDevice(screen)` is what a new flow plays on: a screen wider than 600 units gets `web`/`browser-1280`, any other `mobile`/`iphone-16`.
- **`DESIGN_PROTOTYPE`** (`DesignPrototype`, `engine.service(DESIGN_PROTOTYPE)`) is the one place that edits flows and interactions, each write one undo step (it checkpoints first, as `DesignBrochures` does): `flows(page)` (in `index` order), `flow(id)`, `addFlow(page, start, name?)` (the screen must be on that page; named `"<screen> flow"` in its creator's language, `flow.defaultName`; its `index` after the last flow's), `updateFlow(id, patch)` (a new `platform` without a `device` gets that platform's first device; an empty name is ignored), `removeFlow(id)`, `interactions(nodeId)`, `setInteractions(nodeId, list)`, `addInteraction(nodeId, ix)`, `removeFlowsStartingAt(screenId)` (every flow starting there, one step), `removeInteractions(nodeIds)` (every node in one step) and `linksTo(screenId)` (the nodes with an interaction showing it).
- **Deleting** (`prunePrototype`, the module's `onRemove`, in the deletion's undo step): in one pass over the document, a flow whose page or starting screen was deleted goes, and a node that stays drops its interactions whose `to` was deleted (the rest are written back).
- **Copies** need no `prepareCopies` hook: the clipboard's `remapIds` rewrites every element id in a copy, so a link to a screen copied with it points at the screen's copy, and a link to a screen that wasn't copied keeps pointing at the original. Flows aren't copied with their screens.
- **The mode** (`prototype.mode.ts`): Shift+E (`useToggleCommand`, a session hook because it needs `useEditorMode`) switches between it and the default mode from any mode. In it the select tool (`PrototypeSelectTool`) picks the layer under the pointer, even inside groups (`targetAt(world, true)`), and never moves, resizes or edits text. A press on a screen's empty area selects the screen (the context it hands `SelectTool` never passes `background`), unlike the Design mode, where it starts a selection box: here screens are a frequent target (flow start, a screen's triggers, a link's drop) and a box is rarely needed (decided with the user, 2026-11-08); Delete clears the selection's interactions instead of deleting layers. Only the commands in `PROTOTYPE_ALLOWED_COMMANDS` run. The rail has Flows and Layers.
- **Selection** (`usePrototypeSelection`, type `PrototypeSelection` in `model/`): a flow picked in the Flows tab while the canvas selection is empty, else one selected element as a `screen` or a `layer` (with its screen); several count as none. Selecting on the canvas drops the picked flow and picking a flow clears the canvas selection (`usePrototypeViewStore`). `usePrototypePage` gives the page's flows and screens, read again when the document changes.
- **Flows tab**: "+" (or Add flow start, Shift+F, on the selected screen when it starts no flow) adds a flow with `DESIGN_PROTOTYPE.addFlow` and picks it; without a selected screen "+" uses the page's first screen.
- **Links layer** (`ui/canvas/links-layer.tsx`, the mode's `overlays` entry): redraws on view change and when the document changes. Each node of a screen with interactions gets, per interaction, a `LinkArrow` (a navigate, overlay or swap to a screen; dashed for an overlay) or a `LinkStub` (back, close and link: 18 px and a chip). `linkPath(from, fromScreen, to)` routes in screen px: forward (target left edge at or past the layer's right edge) from the layer's right middle to the target's left edge, `y` clamped 24 px inside it, `k = max(40, dx / 2)`; backward under both screens into the target's bottom edge for a layer in its screen's lower half, otherwise over their tops, 36 px clear. The selected layer's arrows (or every arrow of a selected screen) are thicker, and `showLinks === "selection"` draws only those. Each flow gets a `FlowFlag` above its starting screen: the one part that takes the pointer; a click calls `pickFlow` (the same as picking it in the Flows tab).
- **Interaction editor** (`ui/sidebar/`): with a `layer` selected the sidebar shows `LayerPanel` (its name, "In <screen>") and `InteractionsSection({ owner })`, which works for any node id, a screen included: one `InteractionCard` per interaction (summary with the trigger icon and a remove button; `TriggerFields`, `ActionFields`, `OverlayFields` for `overlay`/`swap`, `TransitionFields` unless the action is `link`), and a + that adds `newInteraction(firstOtherScreen)`, or a `back` when the page has no other screen. The To list holds the page's screens except `screenOf(owner)`; without one the actions that show a screen aren't offered. Every change is one `DESIGN_PROTOTYPE.setInteractions` through `editInteraction(ix, patch)` (`model/`, pure: a new action drops the `to`, `url` and `overlay` it doesn't take and gets the ones it needs, `to` stays between navigate, overlay and swap; a new trigger drops `key`/`delay`), so an interaction is never left unreadable; a link's URL is checked as `readInteraction` does. `interactionSummary(ix, screenName)` words a card's title ("On click → Navigate to Menu").
- **Screen, flow and empty panels** (`ui/sidebar/`, chosen by `PrototypeSidebar` from `usePrototypeSelection`): `ScreenPanel` has a Flow start switch (on adds a flow with `addFlow`, labelled "Starts “<flow>”"; off removes all flows starting there with `removeFlowsStartingAt`, one undo step), then `InteractionsSection({ owner: screenId })` and `LinksToScreen` (the nodes of `linksTo`, each with its screen; a click calls `engine.select`). `FlowPanel` has the name (`CommitInput`), Starts at, `DeviceFields` (platform with icons, the platform's devices labelled with their sizes by `deviceLabel`, orientation for mobile and tablet, a note on what the platform plays in), the hotspots switch, Play (disabled until the player) and Delete flow (picks no flow, then `removeFlow`). `EmptyPanel` says what to select and sets Show links (`setShowLinks`).
- **Connect** (`mode/`, `ui/canvas/`): a link is dragged out of a layer or a screen by `ConnectGesture` (`begin`, `move`, `finish`, `cancel`), from the select tool's connect handle or from anything with the Connect tool. `PrototypeSelectTool` checks, before it selects, whether a press is within 8 screen px of the single selection's right middle (`rightMiddle`), when that selection is on a screen; only then does it drag a link instead, so every other press selects as before. `ConnectTool` (L, crosshair; Connect follows Hand in the toolbar) drags one out of `targetAt(world, true)` (a screen's empty area gives the screen), on a screen; it hovers what a press would link from and never selects by itself. While dragging, the target is the screen of `elementAt(pointer)` unless it's the source's own. On release: a target adds `newInteraction(target)` (a click that navigates there); no element under the pointer, at least 24 screen px from the press, adds a `back` (`editInteraction(newInteraction(), { action: "back" })`); anything else (the source's own screen, a layer off every screen, a short drag) adds nothing. Either write is one `DESIGN_PROTOTYPE.addInteraction`, one undo step; the source is selected after. Esc (`cancel`, taken by the tool mid-drag) and a tool switch drop the drag without writing. `CONNECT_DRAG` (`ConnectDrag`, a service with an `Emitter`) holds the drag in world units (`state()`: `from`, `start` at the source's right middle, `at`, `target`) and what the last one added (`lastDrop()`, set by `end(drop)`). Its overlays: `ConnectHandle`, a 14 px square with a 2 px primary border on the single selection's right middle while the select tool is on (it takes no pointer: the tool does the hit test); `DragLine`, the curve from `start` to the pointer (`dragPath`, bends at least 30 px) and a dashed primary outline 3 px round the target screen, plus the toast on a drop (`useConnectToast`: "Linked “Start order” to Menu", "“Start order” now goes Back").
