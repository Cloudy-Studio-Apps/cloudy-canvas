# Data

Sources of data for a design: a file, a link or a sheet whose rows later fill the design's layers. This folder holds the source record; bindings and iterators build on it.

- **Tier:** core
- **Requires:** core, pages, frame; uses: text, image, auto-layout
- **Contributes:** kinds `DataSourceKind`; the service `DESIGN_DATA_SOURCES` (`engine.service(...)`); source types `file` and `http`; formats `csv` and `json` (also NDJSON)
- **Points it owns:** `dataSourceTypes` (where data comes from; built-ins and plugins), `dataFormats` (how raw data becomes rows). A source type's `icon` is a lucide icon name (a string), since engine code cannot import the UI icon type.
- **MCP tools:** none yet
- **Files:** `settings/` (declarative `SettingSpec`, `missingSettings`, `splitSecrets`), `services/` (`DataServices`, `RawData`, `SourceContext`), `table/` (`parsePath`, `readPath`, `normalizeRows`, `guessFields`: data paths such as `a.b[0].c`, parsed data into rows, and each field's guessed type; fields already known that the rows lack are kept after the found ones, so a partial refresh never wipes their settings), `formats/` (`CSV_FORMAT`, `JSON_FORMAT`, `detectFormat`: by extension, then mime, then `sniff`), `sources/` (`FILE_SOURCE`, `HTTP_SOURCE`; labels are getters so they follow the app language; header values come from `ctx.secrets["headers.<name>"]`), `data.points.ts`, `source/` (the `data-source` record: types, defaults, factory, kind), `update/` (`writeSnapshot`, `readSnapshot`, `updateSource`, the secret keys `secretStoreKey`/`secretKeys`/`loadSecrets`/`missingSecretKeys`), `model/` (`DESIGN_DATA_SOURCES` with `DesignDataSources`, its in-memory Update state `SourceUpdates`, secret writes, `sourceName`, `RESERVED_NAMES`), `data.i18n.ts` with `locales/`, `ui/`.

## How it works

- **The record** (`source/`): a `data-source` element (`DataSourceKind`) is a record, not a layer: never drawn or hit, `creatable = false`, `boxed = false`. It has a `name`, a `sourceType` (where the data comes from) with its `settings`, a `format` (`"auto"` or a format id) with `formatOptions`, the `fields` found in the data (`DataField`: `path`, `alias`, `type`, `format`, `hidden`), the last copy `snapshot` (`DataSnapshot`: an asset id, `updatedAt`, `rowCount`, `hash`; `null` until the data is fetched) and `images`, assets the data names. `assets(el)` lists the snapshot's asset and every image, so they stay in the file and copy with it; `fillDefaults` fills every field for older records.
- **No errors on the record**: a failed fetch is device-local and is kept in memory by a service, never written to the file.
- `createDataSource(index, { name, sourceType, settings, format? })` makes one; `isDataSource(el)` narrows.
- **The snapshot** (`update/snapshot.ts`): the parsed rows are saved as a document asset, `{ version: 1, rows }` as UTF-8 JSON, with a SHA-256 `hash` of those bytes. Assets are outside the undo history and never deleted, so undoing an Update just points the record back at the previous asset (and its fields). `readSnapshot` parses each asset once (cached by asset id: an asset never changes); a missing or broken asset reads as no rows.
- **Update** (`updateSource`): loads the source's secrets from the device, checks the required settings (`Missing: <keys>`), runs the source type's `update` (`fetching`), picks the format (`record.format`, or `detectFormat` for `"auto"`) and parses (`parsing`), turns the result into rows (`normalizeRows`), guesses the fields keeping the known ones (`guessFields`), and saves (`saving`): the new asset is added first, then **one** `checkpoint` and one `update` of `snapshot` and `fields`. When the hash matches the last snapshot no asset is added and only `updatedAt` changes (`changed: false`), unless this device lacks the old asset: then the new one is added and pointed at. Any failure writes nothing: the result is `ok: false` with the message and the previous snapshot stays.
- **The service** (`DESIGN_DATA_SOURCES`, `DesignDataSources`): the only place that makes, edits and updates sources, one undo step each (`checkpoint` first). The editor hands it the registered types and formats and the platform's `DataServices` with `setContext` (`null` when it closes); `create`, `setSettings`, `missingSecrets` and `update` throw "Data sources aren't ready: no editor is open." without one. `error(id)` is the last failed Update's message and `stage(id)` the running one's step, both in memory only (device state: another machine may have the key). `onChange` fires on record changes and on Update stages. One Update of a source runs at a time: a second `update` call while one runs shares the first run's result; `updateAll` runs them one after another. A cancelled Update (its signal aborted) returns `ok: false, aborted: true` and is not recorded in `error(id)`. Removing a source forgets its error and stage, and an Update still running for it records nothing.
- **Secrets**: `create` and `setSettings` take the raw form values and split them with the type's specs (`splitSecrets`): the file keeps only the safe settings (a secret pair keeps its names, values `""`), the device's `SecretStore` keeps the rest under `data-source:<sourceId>:<key>` (`key` for a secret setting, `key.name` for a secret pair's value). An empty (`""`) or left-out value keeps the stored one, since a form round-trip carries `""` for every secret it can't show; a secret setting given `null` is deleted, and a pair name that is gone has its value deleted; `remove` deletes every secret of the source. An empty stored value counts as missing: `missingSecrets(id)` lists the required secrets and secret pair values this device doesn't have, and Update checks the same (`missingSecretKeys`, with `missingSettings`) before fetching, failing with `Missing: …` instead of sending an empty header. Undo never brings secrets back: they live on the device, outside the document.
- **Names** (`sourceName`): a source's name is what bindings use, so it is a lower-case identifier (`[a-z_][a-z0-9_]*`; accents dropped, other characters become `_`, a leading digit gets `data_`), never one of `RESERVED_NAMES` (`page`, `pages`, `title`, `section`, `date`, `toc`, `item`: the brochure's own placeholders), and unique (`_2`, `_3`…). A new source is named from `type.defaultName(settings)` unless given a name; `rename` goes through the same rule.
