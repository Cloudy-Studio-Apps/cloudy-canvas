# Data

Sources of data for a design: a file, a link or a sheet whose rows later fill the design's layers. This folder holds the source record; bindings and iterators build on it.

- **Tier:** core
- **Requires:** core, pages, frame; uses: text, image, auto-layout
- **Contributes:** kinds `DataSourceKind`; the service `DESIGN_DATA_SOURCES` (`engine.service(...)`); source types `file` and `http`; formats `csv` and `json` (also NDJSON); designCanvas: `afterEdit` (`syncData`), `onRemove`; text: `textTemplates` (`BOUND_TEXT_TEMPLATE`); designEditor: `leftTabs` (the Data tab, order 25, after Assets; kept in the Catalog mode), `propertySections` (`data.bindings`, the Data section, order 85: after Effects, before Export; one layer selected; not kept in the Catalog mode's sidebar), `sessionHooks` (`data.services`)
- **Points it owns:** `dataSourceTypes` (where data comes from; built-ins and plugins), `dataFormats` (how raw data becomes rows), `dataSourceForms` (UI, `ui/data.points.ts`: a source type's own settings form, `{ type, component }` with `SourceFormProps`, keyed by the type's id). A source type's `icon` is a lucide icon name (a string), since engine code cannot import the UI icon type.
- **MCP tools** (`mcp/`, `data-sources.mcp.ts`, `designMcpTools` group `data`): `list_data_sources`, `get_data_source` (settings, fields, which secrets are set, which chosen files this device can find (`files[].onDevice`), sample rows; secret values are never returned; its description states the origin and file path rules below), `add_data_source` (updates right away unless `update: false`), `update_data_source` (`source` or `all`), `set_data_source` (name, settings merged, secrets, format, formatOptions, `fields` patched by path) and `remove_data_source`; and `bind_data` (`bind-data.mcp.ts`, made with the design's `kinds`, args read in `bind-data-args.ts`): `layer`, `text` (a template; the layer's style is kept: the same text keeps its runs, otherwise one run copies the first run's style when it spans the text), `bindings`, `visibleWhen`, `hideWhenEmpty` over `bindData` in one `asUndoStep`, returning the layer's data fields and `missing` (`planBindings`' output, resolved in the root scope). Everything is validated before writing (source id, type, format, setting keys against the type's specs, field paths and types, field formats: `decimals` a whole number 0–20, `currency` a 3-letter ISO code (upper-cased), `dateStyle` short, medium or long, the texts text; errors name the field, in `field-args.ts`). A field's alias is a label shown in pickers and the rows table: bindings use paths. The generic tools can't touch a record (`DataSourceKind.patchableFields` is empty, so `update_nodes` refuses it), and a record deleted with `delete_nodes` has its device secrets deleted by the module's `designCanvas.onRemove` (`forgetRemovedSources`). `set_data_source` joins its writes into one undo step with `holdCheckpoints` since `asUndoStep` is synchronous and secret writes await. An optional secret never set reads as `set: true` (`missingSecrets` ignores optional ones).
- **Files:** (bindings import `model` leaves, such as `../model/source-name`, never its index: `model/` imports `bindings/`, so the index would be a cycle) `mcp/` (the tools above, with `describe-source.ts`, `source-args.ts` and `field-args.ts`), `settings/` (declarative `SettingSpec`, a boolean with its `default` while unset, a `file` or `folder` holding a device path (`holdsDevicePath`); `missingSettings`, `splitSecrets`; `baseName`, `withoutExtension`, `isAbsolutePath`), `services/` (`DataServices`, `RawData`, `SourceContext`), `table/` (`parsePath`, `readPath`, `normalizeRows`, `guessFields`, `formatPath`/`joinKey`/`keyStep`/`normalizePath`: data paths such as `a.b[0].c`, a key that isn't a plain identifier (`/^[A-Za-z_$][\w$]*$/`: spaces, hyphens, accents, digits first) quoted as `a["unit price"]` with `\` and `"` escaped, so template tokens read every path; `guessFields` matches known fields and `set_data_source` field patches by `normalizePath`, so a record saved with the older bare form keeps its settings; parsed data into rows, and each field's guessed type; fields already known that the rows lack are kept after the found ones, so a partial refresh never wipes their settings), `formats/` (`CSV_FORMAT`, `JSON_FORMAT`, `detectFormat`: by extension, then mime, then `sniff`), `sources/` (`FILE_SOURCE`, `HTTP_SOURCE`; labels are getters so they follow the app language; header values come from `ctx.secrets["headers.<name>"]`, the file's path from `ctx.files.path`; default names drop the extension, `products.csv` → `products`), `data.points.ts`, `source/` (the `data-source` record: types, defaults, factory, kind, `dataSourcesIn(doc)`), `update/` (`writeSnapshot`, `readSnapshot`, `updateSource`, the secret keys `secretStoreKey`/`secretKeys`/`loadSecrets`/`loadSourceSecrets`/`missingSecretKeys`/`ORIGIN_KEY`, the file paths `filePathKey`/`loadFilePaths`/`requireFilePaths`/`deviceKeys`, `isWebPage`, `imageKey` (the key a source's `images` keeps a picture under), `downloadImages` with `isImageBytes`, `decodeImageData` and `imagePathIn` (see Images), and `UPDATE_ERRORS`/`answeredMessage`: the messages the tab translates), `model/` (`DESIGN_DATA_SOURCES` with `DesignDataSources`, its in-memory Update state `SourceUpdates`, the per-Y.Doc `sharedState`, secret writes, `forgetRemovedSources`, `sourceName`, `RESERVED_NAMES`), `bindings/` (the data fields a layer carries: `NodeDataFields` with `dataText`, `dataBindings`, `dataVisible`, `dataHideEmpty`, read defensively by `dataFieldsOf`/`hasDataFields`; and scopes: `rootScope(sources, rowsOf)` has each source by name as its rows array, `scopeAt(doc, nodeId)` (the scope a layer's expressions read: the root scope now, phase 3 adds the repeats around it), `childScope`, `lookup(scope, expr)` resolving the first step up the chain and the rest with a path read, `x.$count` on a list being its length, and `namesInScope` for pickers; `parseTokens` (`{expr}` tokens, quoted keys with escapes included, `{{` a literal `{`, catalog words like `{page}` left as text), `resolveRichTemplate` (fills tokens, remaps style runs: a token's output takes the style of the run holding its `{`), `formatValue` (never throws; the binding's format over the field's; an explicit `decimals` fixes the digits, `1299.5` with 2 → `1,299.50`, unset at most 2) `evaluateCondition` (unknown ops are false), `planBindings` (with `bindingWrite`/`writePatch`/`writtenFields`, one binding's write through its kind, `readValue`, `sameValue`, and `toNumber`/`toBoolean` in `coerce.ts`); a scope's `fields` are keyed by `fieldKey(steps)`, any index step written `[]`, so `products[3].price` finds `products[].price`; expressions are built from `PathStep[]` with `formatPath`, never by joining keys), `bindData` (the edit below), `dataBindableFields` (what the Data section offers), `CONDITION_OPS`/`opTakesValue`, `editTemplate` (a template's text replaced, its runs spliced as typing does)), `sync/` (`syncData`, `affectedData`, `droppedBindings`/`droppedVisibility`: see Bindings), `data.i18n.ts` with `locales/`, `ui/` (`hooks/`, `data-tab/`, `data-section/`, `source-icon.tsx`).

## How it works

- **The record** (`source/`): a `data-source` element (`DataSourceKind`) is a record, not a layer: never drawn or hit, `creatable = false`, `boxed = false`. It has a `name`, a `sourceType` (where the data comes from) with its `settings`, a `format` (`"auto"` or a format id) with `formatOptions`, the `fields` found in the data (`DataField`: `path`, `alias`, `type`, `format`, `hidden`), the last copy `snapshot` (`DataSnapshot`: an asset id, `updatedAt`, `rowCount`, `hash`; `null` until the data is fetched) and `images`, assets the data names. `assets(el)` lists the snapshot's asset and every image, so they stay in the file and copy with it; `fillDefaults` fills every field for older records.
- **No errors on the record**: a failed fetch is device-local and is kept in memory by a service, never written to the file.
- `createDataSource(index, { name, sourceType, settings, format?, formatOptions? })` makes one; `isDataSource(el)` narrows.
- **The snapshot** (`update/snapshot.ts`): the parsed rows are saved as a document asset, `{ version: 1, rows }` as UTF-8 JSON, with a SHA-256 `hash` of those bytes. Assets are outside the undo history and never deleted, so undoing an Update just points the record back at the previous asset (and its fields). `readSnapshot` parses each asset once (cached per Yjs doc, then by asset id: an asset never changes); the cached rows are frozen (the array and each row) and typed `readonly`, since every reader shares them; a missing or broken asset reads as no rows.
- **Update** (`updateSource`): loads the source's secrets from the device (none when they are bound to another origin, see Secrets), checks the required settings (`Missing: <keys>`), finds the chosen files' paths on this device (`requireFilePaths`: "Pick the file again on this device." without one, and a refusal for a path inside the app's data folder, `services.isPrivatePath`), runs the source type's `update` (`fetching`), fails with "The source answered a web page, not data." when the result is HTML (`isWebPage`: a `text/html` mime, or text starting with `<!doctype html` or `<html`), picks the format (`record.format`, or `detectFormat` for `"auto"`) and parses (`parsing`), turns the result into rows (`normalizeRows`), guesses the fields keeping the known ones (`guessFields`), saves the pictures the data names (`images`, see Images), and saves (`saving`): the new assets are added first, then **one** `checkpoint` and one `update` of `snapshot`, `fields` and `images` (only the ones that changed). When the hash matches the last snapshot no asset is added and only `updatedAt` changes (`changed: false`), unless this device lacks the old asset: then the new one is added and pointed at. Any failure writes nothing: the result is `ok: false` with the message and the previous snapshot stays.
- **The service** (`DESIGN_DATA_SOURCES`, `DesignDataSources`): the only place that makes, edits and updates sources, one undo step each (`checkpoint` first). The editor hands it the registered types and formats and the platform's `DataServices` with `setContext` (`null` when it closes); `create`, `setSettings`, `missingSecrets` and `update` throw "Data sources aren't ready: no editor is open." without one. `error(id)` is the last failed Update's message and `stage(id)` the running one's step, both in memory only (device state: another machine may have the key). `types()` and `formats()` give the registered ones (empty without a context). The context and the Update state are shared by every service on the same Yjs doc (`SharedState`), because an agent's workspace has its own service on a proxy of the document and must reach the editor's platform and see the Updates the tab runs. `onChange` fires on record changes and on Update stages. One Update of a source runs at a time: a second `update` call while one runs shares the first run's result; `updateAll` runs them one after another. A cancelled Update (its signal aborted) returns `ok: false, aborted: true` and is not recorded in `error(id)`. Removing a source forgets its error and stage, and an Update still running for it records nothing.
- **Secrets**: `create` and `setSettings` take the raw form values and split them with the type's specs (`splitSecrets`): the file keeps only the safe settings (a secret pair keeps its names, values `""`), the device's `SecretStore` keeps the rest under `data-source:<sourceId>:<key>` (`key` for a secret setting, `key.name` for a secret pair's value). An empty (`""`) or left-out value keeps the stored one, since a form round-trip carries `""` for every secret it can't show; a secret setting given `null` is deleted, and a pair name that is gone has its value deleted; `remove` deletes every secret of the source. An empty stored value counts as missing: `missingSecrets(id)` lists the required secrets and secret pair values this device doesn't have, and Update checks the same (`missingSecretKeys`, with `missingSettings`) before fetching, failing with `Missing: …` instead of sending an empty header. Undo never brings secrets back: they live on the device, outside the document.
- **Origins** (`DataSourceType.secretOrigin`, the link's URL origin): whenever secret values are written, the origin they were typed for is stored as `data-source:<id>:@origin`. `loadSourceSecrets` (Update, `missingSecrets`, the tab) gives none of them when the settings' origin isn't that one (or none is stored), so they read as missing (`Missing: …`, "Needs a key on this device") and are never sent elsewhere. Typing secrets again re-binds the origin to the current URL; when that moves, the stored secrets not typed again are deleted, so an old header never follows the link.
- **File paths**: a path is this device's, never the file's. A `file` (or `folder`, such as the file source's `imagesFolder`) setting given an absolute path keeps it as `data-source:<id>:@<key>` (`@path`) and only its base name in the settings; another name (or none) deletes the stored path. Only a path supplied in this call is saved: an absolute value equal to the record's (echoed from the document, or a legacy record) is reduced to its name, its stored path deleted, and never trusted. Update reads the device path (`ctx.files`); with none it fails with "Pick the file again on this device." and the file setting shows that line under the name (a folder without one doesn't fail the Update: its image files fail one by one, and the setting says "Pick the folder again on this device."). Paths inside the app data folder (where `secrets.json` is) are refused, by Update and by `platformDataServices.readFile` itself. `missingFiles(id)` lists the file and folder settings without a path here. A folder inside the app data folder fails the Update ("This folder is in the app's own data folder…"). `remove` and `forgetRemovedSources` delete every device key of a source (`deviceKeys`: secrets, `@origin`, file paths).
- **Names** (`sourceName`): a source's name is what bindings use, so it is a lower-case identifier (`[a-z_][a-z0-9_]*`; accents dropped, other characters become `_`, a leading digit gets `data_`), never one of `RESERVED_NAMES` (`page`, `pages`, `title`, `section`, `date`, `toc`, `item`: the brochure's own placeholders), and unique (`_2`, `_3`…). A new source is named from `type.defaultName(settings)` unless given a name; `rename` goes through the same rule.

## Images

- **Saving the data's pictures** (`downloadImages(rows, fields, known, { doc, services, folder, signal, onProgress })`, run by Update between parsing and saving, stage `images`): every value of an `image-url`, `image-base64` or `image-file` field, once per `imageKey`, not already in the record's `images` with an asset this device has, is fetched: a link (`http(s)` only) with `services.http.getBytes`, never with the source's secrets; a `data:` URL (base64 or percent-encoded) or bare base64 decoded (`decodeImageData`); a file name read with `services.readFile` inside the chosen folder only (`imagePathIn`: an absolute name, a drive or a `..` step is refused; subfolders are joined with the folder's separator; each resolved path is checked with `isPrivatePath` too). 4 run at a time, and `onProgress(done, total)` reports them. Bytes are kept only when their first bytes are a picture (`isImageBytes`: PNG, JPEG, GIF, WebP, or an SVG by the renderer's own `isSvg` from `@canvas`, so a saved picture always decodes) of at most `MAX_IMAGE_BYTES` (25 MB, checked after reading; base64 far over it isn't decoded); anything else, a failed download or a missing file is in `failed` with its reason (`ImageFailure`: `unreadable`, `notImage`, `tooLarge`, `overLimit`), never throws and never paints an empty fill (the binding keeps the current picture). At most `MAX_NEW_IMAGES` (2,000) new pictures per Update; the rest are failed too (`overLimit`), and the next Update takes the next ones. A cancel stops the downloads and adds nothing: the assets are added (`createId()`) after every picture is in, and nothing awaits between that and the record's update, which writes the merged `images` with the snapshot in one undo step.
- **Device state**: `UpdateResult.imagesFailed` (and `imagesOverLimit`) count them; `imagesTooLarge` the ones over 25 MB; the service keeps the last good Update's in memory (`imageFailures(id)` the values, `imageFailureDetails(id)` with reasons, `imagesOverLimit(id)`) and the running one's `progress(id)`. The folder (`imagesFolder` on the file source, the first `folder` setting of a type) is device-local like a file path (`@imagesFolder`).

## Bindings

- **Planning a layer** (`planBindings(el, scope, { kinds, locale, images })`, pure): its text from `dataText` (`resolveRichTemplate`, each token written with `formatValue` in `locale`; a token reading nothing, no such name or an `undefined` value (`readValue`), writes nothing and is listed in `missing`), laid out again with `alignedTextPatch` (the text module's: an auto-width text keeps its aligned edge, as the catalog's page items do). Each `dataBindings` entry is written the way its kind writes a variable's value (`bindingWrite`, `writePatch`): the path's `BindableField` in `kinds.kindOf(el).bindable(el)` says the type, the data value becomes that `ResolvedValue` (a number with `toNumber`, a color with `parseTokenColor` (`#rgb`…`#rrggbbaa`), a boolean with `toBoolean`, a string with `formatValue` and the binding's format) and `kind.bindPatch` writes it (an opacity clamped, a size through resize, a text's typography laid out again, a paint's alpha in its opacity), folded over the layer as `syncTokens` does. `fills.<i>.image`/`strokes.<i>.image` are data's own: `images(value)` becomes the paint's `assetId` (another paint becomes an image paint keeping its opacity and visibility). A path the kind doesn't offer, a value that doesn't fit, a picture not saved yet (`null`) or a binding reading nothing leaves the field alone. `visible` follows `dataVisible` (`evaluateCondition`); with `dataHideEmpty` a text whose template came out `empty`, or a layer whose image value is empty, is hidden (a filled image doesn't clear an empty text: any empty part hides it); without either, `visible` is the user's. Only fields that differ from the layer's are in the patch (`sameValue`: numbers within 1e-3, colors in either case, as variables compare), so the second pass writes nothing.
- **Language:** values are written in each client's app language (`getLocale()`), so two people in a live session may see `1,299.50` and `1.299,50`; brochure pages get the brochure's language in phase 4.
- **Editing a bound text** (`BOUND_TEXT_TEMPLATE` in `bindings/bound-text-template.ts`, contributed to the text module's `textTemplates`): a text with `dataText` (and no `catalogText`, which the catalog fills) opens in the editor on its template, shows what's typed while editing, and its commit writes only `dataText`; the sync then writes the resolved text. Writing only `dataText` unlinks nothing (no binding's path nor `visible` is in the edit's `before`).
- **Hand edits unlink**, as variables do (`droppedBindings`, `droppedVisibility` in `sync/hand-edits.ts`): a bound field the edit wrote (its root in the edit's `before`) with anything but what its data gives (`writtenFields`, the kind's `bindValues`) loses its binding and keeps what was written; the sync's own writes hold the data's value, so they never unlink. Writing `visible` by hand (the eye) on a layer the data would set back drops `dataVisible` (to `null`) and `dataHideEmpty` (to `false`), and the choice stays. An edit that also changed a source (`affectedData`'s `all`) unlinks nothing: the sync owns it.
- **The sync** (`syncData(doc, change, kinds)`, the module's `designCanvas.afterEdit`, so inside each edit's undo step): `affectedData` says what to fill. `all` when a source record was added or removed, or its `name`, `fields`, `images` or data changed, compared from the edit's `before` (the changed fields' earlier values) against the record now: an Update that found the same data moves only `snapshot.updatedAt` (and writes equal fields again), and a settings change needs an Update to matter, so neither refills anything. Otherwise the changed layers that carry data fields. It builds the root scope once per run (`dataSourcesIn` and `readSnapshot`, the same rows `DESIGN_DATA_SOURCES.rows` gives; the rows are frozen and never written), merges every source's `images` into one lookup by `imageKey` (a URL or file name as it is, base64 as `"b64:"` + a 64-bit FNV-1a hash of the whole text + `:` + its length; keys saved by older files don't match and are downloaded again), leaving out pictures this device lacks the asset of, so their layers keep the current picture, unlinks hand edits, plans each layer (with `all`, one pass over the document) in the app's language (`getLocale()`), and writes the patches with one `updateMany`. Its writes run it again with the layers it changed, whose plans now differ in nothing, so it ends. Layers with a catalog template (`catalogText`) are skipped: the catalog fills them.
- **Binding a layer** (`bindData(doc, id, patch, kinds?)`, `bindings/bind-data.ts`): the one edit the Data section and agents share. `patch` (`BindDataPatch`) may set `text` (a text's template; `null` stops it and the text keeps what it shows), `bindings` (by field path; `null` unbinds one, keeping its value), `visible` (the show condition, `null` removes it) and `hideWhenEmpty`; what's left out stays. Everything is checked before writing, with English errors naming the bad path: the layer exists and is a design node, a template only on a text and each of its tokens a data path (`parseTokens`, `parsePath`), each binding key a field path and its `path` an expression starting with a name, an image key's paint present, a binding's `format` checked as a field's is (`readFieldFormat`, `source/read-field-format.ts`, shared with `set_data_source`; the currency upper-cased), the template's runs `{ start, end, style }` sorted, apart and inside its text, no template on a text with a catalog template (`isCatalogText`, the one check `syncData`, `BOUND_TEXT_TEMPLATE` and the section use), with `kinds` each key a field the kind offers (`bindable`, not a style, or `dataBindableFields`) and the data's type (`dataTypeOf`: the field's, `integer` for a row count, unknown when the source doesn't list it) one `acceptedTypes` allows for it (the Data section's table: colors `color`, numbers `integer`/`number`/`currency`, pictures the image types, anything for a boolean or a text), a condition's op one of `CONDITION_OPS` and its value a text or a number, and `hideWhenEmpty` a boolean. The checks are in `bind-data-checks.ts`. One field has one binding: binding a field (or a text's template) removes the variable binding of that field (`el.bindings`, any path overlapping it, so a `fills` style goes too; for a picture, the paint's), in the same write. When the edit leaves neither `dataVisible` nor `dataHideEmpty` on a layer that had one, a layer the data hid is shown again. One `checkpoint` and one `update`; the sync (an `afterEdit`) fills the layer in the same undo step.
- **Renaming a source** (`DesignDataSources.rename`, one undo step with `doc.batch`): `renameReferences(doc, from, to)` (`bindings/rename-references.ts`) parses and rewrites, never text-replaces, the first name of every `dataText` token (`rename-template.ts`: only the changed tokens are rebuilt, with `formatPath`; the runs move with their text, a run touching a token covers the whole renamed one), `dataBindings[*].path` and `dataVisible.path`, in one `updateMany`. It runs in the same transaction as the name change, which `affectedData` reads as a source change (`all`), so the rewrite unlinks nothing. When repeats arrive (phase 3), an iterator's `as` name shadows sources: expressions whose first name is a nearer row name must be skipped, and `repeat.source` is renamed too.

## The Data section (`ui/data-section/`)

- `DataSection` (the `data.bindings` property section, one layer selected): without sources it says to add one in the Data tab and shows only what is bound (the template's switch, bound fields, a set condition or "Hide when empty"), so each can still be turned off. Otherwise, for a text (not one with a catalog template, `catalogText`: the catalog fills it), "Text from data" (`TextDataBlock`, a `SwitchField`: on starts the template from the text it shows, with its runs; off stops it) and `TextTemplateField` (the template in a text area, line breaks kept, `useCommitField` with `commitOn: "mod-enter"`: blur or Ctrl/⌘+Enter commit, Escape reverts; a commit goes through `editTemplate`, so the style runs follow the typed change; the braces button's `FieldPicker` inserts `{expr}` where the caret was, `onSelect` keeping it, and commits, and its `onCloseAutoFocus` puts the focus back in the text area right after the token instead of on the button). Switching it on starts the template from the text as it is, so any `{word}` already in it becomes a field; the field's hint says so. Then **Fields** (`DataFieldsBlock`): one `BindFieldRow` per `dataBindableFields(node, kinds)`, then one per other bound key (an agent's, a fill since removed) so it can be unbound (colors take `color` fields; numbers `integer`, `number`, `currency`, and a source's row count; each fill's picture the image types), its `FieldPicker` offering only the fitting names, × unbinds. **Show when** (`ShowWhenBlock`): `ConditionField` (a field, the op `SelectField`, the value a `CommitInput` for the comparing ops) and "Hide when empty". Every change is `useBindData` (`bindData` with the engine's kinds; a refusal is `notifyError`ed).
- `FieldPicker` (exported from `ui/index.ts`): a dropdown of `pickerNames(scopeAt(doc, node))`, from `namesInScope`, hidden fields left out, grouped under their source, each by its alias (else the expression) with the first row's value; picking hands the expression exactly as `namesInScope` wrote it (quoted keys kept).

## The Data tab (`ui/`)

- **Platform** (`ui/hooks/data-services.ts`): `platformDataServices` is this device's `DataServices` (`@platform`'s `http`, `readLocalFile` (refusing the app data folder), `secretStore`, `isPrivatePath` over `isAppDataPath`, and `pickFile` over `openFile`, which gives the path, and `pickFolder`). `useDataServices`, the module's session hook, hands it with the registered types and formats (`useDataRegistry`, read once from the host's points) to the service with `setContext` in a layout effect, so it is set before any panel's effect, and `null` when the editor closes.
- **Images:** Update's stage line reads "Saving images… 12 of 40" (`stageText` with `progress`); the row and the Fields section show how many pictures the last Update couldn't save (`ImageFailuresLine`, saying when some were past the limit, and why the others failed: `failureReasons`, "2 are over 25 MB · 1 isn't a picture"), and an image field whose pictures aren't saved yet (its type just changed to an image type, say) says "Update to download its images" (`hasUnsavedImages`). The folder setting is a `FileField` that picks a folder (`DataServices.pickFolder`, `@platform`'s `pickFolder`).
- **Hooks:** `useDataSources()` is `list()`, re-rendered on `onChange` (`useDataVersion`). `useUpdateSource(id)` gives `{ run, stage, cancel, cancellable }`: Updates the tab starts (`ui/hooks/run-update.ts`) keep their `AbortController` by service and source, and the Update all loop its own with its running flag (`useUpdatingAll`), so the row, the detail and the header share them, also after leaving the list and coming back (a second Update all while one runs does nothing); a failed Update is `notifyError`ed, a cancelled one isn't. Update all runs the sources one after another and one cancel stops the rest. An Update an agent started shows its stage but can't be cancelled from the tab. `useSourceSecrets(source)` reads which of the source's secrets (origin-checked, `loadSourceSecrets`) and file paths (`@key`) this device holds, and `missingSecretKeys`, whenever its settings change and on every `onChange` of the service (an agent's secret write, an Update).
- **List** (`DataTab`, `SourceList`, `SourceRow`): the type's icon (`SourceIcon` maps a type's lucide icon name, an unknown one gets the database icon), the name, "N rows · updated 3 days ago" (`relativeTime` in the app's language) or the stage while it runs, the last error in the destructive color (`errorText`: the known engine messages, `UPDATE_ERRORS` and a link's `<url> answered <status>.`, are translated, others shown as they are; failure toasts go through `translatedError` too), "Needs a key on this device" when secrets are missing, and Update (a spinner while it runs; a click then cancels). The header has Update all and "+" (`AddSourceMenu`, one item per type).
- **Add** (`SourceDetail` with no source, `CreateSourceForm`): the type's form (its `dataSourceForms` entry, else `SettingsForm` from its `settings`) and the format; picking a file proposes the format from its extension (`detectFormat`). "Create and update" creates the source with its format and options (one undo step, `DataSourceInit.formatOptions`), opens its detail and runs Update. A typed key says "Will be saved on this device".
- **Detail** (`SourceDetail` header: back, the name, renamed with a double-click through the layers module's `LayerName`, and Update; `SourceSections`): settings (each committed change is `setSettings`, one undo step; secret inputs are empty, say "Saved on this device" when the device has the value and send `""` unless something was typed, × forgets a secret setting), a picked file switches an explicit format to the one its extension says, while "Automatic" stays automatic; the format (`FormatSelect`: "Automatic" or a format, then its options), the fields (`FieldList`, `FieldRow`: path, name (alias), type, hidden, row 0's value; each change one `setFields`), the first 200 rows (`RowsTable`, the visible fields as columns) and Remove source (`RemoveSourceButton`, after a dialog: undo brings the source back, not its secrets). A source that goes away (undo, an agent) brings the list back.
