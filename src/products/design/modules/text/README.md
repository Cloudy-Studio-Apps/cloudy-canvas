# Text

Text layers (T) with mixed styles in one text, the Typography section and its font picker, text styles and outlines for export.

- **Tier:** core
- **Requires:** core
- **Contributes:** kinds `TextKind`; designCanvas: `afterEdit`, `kinds`, `options`, `tools`; designEditor: `propertySections`, `sessionHooks`, `tools`; `designMcpTools`, `designStyleTypes`
- **Points it owns:** `textTemplates` (`text.points.ts`, `TextTemplateSource`: `claims`, `read`, `write`, keyed by id): templates a text is edited through instead of its shown text (data contributes `dataText`'s).
- **MCP tools:** `text_fonts_list`, `text_range_style`
- **Files:** `text.kind.ts`, `text.points.ts`, `text-template.ts`, `text-layout.ts`, `text-spans.ts`, `text-style.ts`, `run-style-bindings.ts`, `text-outline.ts`, `text.mcp.ts`, `ui/` (Typography, font picker, text styles).

## How it works

### Mixed text

- **Mixed text** (`text/`): a text's `runs` (`TextNodeRun`: a `TextRunStyle` of typography, `fills`, `textDecoration` over the text's own) and `textDecoration` are drawn, sized and outlined through one layout (`textLayout`, cached; `textSpans` resolves each stretch's style, `textFrame` where it wraps), so the editor's caret, the drawing and `textOutline` (each fragment shaped in its run's face at its place; decorations included) agree. `TEXT_RICH` is its `RichTextSpec` (`textContentPatch`, Ctrl+B/I/U toggles); `alignedTextPatch(el, text, runs)` is `textContentPatch` for writes from outside the editor (filled templates: the catalog's page items, data bindings), an auto-width text keeping its aligned edge where it was; `text.set` moves runs with the change. The Typography section reads and writes a `TypographyTarget` (`useTypographyTarget`: the selected characters while editing, with a color field, `rangeStyleValue`; otherwise whole texts, clearing the field from their runs, `textStyleValue`) and has underline/strikethrough buttons. Agents: `runs` and `textDecoration` in `nodes_create`/`nodes_update` (`text-run-args.ts`: a new `text` moves the runs, a whole-text field clears them), `text_range_style`. The Figma import maps `characterStyleIDs` + `styleOverrideTable` (`fig-text-runs.ts`; `withFigStyles` applies the entries' own styles) and decorations (`fig-typography.ts`).

### Text

- **Text** (`text/`): `TextKind` (`text`, `fontFamily` (a family name), `fontSize`, `fontWeight`, `fontStyle`, `lineHeight`, `letterSpacing`, `textAlign`, `verticalAlign`, `autoResize`: `width`/`height`/`none`); one visible solid fill is its color; other fills (gradients, images, several paints) show through its glyphs (`setPaintTextMask`; `strokable` is off), its layer is named after its first line (`layerName`) until renamed, and `textSize`/`retypeset` lay it out again after any change (resizing a side fixes the width, the height the size). `TextTool` (T): click for auto width, drag for a fixed width, click a text to edit it. The Typography section has `FontPicker` (`useFontFamilies`, a searchable list of installed and Google families), the face, size, line height, letter spacing, alignment and resizing; its changes become the `textTypography` tool option new texts use.

### Editing through a template

- **Templates** (`textTemplates`): a text some entry `claims` (the first one, in module order) is edited as that template, not as the text it shows (a text bound to data opens on `{product.name}`). The kind gets the point's entries from the module host (`new TextKind(outliner, () => host.get(textTemplates))`). Only the editor sees the template: its open (`text.get`, `TEXT_RICH`'s `runs`) reads `read(el)`, its live preview (`apply`, unchanged) shows what's typed, and its commit (`RichTextSpec.commit`, `templateCommit`) writes only the entry's `write` (nothing when the template is unchanged), never `text`/`runs`; the owner writes the shown text after (data's sync). Callers checked: the kind's `text.get` and the rich spec's `runs`/`apply`/`layout`/`shortcut` are called only by `canvas/text/text-editor.ts` and `rich-editor/rich-text-session.ts`; `text.set` is also the variables' write of `text` (`bindPatch`), so it stays on the shown text (design texts are always rich, so the editor never calls it); `textContentPatch` is also `alignedTextPatch` (catalog, data sync) and `text_range_style`. Drawing, export, layout, outlines, layer names, search and agents read `el.text`/`el.runs` directly. A text nothing claims is edited exactly as before (`commit` is `textContentPatch`, as `apply`). Writes of the shown `runs` from outside the editor (Typography on the whole text, `bindPatch` for a range's text style, `syncRunStyleBindings`) stay on the shown runs: the template's owner carries them into its template (data's sync does, see the data README's "Run styles of a bound text" for why that, not a run-mapping hook here). `text_range_style` (`textTools(templates)`) refuses a range that isn't the whole text on a claimed text: "style a bound text's ranges while editing its template".

### Text outlines

- **Text outlines:** `TextKind(outliner)`'s geometry is its glyphs (`textOutline`: its lines wrapped as drawn, aligned, on their baselines, letter-spaced, then `normalizePath`), from a `GlyphOutliner` (`shared/core/fonts`; `glyphOutliner` in `@platform`: HarfBuzz, `harfbuzzjs`, loaded the first time text is outlined, excluded from Vite's pre-bundling; each face read once from `FontLibrary.fontData`: an installed face's file from the Rust `system_font_data` command, a Google face as TTF fetched with an old user agent and cached as `face.ttf`). Until a face is read the text has no shape; `useTextOutlines` then calls `engine.refreshElements` on its texts, so booleans and masks made of them update.
