# Pages (Design module)

_How it works. The rules are in the root [CLAUDE.md](../../../../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

## Pages

- **Pages** (`modules/pages/`): a page is a `page` element (`PageKind`: a record, never drawn or hit; its `index` orders the pages) and every node has `pageId`. A page with `hidden: true` belongs to a feature (the design system's): `pagesOf` leaves it out (`allPagesOf` lists it last), and `PAGE_SCOPES` lists it as a background scope. `PAGE_SCOPES` is the design's `scopes`, so one page is on screen at a time and new nodes land on it (`createNodeBase` leaves `pageId` empty; `prepareTreeCopies` clears it so pastes go to the page on screen). `DESIGN_PAGES` (`DesignPages`) reads and edits them, one undo step each: `add(after, name?)` ("Page N"), `rename`, `duplicate` (the page and its nodes, `cloneElements`), `remove` (with its nodes; never the last page), `reorder(id, position)` and `moveNodes(ids, pageId)` (with descendants, on top, parents left behind become the top of the page). `ensurePages` (a `designMigrations` entry, also run on new designs by `newDesignDocument`) gives a design without pages "Page 1" and puts unplaced nodes on it. `DESIGN_TREE.layers(page)` reads one page's tree. UI (`modules/pages/ui/`): `PagesSection` at the bottom of the Layers tab (click shows a page, double-click renames, ⋯ renames, duplicates and deletes, rows drag to reorder, "+" adds one after the current), the Page section (its name, zoom), "Move to page" in the selection's context menu (a `ContextMenuSubmenu`: `canvas-ui` context menu items can be submenus of actions), and the `previousPage`/`nextPage` host commands (PageUp/PageDown, in the main menu). Agent tools: `list_pages`, `switch_page`, `create_page`, `rename_page`, `duplicate_page`, `delete_page`, `reorder_page`, `move_nodes_to_page`; every other tool works on the page on screen (`get_design` reports `currentPage`). Each page keeps its ruler guides (`PageElement.guides`, `PAGE_GUIDES` is the design's `guides`; duplicated with the page, frames' guides following their copies; a deleted frame's are dropped by `pruneFrameGuides`, an `onRemove`; kept from Figma pages by `figPageGuides`); the core module's `toggleRulers` (Shift+R), `toggleGuides` (Shift+;) and `clearGuides` host commands (`useViewCommands`, remembered in `ui/stores/design-view-store.ts`) are checkbox items of the main menu (`MainMenuItem.checked`), "Snap to guides" is in the `ZoomMenu`, and agents use `list_guides`, `add_guides` (with an optional `frame`) and `remove_guides` (`mcp/guides.mcp.ts`; `get_design` counts them).
