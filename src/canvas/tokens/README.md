# Variables (engine)

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

## Variables

- **Variables** (`canvas/tokens/`, plain TS, Figma's variables): the document's `"tokens"` Y.Map holds `TokenRecord`s by id (`ModeAxisRecord`: the file's **mode axes** (Theme: Light/Dark; axes combine), `modes` with the first the base, `current` the mode the file shows (the global switch, `setCurrentMode`); `CollectionRecord`: a folder of variables (`name`, `order`; older files' collection `modes` become axes when they open, `migrateCollectionModes`, the variables module's `variable-modes` migration renaming layers' `variableModes` keys); `VariableRecord`: `collectionId`, `name` a slash path (its groups), `type` `color` (`#RRGGBBAA`, `token-color.ts`), `number`, `string` or `boolean` (`defaultValueOf`), `values` with its default at `DEFAULT_VALUE` and, with `axisId` (the axis it varies by), optional overrides by mode id (the base mode is the default: `valueKeyOf`; `hasOverrides`); a value is raw or `{ alias }` of a variable of the same type, `scopes` (`TokenScope`, where pickers offer it; empty: everywhere), `description`, `codeSyntax`, `hidden`; `StyleRecord`: a named look, see the design's styles; its `bindings` (a path in its `value` → variable id, `DocumentTokens.bindStyleField`) are resolved in each layer's modes by `resolveStyle`, the `BindingIndex` following variable → style (`TokenStore.styleUsers`) → layer; `updateStyle` unlinks the paths a new value overwrote unless given `bindings` (a stack reordered), deleting a variable bakes its value into the styles using it, `stylesWithout`), validated on read (`isTokenRecord`), undoable and synced like elements (`doc.tokenRecords`, `setTokenRecords`, `removeTokenRecords`, `observeTokens`, `tokensVersion`). `TokenStore.of(doc)` is the read model (cached per version: sorted lists, `find(ref)` by id, `Collection/path` or a unique path, `aliasDependents`); `resolveVariable(store, id, modes)` follows aliases, each by its own axis (`valueIn`: the override for the axis's mode, else the default; `modeFor`: the `ModeContext`'s pick (axis id → mode id), else the axis's `current`, else its base; `null` for a loop, a broken chain or a wrong type); `groupTree` turns paths into accordion groups. `DOCUMENT_TOKENS` (`DocumentTokens`, a service, so agents' workspaces edit as themselves) is the only place that edits them, one undo step each (collections, axes and their modes (`createAxis`, `addMode(null)` makes the file's first axis), variables (`setValue(id, mode)`: a mode of another axis makes it vary by that one when it has no overrides, `clearValue`, `setVariableAxis`), `setValue` refusing loops, `renameGroup`, `moveVariables`, `deleteVariables` detaching every use, `usage`). **Bindings:** an element's `bindings` maps field paths (`"fills.0.color"`, `"layout.padding.top"`) to variable ids while its fields keep the resolved values, so everything else reads fields as before; `variableModes` (pages, containers, keyed by axis) picks modes over the file's. Kinds list what can be bound (`kind.bindable(el)`: `BindableField` path, type (`style` with a `styleType` for styles), scopes, label; a binding stays while its kind still offers the path, `bindsPath`, so style paths that aren't fields (`textStyle`) survive; binding a path replaces bindings over or under it, `pathsOverlap`) and write it (`bindValues` — leaf paths → values (`tokenValueFields`), a color also sets its paint's `opacity` from the alpha — and `bindPatch`, overridden where a field has consequences: `w`/`h` resize, a text lays out again). `syncTokens(doc, change, kinds, context)` (an `afterEdit` hook a product's module contributes with its `TokenContext`: `modesOf`, `modeDependents`) first unlinks a bound field the edit wrote with anything but its variable's value (a drag, the Scale tool, an agent's `update_nodes`: the detach rule; sync-written values never detach), then resolves the bindings of the elements the edit touched, those bound to a changed variable or style, an alias of one, or a variable varying by a changed axis (`BindingIndex`, from the stored `bindings` fields), and those whose modes changed; unresolvable variables leave fields alone, bindings whose field is gone are dropped. Stack edits remap paths (`remapStackBindings`, `withoutBindingsUnder`); Copy properties carries the bindings of the copied fields (`pastedBindings`); the clipboard carries the variables copied elements use with their alias targets and collections (`clipboardTokens`, `restoreTokens` keeps the target file's own). Shared UI in `canvas-ui/tokens/`: `useDocumentTokens`, `VariablePicker` (search, type and scope filter, collections and group accordions), `VariableChip` (a bound field: pick another, detach), `TokenGroupAccordion`, `TokenSwatch`, `VariableValue`.
