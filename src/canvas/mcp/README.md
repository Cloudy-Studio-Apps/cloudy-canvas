# MCP helpers

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md)._

## Agent helpers

- **MCP helpers** (`canvas/mcp/`): `McpTool<H>` (generic over what the tool can reach), argument parsers (`tool-args.ts`), `asUndoStep(doc, edit)`, and `buildElement` / `elementPatch` / `summarizeElement`, which go through the kinds. Products assemble their MCP tools from these.
- **App tools** (`tabs.mcp.ts`, `files.mcp.ts`, `plugins.mcp.ts`; groups with `prefix`es `tabs`, `file`, `plugins`, whose tools need no open file, `scope: "app"`): `tabs_list`, `tabs_switch` on `TabsAgentHost`; `file_recent_list`, `file_open`, `file_new` and `plugins_list` on `FilesAgentHost` (`files.mcp.types.ts`, with `AgentFileOpened` and `AgentPlugin`), one tool for both products (`type` picks the product; required for `file_new`). They share: `AgentFileRef`, `AgentNewFile`, the `AgentFileCandidates`/`AgentProjectChoice` answers, the name rules (`sameFileName`, `projectNameMatches`) and their argument parsers. The app implements the host (`app/mcp/`).

## Tool names

- **Full names** (`mcp-tool-name.ts`): a tool's `name` is local; the server lists it as `mcpToolName(prefix, local)`, `<prefix>_<local>`. `checkMcpToolName(name)` returns why a full name can't be served (not matching `^[a-z0-9][a-z0-9_-]*$`, or longer than `MCP_TOOL_NAME_MAX`, 44, since agent apps add their own prefix), else `null`. `McpTool.scope` is `"app"` for a tool that needs no open file (`"file"` by default).
- **The prefix** (`mcpPrefixFor(group, owner, reserved)`, `mcp-prefix.ts`): the owner (`McpToolOwner`: module id, its `tier`, its plugin id; `mcpToolOwner(modules, point, groupId, pluginOf)` reads it with `ModuleHost.ownerOf`/`tierOf`) decides it. A plugin's tools take its plugin id, and are refused when its group declares a `prefix` or the id is in `reserved` (`The plugin id "<id>" is a built-in prefix.`). A built-in group's tools take its declared topic (`McpToolGroup.prefix`) if any, else its module id; only core modules may declare one, and a feature module that does throws, naming it. The board's and the design's `core` modules declare the shared topics (`file`, `selection`, `history`, `view`, `clipboard`, `arrange`, `style`; a core module may declare a reserved app topic such as `file`, since reserving only blocks plugins, and its `file_get`, `file_info_set`, `file_save` never share a name with the app's `file_recent_list`, `file_open`, `file_new`) and, for their element tools, `board`/`design` for now. `builtInPrefixes(modules, point)` is one product's reserved set: the id of every built-in module (`ModuleHost.moduleIds()` with a tier, whether or not it adds tools) and the topics declared on the point (the app joins both products' and adds `tabs`).
- **Collecting** (`collectMcpTools(groups, context, ownerOf, reserved)`): one product's tools as `CollectedMcpTool`s (full name, tool, module id, plugin id) in group order, plus the plugins' `RefusedMcpTool`s (full name, plugin id, reason). An invalid name or one an earlier tool took throws for a built-in (`The module "<a>" adds an MCP tool that can't be served: "<name>" is the name of a tool of the module "<b>".`) and refuses a plugin's tool (e.g. `"<name>" is longer than 44 characters.`); a refused plugin never throws. The app tools are groups too; the app collects them with `collectMcpTools` (`app/mcp/app-tools.ts`). `sameSchema(a, b)` (`same-schema.ts`) compares two JSON schemas (keys in any order, arrays in order); the app uses it to accept the same tool name in both products as one shared tool.
- **Shared tools** (`shared/`, see its [README](shared/README.md)): a tool both products serve under one full name is one listed tool, so its `inputSchema` must be the same in both (`sameSchema`, or the server throws when it starts). Its local name, its one description and its schema are one `SharedToolSpec` constant both products spread before their own `run`: `FILE_GET_TOOL`, `FILE_INFO_SET_TOOL`, `FILE_SAVE_TOOL`, `SELECTION_GET_TOOL`, `SELECTION_SET_TOOL`, `HISTORY_UNDO_TOOL`, `HISTORY_REDO_TOOL`, `VIEW_FIT_TOOL`, `VIEW_FIT_ELEMENTS_TOOL`, `VIEW_SNAPSHOT_TOOL` (with `VIEW_SNAPSHOT_MAX_SIDE`), `CLIPBOARD_PNG_COPY_TOOL`, `STICKER_STAMP_TOOL`; the 3D model ones are in `canvas/model3d/mcp/`. The factories build whole tools for both instead: `arrangeTools(options)` (`arrange.mcp.ts`: `align`, `distribute`, `tidy_up` and `scale.mcp.ts`'s `scale`) and `copyPropertiesTool(options)` (`style.mcp.ts`: `copy`), given only `resolve` (`ArrangeToolsOptions`), with descriptions that say "elements". The schema is the union of both products' arguments: one only a product honors says "Boards only." or "Designs only." and the other ignores it.
