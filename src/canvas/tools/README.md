# Tools and modes

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md)._

## Tools

- **Tools** implement `Tool` (`tools/tool.types.ts`, `id: string`) and act only through `ToolContext`, never through the engine directly. Select and hand are built in (`createBaseTools`); a product adds its own in `createTools`. A tool previews an element it's creating with `ctx.setDraft(el)`: the draft layer draws it with its kind, like any element. Other gesture feedback (a line being dragged, a drop target) is a `Guide` set with `ctx.setGuide(fn)`, drawn above the elements. `ctx.setFaded(ids)` dims elements a gesture is about to remove (the eraser); switching tools clears it. **Modes** (`canvas/modes/`): a product's modules register `CanvasMode`s (the `modes` point, keyed by id; `CanvasProduct.modes`) besides `DEFAULT_MODE` (`default`: every tool): `tool` (it starts with, and Esc goes back to), `tools` (the others that work in it; `setTool` ignores the rest, shortcuts included, `modeAllows`) and `isolate(el)` (only what it accepts can be hit, selected, marqueed or Ctrl+A'd: `Scene.isolation`, `Scene.reachable(el)`, which every locked check goes through; the rest is dimmed, the engine's `applyFaded` merging it with `setFaded`, again on each scene refresh, and leaves the selection), `faded(context)` (a `ModeFadeContext`: the scene's elements, the document, the active tool and the scope on screen; what it dims instead of what `isolate` leaves out, worked out again on each scene refresh and tool switch: the Catalog's unprinted frames), `commands` (the only engine commands that run while it's on besides its keybindings' and `tool.<id>`: `modeAllowsCommand`, `engine.allowsCommand(id)`, checked by `createCommands` after `toolTakes`; the context menu hides what isn't allowed, `allowedGroups`, a submenu of actions counting by its id, and the design's main menu shows it disabled). `keybindings` (shortcuts that exist only while it's on: the `Keymap`'s layer, `keymap.setLayer`, matched and labelled first; their commands are host commands without keys of their own). `engine.setMode(id)`, `engine.modeId`, `EngineState.mode`, `ctx.getMode()`/`ctx.setMode(id)` (and `ctx.getScope()`); Esc drops the part, then the selection, then goes back to the mode's tool, then leaves the mode. `SelectTool` is exported so tools can build on it (`ScaleTool`; `movesSelection: false` keeps what it selects in place and `ResizeMode` `none` shows no handles or rotate zones, the Catalog's tool); `Tool.editsOnDoubleClick` (the select tool's, not the Scale tool's) is what lets double-click enter groups, call `editElement` and edit text. `ctx.animateIn(ids)` plays a quick pop on elements a tool just added (`render/entrance.ts`; the element layers advance it each frame and the engine keeps requesting frames while it plays; skipped with reduced motion). `engine.animateMoves(offsets)` has elements an edit just moved glide there from where they were (`render/move-glide.ts`, `ElementView.setGlide`, advanced with the entrances by drawn frames, at most `MOVE_GLIDE.maxStepMs` each, so a busy moment slows the glide instead of skipping it; the Catalog's arrange).
