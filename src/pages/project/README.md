# Project page

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md); the model is in
[shared/core/projects/](../../shared/core/projects/README.md), the Projects page in
[pages/projects](../projects/README.md)._

- **`/project/:id[?folder=<rel>|tab=libraries&library=<id>|tab=content&kind=<kind>|tab=trash]` (`project-page.tsx`):** a project's home. It reads the project with `useProject(id)` (the registry record, the manifest and `manifestFile`, the `.cproject` it was read from through `readManifestFile`, `saveManifest(patch)` which rewrites that file atomically and refreshes the registry, and `renameProject`, which renames the manifest's name and that file to `<name>.cproject`, never the folder) and shows a message while loading, when the id isn't on this device's list, or when the folder is missing (with Locate…). A ready project is `ProjectHome`. The route redirects Home where projects don't exist (Android, the browser build). `?folder=` is the folder open in the Files tab (a path relative to the project, `/`-separated).
- **`ProjectHome` (`project-home.tsx`):** builds the `ProjectContext` (`project-context.ts`: the record, manifest, open folder, `scanRev`, in-place rename and Move to… state, the row drag, the actions and the recent files) and lays out the sidebar and, in the scrolling main column, `ProjectHeader` with the tab's content. Everything below reads the context with `useProjectContext()`. `bump()` makes every scan read again after files moved.
- **`components/`:** the header (`ProjectHeader`: `ProjectCover` with Change cover, the mark, name, facts, Pin, `ProjectMoreMenu`, `NewMenu`, `ProjectTabs`), the project's menu (rename, icon and color through `RenameProjectDialog` / `AppearanceDialog`, show in folder, export as .zip with `export-project-zip.ts`, which packs the `.cproject` that was read, remove from list), the sidebar (`ProjectSidebar`, `FolderTree` / `FolderTreeNode` with `FolderColorButton`, and Trash), `MoveDialog` with `FolderPicker`, and `TrashRow`.
- **`files/`:** the Files tab (`FilesTab`): `RecentlyEdited` (the 3 newest files of the project from the recent files), `PathBar`, `FilesToolbar` (search names in the open folder and below with `use-folder-search.ts`, sort, grid or list), `FolderTile` (three previews, count, `NewFolderTile`) and `ProjectFileCard`. Menus come from `entryActions`; `InlineName` turns a name into a `CommitInput` while it is being renamed.
- **Data:** `useFolderScan(root, rel, rev)` reads one level of a folder (folders, boards and designs). `useProjectRecents` pairs files with their recent-files entries (by path) for previews, or builds a stand-in for a file never opened. The previews, kinds and menus come from `@pages/shared/files`, the project mark and images from `@pages/shared/projects` (see [shared/files](../shared/files/README.md) and [shared/projects](../shared/projects/README.md)).
- **Add existing file…** (New ▾): `chooseExistingFile` picks a board or design (one in a project already is refused with a toast) and the Add to project dialog of [shared/add-to-project](../shared/add-to-project/README.md) opens with this project fixed and the open folder first; the home sits in an `AddToProjectProvider` that rescans (`bump`) once the file is in.
- **Actions (`project-file-actions.ts`):** open (registers the file in the recents, then `/<type>/<id>`), create folder, rename, move, duplicate, show in folder, new design/board, folder color. New files open `/design|board/<new id>?dir=<absolute folder>&project=<project id>`; the editors read those parameters later. A move or rename calls `storage.relocate` for the files that are in the recent files (`relocate-recents.ts`; it and `forget-recents.ts` match paths with `isPathInside`, ignoring case for Windows-style paths) and re-keys the manifest's `folders` styles; moving into the folder an item is in already does nothing. Dragging a card, tile or tree row onto a folder uses `useRowDrag` (ids `file:<rel>` / `folder:<rel>`).
- **Trash (`trash-tab.tsx`, `use-project-trash.ts`):** `actions.trash(entry)` (the Move to trash menu item, or Delete on a focused card or tile, never while a name is being typed) moves a file or folder to `.cloudy/trash/` through `projectFs.toTrash`, closes the open folder if it was inside, and forgets the recent files that were in it (`forget-recents.ts`). The Trash tab lists name, where it was, when it was deleted, size and Restore (`actions.restore`), and Empty trash asks first with the kit's `ConfirmDialog`. The sidebar's Trash row and the tab show the count and size, which the context holds as `trash`. `ProjectFooter` shows "N items in trash · size", Open trash and the project's size (`use-project-size.ts`, measured after the first paint and after file actions, at most once per 500 ms; a newer action aborts a walk still running through `measureProject`'s signal).
- **Libraries (`libraries/`):** the project home opens the project's `LibraryHub` while it is shown (`useProjectLibraryDocs`: `open` on mount, `release` on unmount, a `LibrarySummary` per library re-read on every change: colors with their values, text and effect styles, images, SVGs, mode axes) and keeps it in the context as `libs`, with `reload()` after the manifest changed. The URL says what is shown: `?tab=libraries` (the cards, `LibrariesTab`/`LibraryCard`), `&library=<id>` (that library's page, `LibraryPage`: colors, text styles, images, SVG & icons, components, effects, each a `KindSection` over a `KindBody`), `?tab=content&kind=<kind>` (`ContentView`: one kind across the libraries, grouped by library; Components is an empty state). The sidebar's Libraries and Content sections (`LibrariesSidebar`) and `nav.openLibrary` / `nav.openKind` move between them; `tab`, `setTab`, `libraryId` and `kind` are in the context.
  - **Colors and styles are edited in a file:** the project home has no color or text style editors. Edit in a file opens the newest recent design of the project whose link uses that library (`design-for-library.ts` reads the link of up to 8 of the newest designs from disk; else a new design in the root, with `?dir=&project=`, which the editor links to the project, plus `&libraries=` listing the libraries new files take and this one when new files don't take it); Add ▾ offers Images or SVG… (`pickImageFiles`, `imageSize`, `hub.addAssetFile`, which dedupes by hash) and Import a file's styles… / a tokens JSON (`pickStylesSource`, then `firstLibraryRecords` with the ids the other libraries hold, into the library's `LibraryDocument`; the hub saves it).
  - **Actions (`use-library-actions.ts`):** `create` (`createLibraryFile`, the manifest, `hub.refresh()` through `reload`, then the records: a file's or tokens JSON's, or a copy of another library with new ids for everything, `copyLibraryRecords` from shared/projects, and its pictures; a file's records that are a library's, or whose id another library of the project holds, get new ids too), `rename` (`hold` the library's saves, `flush`, rename the `.clib` and `.assets` to a file name no other library has, `hub.relocate` to the new name, save the manifest; if that fails both are renamed back and a failed rollback is reported, then the hold is released and `reload()` runs), `remove` (out of the manifest and `reload()` first, so the hub drops it and its pending save, then the `.clib` and `.assets` folder go to the project trash with `projectFs.toTrash`, which accepts those two paths in `.cloudy/libraries/`) and `setAutoAdd` (turning it off asks first, from the library's ⋯ menu: files that already use the library keep it, see `librariesUsedBy` in canvas/libraries). Restoring either half of a deleted library from the Trash tab restores the other half of the pair too if it is in the trash, both under the `.clib`'s stem, and puts the library back in the manifest (`adoptRestored`, not added to new files). A `create` that fails after the manifest entry was added removes the entry and trashes the files.
  - **Used by N files (`library-usage.ts`):** a file's link is inside the file and the home doesn't open files, so a library new files take (`autoAdd`) counts every board and design of the project (`fileCount`, from `useProjectFileCount`, once in the context) and any other says it is used by the files that have it or turn it on, uncounted.
  - **Effects:** the Effects kind lists the libraries' `StyleRecord`s of the effects module's style type (`EFFECT_STYLE`); with none it shows "No effects yet".
  - **Cover and cards:** with no cover image the header's band shows the first library's colors (`LibraryStrip`), else the project's color; the Projects page's cards do the same with `useProjectLibraryColors`.

Its strings are `t` from `project.i18n.ts` (`locales/`).
