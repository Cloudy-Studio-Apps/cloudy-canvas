# Project page

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md); the model is in
[shared/core/projects/](../../shared/core/projects/README.md), the Projects page in
[pages/projects](../projects/README.md)._

- **`/project/:id[?folder=<rel>]` (`project-page.tsx`):** a project's home. It reads the project with `useProject(id)` (the registry record, the manifest, `saveManifest(patch)` which rewrites the `.cproject` atomically and refreshes the registry, and `renameProject`, which renames the manifest's name and the `.cproject`, never the folder) and shows a message while loading, when the id isn't on this device's list, or when the folder is missing (with Locate…). A ready project is `ProjectHome`. The route redirects Home where projects don't exist (Android, the browser build). `?folder=` is the folder open in the Files tab (a path relative to the project, `/`-separated).
- **`ProjectHome` (`project-home.tsx`):** builds the `ProjectContext` (`project-context.ts`: the record, manifest, open folder, `scanRev`, in-place rename and Move to… state, the row drag, the actions and the recent files) and lays out the sidebar and, in the scrolling main column, `ProjectHeader` with the tab's content. Everything below reads the context with `useProjectContext()`. `bump()` makes every scan read again after files moved.
- **`components/`:** the header (`ProjectHeader`: `ProjectCover` with Change cover, the mark, name, facts, Pin, `ProjectMoreMenu`, `NewMenu`, `ProjectTabs`), the project's menu (rename, icon and color through `RenameProjectDialog` / `AppearanceDialog`, show in folder, export as .zip with `export-project-zip.ts`, remove from list), the sidebar (`ProjectSidebar`, `FolderTree` / `FolderTreeNode` with `FolderColorButton`, and Trash), `MoveDialog` with `FolderPicker`, and `PlaceholderTab` for Libraries and Trash until they exist.
- **`files/`:** the Files tab (`FilesTab`): `RecentlyEdited` (the 3 newest files of the project from the recent files), `PathBar`, `FilesToolbar` (search names in the open folder and below with `use-folder-search.ts`, sort, grid or list), `FolderTile` (three previews, count, `NewFolderTile`) and `ProjectFileCard`. Menus come from `entryActions`; `InlineName` turns a name into a `CommitInput` while it is being renamed.
- **Data:** `useFolderScan(root, rel, rev)` reads one level of a folder (folders, boards and designs). `useProjectRecents` pairs files with their recent-files entries (by path) for previews, or builds a stand-in for a file never opened. The previews, kinds and menus come from `@pages/shared/files`, the project mark and images from `@pages/shared/projects` (see [shared/files](../shared/files/README.md) and [shared/projects](../shared/projects/README.md)).
- **Actions (`project-file-actions.ts`):** open (registers the file in the recents, then `/<type>/<id>`), create folder, rename, move, duplicate, show in folder, new design/board, folder color. New files open `/design|board/<new id>?dir=<absolute folder>&project=<project id>`; the editors read those parameters later. A move or rename calls `storage.relocate` for the files that are in the recent files (`relocate-recents.ts`) and re-keys the manifest's `folders` styles; moving into the folder an item is in already does nothing. Dragging a card, tile or tree row onto a folder uses `useRowDrag` (ids `file:<rel>` / `folder:<rel>`).
- Libraries and Trash are placeholders for now; the sidebar shows the Files tree and Trash.

Its strings are `t` from `project.i18n.ts` (`locales/`).
