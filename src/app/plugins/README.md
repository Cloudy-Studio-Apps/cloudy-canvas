# Plugins

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

## Plugins

- **Plugins** are modules installed outside the source (guide: `docs/plugins.md`, example: `examples/plugins/callout/`). A plugin is a folder with `plugin.json` (`readPluginManifest`, `PLUGIN_API_VERSION` in `shared/core/plugins/`) and one ES module with no imports, whose default `activate(api)` returns modules; `api` is the `PluginApi` (`app/plugins/create-plugin-api.ts`: the module API, `defineMessages` and `getLocale` for the plugin's translations, kind bases, canvas-ui chrome, the app's React, the board's points and the design's (`api.design`: points, node base, panel blocks, hooks); wrapped by `strictApi` so reading a name it doesn't have throws, naming it, while extension points stay the same objects).
  - **On disk:** `PluginStorage` (`shared/core`, `pluginStorage` in `@platform`): copied plugins in `<appData>/plugins/<id>/`, development folders linked in `plugins/index.json`.
  - **Loading:** `app/main.tsx` awaits `loadPlugins()` (`app/plugins/`) before rendering. Each enabled and trusted plugin is imported from a `blob:` URL (5 s timeout); `activate` returns modules for the one product in its manifest's `products`, or `{ board, design }`, registered with `registerBoardModule`/`registerDesignModule(module, { plugin })`. Plugin modules are **optional** for `createModuleHost` (`ModuleLoadOptions`): one that throws, misses a `requires`, collides on a key or loops is left out with its dependents and reported; `getBoardProduct` recomposes without plugins if composing fails. Built-in errors still throw.
  - **Stickers:** `api.stickers` (`app/plugins/plugin-stickers.ts`, `PluginStickersApi`: `registerGroup`, `registerSet(groupId, stickers)` into a new or existing group, `stickerSvg`) is app-level, not a module point: what `activate` registers is staged (`PluginStickerStage`) and committed to `stickerCatalog` once it returns (`loadPlugin`), owned by the plugin and dropped when it fails (`failPlugin`); `PluginStatus.stickers` counts them (Settings › Plugins). Sticker ids are `plugin:<id>:<name>`.
  - **State:** `usePluginsStore` (`shared/stores/plugins-store.ts`): `enabled` and `trusted` are saved; what was found and each `PluginStatus` is not. Settings › Plugins (`pages/settings/sections/plugins/`) installs, links, removes, asks for trust before the first run, and offers a reload.
  - **MCP:** the agent server is built on the first request (`use-agent-server.ts`), so plugin tools are listed. `createBoardMcpTools` leaves out a tool whose name is taken, and `list_plugins` (`modules/core/mcp/plugins.mcp.ts`, `AgentHost.plugins`) reports the plugins and their tools (`ModuleHost.ownerOf`).
