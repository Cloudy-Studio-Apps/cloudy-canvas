# Plugins

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md)._

## Plugins

- **Plugins** are modules installed outside the source (guide: `docs/plugins.md`, examples: `examples/plugins/`: `callout/` in plain JavaScript; plugins in TypeScript are built by `pnpm plugin:build`, `scripts/plugin-kit/`). A plugin is a folder with `plugin.json` (`readPluginManifest`, `PLUGIN_API_VERSION` in `shared/core/plugins/`) and one ES module with no imports, whose default `activate(api)` returns modules; `api` is the `PluginApi` (`app/plugins/create-plugin-api.ts`), which lists no names: its groups are the barrels, whole (`core` = `@shared/core`, `canvas` = `@canvas`, `canvasUi` = `@canvas-ui`, `board` = `@board` + `@board/ui`, `design` = `@design` + `@design/ui`), so a plugin reaches what a built-in feature imports, plus three curated groups in `api/` (`ui`: notices, `runWithLoading`, `CodeEditor`, the brand seals, palette favorites and `ui.kit`; `platform`: files, images, HTTP, links, clipboard, fonts; `libs`: the app's React, `createPortal`, lucide `icons`, zustand's `createStore`/`persist`, `StreamLanguage`). `strictApi` wraps the api and each group (not what they hold): reading a name a group doesn't have throws, naming it, while a value's own keys (`api.board.STICKY_COLORS[name]`) read as usual and extension points stay the same objects. A module's UI pieces and points that aren't in a barrel (`boardLibrary`, `designEffectTypes`, `FramePresetPicker`, …) come from `host.require(id)` (`shared/core/modules/`). `scripts/check-public-api.mjs` keeps features on the same surface.
  - **On disk:** `PluginStorage` (`shared/core`, `pluginStorage` in `@platform`): copied plugins in `<appData>/plugins/<id>/`, development folders linked in `plugins/index.json`.
  - **Loading:** `app/main.tsx` awaits `loadPlugins()` (`app/plugins/`) before rendering. Each enabled and trusted plugin is imported from a `blob:` URL (5 s timeout); `activate` returns modules for the one product in its manifest's `products`, or `{ board, design }`, registered with `registerBoardModule`/`registerDesignModule(module, { plugin })`. Plugin modules are **optional** for `createModuleHost` (`ModuleLoadOptions`): one that throws, misses a `requires`, collides on a key or loops is left out with its dependents and reported; `getBoardProduct` recomposes without plugins if composing fails. Built-in errors still throw.
  - **Stickers:** `api.stickers` (`app/plugins/plugin-stickers.ts`, `PluginStickersApi`: `registerGroup`, `registerSet(groupId, stickers)` into a new or existing group, `stickerSvg`) is app-level, not a module point: what `activate` registers is staged (`PluginStickerStage`) and committed to `stickerCatalog` once it returns (`loadPlugin`), owned by the plugin and dropped when it fails (`failPlugin`); `PluginStatus.stickers` counts them (Settings › Plugins). Sticker ids are `plugin:<id>:<name>`.
  - **HTML export:** a plugin whose `main.js` also exports `activateViewer` has its code kept in `pluginViewerSources` (`shared/core/plugins/`, by plugin id, set by `loadPlugin` once its modules registered, dropped when it fails), which the board's HTML export copies into the file (see `docs/plugins.md`, In the HTML export).
  - **State:** `usePluginsStore` (`shared/stores/plugins-store.ts`): `enabled` and `trusted` are saved; what was found and each `PluginStatus` is not. Settings › Plugins (`pages/settings/sections/plugins/`) installs, links, removes (also a folder that couldn't be read, `BrokenPlugin`: a deleted development folder is forgotten, a broken copy deleted), asks for trust before the first run, and offers a reload.
  - **MCP:** the agent server is built on the first request (`use-agent-server.ts`), so plugin tools are listed. `createBoardMcpTools` leaves out a tool whose name is taken, and `list_plugins` (`modules/core/mcp/plugins.mcp.ts`, `AgentHost.plugins`) reports the plugins and their tools (`ModuleHost.ownerOf`).
