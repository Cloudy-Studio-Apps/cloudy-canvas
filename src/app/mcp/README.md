# Agent (MCP) server

_How it works. The rules are in the root [CLAUDE.md](../../../CLAUDE.md); names may still follow the pre-refactor conventions until their phase (see its Transition table)._

Agents (Claude Code, Cursor, …) connect to the running app at `http://127.0.0.1:47821/mcp`. If that port is taken the server tries the next nine, and the URL is written to `mcp.json` in the app data folder. Access is on by default, with no auth: only loopback, with Host and Origin checked against DNS rebinding.

## Agents are collaborators

- **Agents are collaborators** (see Collaborators and workspaces): sessions only tell agents apart. `handleMcpMessage(body, server, context, observer)` gives a session on `initialize` (unknown ids are kept, never refused), passes the `McpMessageContext` to `McpServerTool.run(args, context)`, appends `server.notesFor(context)` after a result, and reports to a `McpObserver` (`connected` with `clientInfo`, `seen`, `toolCall` → its outcome). `createAgentServerDefinition(hostFor, notesFor)` runs each call with `agentHostFor(presenceKey(context))` (`app/mcp/agent-host.ts`): the open file comes with that agent's own workspace (`withWorkspace`, `engine.workspace(id)`), so `AgentBoard`/`AgentDesign` are `AgentFile<BoardWorkspace | DesignWorkspace>` while the editors register `OpenBoard`/`OpenDesign` (the user's engine). `app/mcp/agent-presence-source.ts` is the agent presence source: identification (`identifyAgent`, `AgentClient.match` against the client's name or User-Agent; `agentName` numbers a second one, `agentColor` its brand colour or a free one), activity (`agentCallLabel`, a sentence from the tool's name, also stamped on the agent's undo steps with `history.setNextLabel`), and after each call (`trackAgentCall`: what changed in the workspace, else the ids the arguments name) the agent's selection becomes what it changed, its view follows (`followEdit`) and its cursor goes to the middle; failed calls toast. Steps the user undoes or redoes outside the agent's calls are noted (`createUndoNotes`) and sent with its next reply.

## The app wires it up

- **The app wires it up** in `app/mcp/` (`useAgentServer`, mounted by `<AgentServer />` in the providers): one server with the board's and the design's tools (one set of names, so neither shadows the other) and both products' instructions; `agentHost` implements `AgentHost` and `DesignAgentHost`. The open board and design register themselves for agents with `useAgentBoard` (`products/board/ui/agent/`) and `useAgentDesign` (`products/design/ui/agent/`), both `useAgentFile` on a `createActiveFile` (`canvas-ui/agent/`). The on/off setting is `shared/stores/agent-server-store.ts`, and `shared/agent-server/` is the menu in the top bars and the Settings panel (switch, URL, "Connect an agent…"), which open `ConnectAgentDialog` (`connect-agent-dialog/`): a grid of agent apps with their logos (`simple-icons`, Lucide where there's none), "Other AI tools", one app's setup (snippet, where it goes, "Add to …") and "Install manually" (the default settings: URL, transport, the generic JSON). The apps are data, `AGENT_CLIENTS` (`agent-clients.ts`: Claude Code, Codex, Cursor, VS Code, Antigravity, Gemini CLI, Claude Desktop through `mcp-remote`, Windsurf, and under `more` Zed and opencode; `GENERIC_AGENT_CLIENT` is the manual JSON); Cursor and VS Code have a one-click `installLink`, whose `cursor://`/`vscode:` schemes are allowed in the capabilities.
